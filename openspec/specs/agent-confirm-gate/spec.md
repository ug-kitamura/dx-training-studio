## Requirements
### Requirement: 実行前ユーザー確認

書込（新規・上書き）・スクリプト実行・生成書込（generate_and_write）・web 検索は、実行前に `confirm_required` SSE イベントを送出しユーザーの決裁を待たなければならない（SHALL）。承認時はツールを実行し、拒否時は `rejected` と理由・ガイダンスを含む結果をモデルへ返して継続しなければならない（SHALL）。時間内に応答がない場合はタイムアウトとして実行を見送り、画面再読み込みの案内を含む結果を返さなければならない（SHALL）。

#### Scenario: 上書きを承認して実行する
- **WHEN** 既存ファイルへの `write_file` で確認ダイアログが表示され、ユーザーが承認する
- **THEN** 書込が実行され、tool_result に成功が記録される

#### Scenario: 拒否するとモデルにガイダンスが返る
- **WHEN** ユーザーが確認ダイアログで拒否する
- **THEN** tool_result に `rejected: true` と理由が含まれ、エージェントループは停止せず継続する

#### Scenario: 無応答はタイムアウトで見送る
- **WHEN** 確認ダイアログが時間内に応答されない
- **THEN** 実行は見送られ、timedOut を含む結果と再読み込み案内がモデルへ返る

### Requirement: 承認済みパスのスキップ追跡

同一セッション内で AI が作成したファイル、および上書きを承認済みのパスへの再書込は、以後の上書き確認をスキップしなければならない（SHALL）。スキップ対象は会話履歴からも復元（seed）されなければならない（SHALL）。

#### Scenario: AI 作成ファイルへの再書込は確認なし
- **WHEN** 同一セッション内で AI が新規作成したファイルへ再度 `write_file` が実行される
- **THEN** 確認ダイアログは表示されず書込が実行される

#### Scenario: リロード後もスキップが維持される
- **WHEN** セッション復元後、履歴上で承認済みのパスへ書込が実行される
- **THEN** 確認ダイアログは表示されない

### Requirement: コンテンツフォルダ作成の実行前確認

`contents/` 配下への書込が、まだ存在しないシリーズ・コース・レッスンのフォルダを新しく生じさせる場合、書込の実行前に `confirm_required` を送出しユーザーの決裁を待たなければならない（SHALL）。確認要求には**新しく作られるすべての階層の名前**（シリーズ名・コース名・レッスン名のうち未作成のもの）を含めなければならない（SHALL）。

対象は `contents/` 直下から 3 段（シリーズ・コース・レッスン）に限らなければならない（SHALL）。レッスンより深いディレクトリはローダーが走査せず構造を作らないため、確認を発火させてはならない（MUST NOT）。`content-folder-loader` が構造として解釈しない名前（`_` / `.` 始まり）も同様に発火させてはならない（MUST NOT）。

複数階層が同時に生まれる場合であっても、確認は**1 回にまとめなければならない**（SHALL）——階層ごとにダイアログを分けてはならない（MUST NOT）。

この確認種別は**ホスト側で定義されなければならない**（SHALL）。スキル frontmatter の宣言や本文の記述によって発火の有無が変わってはならない（MUST NOT）。

書込先の全階層が既に存在する場合、本確認を発火させてはならない（MUST NOT）——既存ファイルへの上書きは「実行前ユーザー確認」の上書き確認に従い、両者が同時に発火してはならない（MUST NOT）。

拒否・タイムアウト時はフォルダを作成せず、書込も実行してはならない（MUST NOT）。エージェントループは停止せず継続しなければならない（SHALL）。

#### Scenario: 3 階層まとめて 1 回の確認になる
- **WHEN** いずれの階層も未作成の `contents/新S/新C/新L/contents.md` へ `write_file` が実行される
- **THEN** 確認要求が 1 回だけ送出され、シリーズ「新S」・コース「新C」・レッスン「新L」がすべて提示される

#### Scenario: 既存コースへのレッスン追加でも確認が出る
- **WHEN** 既存シリーズ・既存コース配下の未作成レッスン `contents/既存S/既存C/新L/contents.md` へ `write_file` が実行される
- **THEN** 確認要求が送出され、新しく作られる階層としてレッスン「新L」のみが提示される

#### Scenario: 既存レッスンへの書込では発火しない
- **WHEN** すべての階層が存在する `contents/既存S/既存C/既存L/contents.md` へ `write_file` が実行される
- **THEN** フォルダ作成の確認は送出されない（上書き確認の要否は「実行前ユーザー確認」に従う）

#### Scenario: 拒否するとフォルダが作られない
- **WHEN** フォルダ作成の確認要求をユーザーが拒否する
- **THEN** `contents/新S/` は作成されず、書込も実行されない
- **AND** tool_result に `rejected: true` と理由が含まれ、エージェントループは継続する

#### Scenario: レッスンより深いディレクトリでは発火しない
- **WHEN** 既存レッスン配下の未作成ディレクトリ `contents/既存S/既存C/既存L/assets/diagram.svg` へ `write_file` が実行される
- **THEN** フォルダ作成の確認は送出されない

#### Scenario: 構造として解釈されない名前では発火しない
- **WHEN** `contents/_work/report.html` へ `write_file` が実行される
- **THEN** フォルダ作成の確認は送出されない

#### Scenario: スキルの宣言に依存しない
- **WHEN** スキル frontmatter に確認に関する記述が一切ない状態で新しいシリーズを伴う書込が実行される
- **THEN** 確認要求は通常どおり送出される

### Requirement: ペイン4 の確認 UI

確認要求はペイン4 のツール実行ブロック内にインライン表示され、種別（上書き / フォルダ作成 / スクリプト / 生成 / 検索）・対象パス・目的（purpose）を提示しなければならない（SHALL）。ユーザーは承認・拒否を選択できなければならない（SHALL）。

フォルダ作成の確認では、新しく作られる階層の名前を種別（シリーズ / コース / レッスン）とともに提示しなければならない（SHALL）——ユーザーが名前の打ち間違いを読んで判別できるようにするためである。

確認種別の一覧は、実際に発火しうる種別のみで構成されなければならない（SHALL）。到達不能な種別を確認種別の定義および UI の分岐として残してはならない（MUST NOT）。書込 2 ルート化によりルート外のパスは確認要求ではなくパスガードのエラーで停止するため、プロジェクト外パスの読取・書込に対応する確認種別と専用ダイアログは存在してはならない（MUST NOT）。

#### Scenario: 確認ダイアログの表示内容
- **WHEN** `generate_and_write` の確認要求が発生する
- **THEN** ツールブロックに書込先パスと purpose が表示され、承認 / 拒否ボタンが提供される

#### Scenario: フォルダ作成の表示内容
- **WHEN** 新しいシリーズ・コース・レッスンを伴う書込の確認要求が発生する
- **THEN** ツールブロックに各階層の種別と名前が表示され、承認 / 拒否ボタンが提供される

#### Scenario: ルート外のパスは確認ではなくエラーになる
- **WHEN** ツール入力に `contents/` `contents-work/` いずれの配下でもないパスが指定される
- **THEN** 確認要求は送出されず、エラー結果が tool_result として返る
- **AND** プロジェクト外パス専用の確認ダイアログは存在しない
