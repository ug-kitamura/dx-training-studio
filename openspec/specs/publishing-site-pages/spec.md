# publishing-site-pages Specification

## Purpose

公開サイトのページ構成（トップページ3階層・レッスンページ・パンくず・バッジ・静的 export）の要件を規定する。
## Requirements
### Requirement: サイトは静的 export で全ページを生成できる

サイトは Nextra 4（Next.js）で構築し、`output: 'export'` で全ページを静的 HTML として生成できなければならない（SHALL）。サーバーランタイムを前提とする機能（Route Handlers・middleware・画像最適化）に依存してはならない（SHALL NOT）。GitHub Pages のサブパス配信（`basePath`）と Vercel のルート配信の両方でリンク・アセットが解決できなければならない（SHALL）。

出力は **`trailingSlash: true` を常時有効**とし、各ページを `<slug>/index.html` の形で生成しなければならない（SHALL）。配信先やビルドごとに `trailingSlash` を切り替えてはならない（MUST NOT）——配信先間のビルド差は `basePath` の 1 軸に閉じる。「拡張子なし URL（`/git`）に `.html` を補って返す」というサーバー側の機能に依存してはならない（MUST NOT）——ディレクトリ URL に `index.html` を補う**ディレクトリインデックスだけを持つ素朴なサーバー**（社内ホスティング等）でも全リンク・アセットが解決できなければならない（SHALL）。

#### Scenario: 静的 export が通る

- **WHEN** 変換済みの `content/` がある状態で `next build`（export 設定）を実行する
- **THEN** `out/` に全ページの HTML が生成される
- **AND** 各ページは `<slug>/index.html` の形で出力され、ページ内リンクは末尾スラッシュ付きである

#### Scenario: basePath 配信でアセットが解決する

- **WHEN** `basePath` を設定してビルドし、サブパス配下で配信する
- **THEN** ページ内のリンクと画像・JS・CSS が 404 にならない

#### Scenario: ディレクトリインデックスだけのサーバーで閲覧できる

- **WHEN** 「ディレクトリ URL に `index.html` を補う」機能しか持たない静的サーバーに `out/` を配置して閲覧する
- **THEN** トップ・シリーズ・コース・レッスンの全ページと検索が動作する
- **AND** 拡張子なし URL の `.html` 補完機能が無くても 404 は発生しない

### Requirement: 全体・シリーズ・コースのトップページを自動生成する

3階層のトップページを、正本のメタデータから自動生成しなければならない（SHALL）。手書きの紹介文ファイルを要求してはならない（SHALL NOT）。

- **全体トップ**: ヒーロー画像（サイト専用アセット。下記）・サイト名・全体 `description`（`contents/.meta.json`）・グローバル曼陀羅・シリーズ一覧（各 `description` 付き）
- **シリーズトップ**: ヒーロー（シリーズ見出し。**画像は置かない**）・`description`・コース一覧（`target`・`description`・レッスン数・合計所要時間付き）。曼陀羅・「最初のレッスンへ」等の導線は置かない
- **コーストップ**: ヒーロー（コース見出し）・`target`・`description`・レッスン一覧（各レッスンの `description`・所要時間付き）・前後コースの章（下記）。曼陀羅は置かない

コーストップは「レッスン → 前に受けるコース → 次に受けるコース」の順で同格の章見出しを持たなければならない（SHALL）。英語ページの章名はそれぞれ Lessons / Before this course / Next courses とする。前後コースの章は次の規則に従わなければならない（SHALL）:

- 掲載対象は曼陀羅グラフの辺で当該コースと結ばれた実在コースとし、「前」は当該コースへ入る辺の始点、「次」は当該コースから出る辺の終点から導出する
- 各章の並びは同シリーズ（順序辺）のコースが先、他シリーズ（跨ぎ辺）のコースが後
- 各コースはバレットのテキストリンクで表示し、コース名のみをリンクにする。レッスン一覧のようなカード表示にしてはならない（SHALL NOT）
- 他シリーズのコースには所属シリーズ名を控えめな添え字としてリンクの外に表示する。同シリーズのコースには添え字を付けない
- 該当コースが0件の章は、見出しを表示したままリンク無しのテキスト「なし」（英: None）を表示する

キャッチコピーは「{タイトル} ——{キャッチコピー}」の1行で表示しなければならない（SHALL）——キャッチコピーはタイトルの右に**半角スペース**と EM DASH 2つ（——）を挟んで続け、末尾に閉じ記号は付けない。全角スペースを使ってはならない（MUST NOT）——EM DASH 自体が前後に空きを持つため、全角スペースを重ねると字間が抜けて見える。`catch` が未設定ならタイトルのみを表示する。この記法は次の3箇所に適用しなければならない（SHALL）: シリーズトップのヒーロー見出し・コーストップのヒーロー見出し・**一覧カード**（全体トップのシリーズ一覧、シリーズトップのコース一覧）。記法の組み立ては単一の実装に集約しなければならない（SHALL）——ヒーローと一覧カードで別々に組み立ててはならない（MUST NOT）。過去に記法の変更（閉じ記号の削除・全角スペースから半角スペースへの変更）が経路ごとの取りこぼしを生んでいるためである。

キャッチコピーの文字サイズ・色は場所ごとに持ち、記法の実装が決めてはならない（MUST NOT）。ヒーロー見出し・一覧カードとも既存の表示スタイル（本文色ではなくブランド色、当該箇所のタイトルより小さい文字サイズ）を保たなければならない（SHALL）。一覧カードではキャッチコピーがタイトルの太さを継いではならない（MUST NOT）——タイトルと同じ行に並ぶため、太さでも従属が読み取れる必要がある。

一覧カードにおいて、タイトルとキャッチコピーは同一のインラインフローに置き、狭い画面では両者をまたいで自然に折り返さなければならない（SHALL）。タイトルとキャッチコピーの間に、記法の半角スペース以外の余白を挿入してはならない（MUST NOT）。一覧カードの `description` はキャッチコピーとは別の行として従来どおり表示しなければならない（SHALL）。

曼陀羅ノードのキャッチコピー表示にはこの記法を適用しない——ノードの幅が狭く1行に収まらないため、タイトルの下の行に置く従来の表示を維持する。レッスン一覧のカードはキャッチコピーを持たない（レッスンのメタスキーマに `catch` フィールドが存在しない）。

サイドバーとパンくずにおける全体トップページの表示名は日本語「ホーム」・英語「Home」としなければならない（SHALL）。

全体トップのヒーロー画像は `mandala/app/` 直下の固定ファイル名の画像（ツール埋め込み資産・静的 import）とし、正本 `images/` やコンテンツメタから取得してはならない（SHALL NOT）——画像の差し替えはファイルの置き換えで行う。ヒーロー画像は**切り抜かずに全体を表示**しなければならない（SHALL）——幅を本文カラムに合わせ、高さは縦横比に従って決まる（固定高で上下を切り落とさない）。`.meta.json` の `cover` フィールドはどのページでも表示に使わない（温存はするが読者向け出力に出さない）。

#### Scenario: 全体トップの構成

- **WHEN** 全体トップページを開く
- **THEN** 最上部にヒーロー画像、続いてサイト名・description・曼陀羅・シリーズ一覧が並ぶ
- **AND** サイドバーの全体トップ項目は「ホーム」（英語ツリーでは「Home」）と表示される

#### Scenario: シリーズトップは目次に徹する

- **WHEN** シリーズトップページを開く
- **THEN** ヒーロー見出し・description・コース一覧が表示される
- **AND** 曼陀羅と「最初のレッスンへ」の導線は表示されない

#### Scenario: コーストップに曼陀羅が無い

- **WHEN** コーストップページを開く
- **THEN** 曼陀羅は表示されない

#### Scenario: コーストップの前後コースの章

- **WHEN** 前に同シリーズ1コース、次に他シリーズ1コースを持つコースのトップページを開く
- **THEN** レッスン一覧の後に「前に受けるコース」「次に受けるコース」の章がこの順で並ぶ
- **AND** 前の章には同シリーズのコースがバレットのテキストリンクで表示され、添え字は付かない
- **AND** 次の章には他シリーズのコースがリンクで表示され、所属シリーズ名がリンクの外に添えられる

#### Scenario: 前後コースが0件の章は「なし」

- **WHEN** 前に受けるコースが存在しないコースのトップページを開く
- **THEN** 「前に受けるコース」の見出しは表示され、その下にリンク無しの「なし」が表示される

#### Scenario: ヒーロー画像が切り抜かれない

- **WHEN** 縦横比 3.75:1 のヒーロー画像を置いて全体トップページを開く
- **THEN** 画像の全体が表示され、上下の切り落としが発生しない
- **AND** 画面幅を狭めると画像は縦横比を保ったまま縮む

#### Scenario: シリーズトップの見出しの型

- **WHEN** `catch: 地図を手に入れる` を持つコース「DX入門コース」のトップページを開く
- **THEN** 見出しは「DX入門コース ——地図を手に入れる」の1行で表示され、タイトルとダッシュの間は半角スペース1つである
- **AND** キャッチコピー部分の文字サイズ・色は従来のキャッチコピー表示と同じである

#### Scenario: catch が無いときは見出しのみ

- **WHEN** `catch` 未設定のシリーズのトップページを開く
- **THEN** 見出しはシリーズ名のみで、ダッシュの装飾は表示されない

#### Scenario: 全体トップのシリーズカードの見出しの型

- **WHEN** `catch: ここから旅がはじまる` を持つシリーズ「はじめにシリーズ」がある状態で全体トップページを開く
- **THEN** そのカードのタイトル行は「はじめにシリーズ ——ここから旅がはじまる」の1行で表示され、タイトルとダッシュの間は半角スペース1つである
- **AND** キャッチコピーはタイトルの下の行には表示されない
- **AND** カードの `description` はキャッチコピーとは別の行として引き続き表示される

#### Scenario: シリーズトップのコースカードの見出しの型

- **WHEN** `catch: 地図を手に入れる` を持つコース「DX入門コース」を含むシリーズのトップページを開く
- **THEN** そのカードのタイトル行は「DX入門コース ——地図を手に入れる」の1行で表示される
- **AND** キャッチコピー部分の文字色はブランド色であり、文字サイズと太さはカードのタイトルより小さく細い

#### Scenario: 一覧カードのキャッチに全角スペースが混ざらない

- **WHEN** `catch` を持つシリーズ・コースのカードを含むページを生成する
- **THEN** カードのタイトル行のテキストに全角スペースは含まれない
- **AND** タイトルとダッシュの間の余白は記法の半角スペース1つのみであり、レイアウト由来の余白は加算されない

#### Scenario: catch が無いカードはタイトルのみ

- **WHEN** `catch` 未設定のコースを含むシリーズのトップページを開く
- **THEN** そのカードのタイトル行はコース名のみで、ダッシュの装飾は表示されない

#### Scenario: 曼陀羅ノードのキャッチは従来のまま

- **WHEN** `catch` を持つコースのノードを含む曼陀羅を表示する
- **THEN** ノードのキャッチコピーはタイトルの下の行に表示され、ダッシュの記法は使われない

#### Scenario: cover を設定していても表示されない

- **WHEN** `.meta.json` に `cover` を持つシリーズのトップページを開く
- **THEN** cover 画像は表示されず、ビルドもエラーにならない

#### Scenario: コーストップのレッスン一覧

- **WHEN** 3レッスンを持つコースのトップページを開く
- **THEN** レッスンが `order` の順に、それぞれの description と所要時間つきで一覧される

### Requirement: レッスンページとパンくず

各レッスンは本文（`contents.md` の markdown）を描画するページとして生成されなければならない（SHALL）。本文中の画像プロンプト（HTML コメント）を読者向け出力に含めてはならない（SHALL NOT）。

パンくずは **Nextra 内蔵のパンくず1本だけ**を表示しなければならない（SHALL）——サイト独自のパンくず実装を持ってはならない（SHALL NOT）。レッスンページでは「シリーズ / コース / レッスン」、コーストップでは「シリーズ / コース」の形で表示され、各段は対応するページへのリンクである（SHALL）。**全体トップページとシリーズトップページにはパンくずを表示しない**（SHALL NOT）。パンくずとその下の内容（ラベル行・見出し）の間には視認できる余白を設けなければならない（SHALL）。

レッスンページの本文の上に**ラベル行**を表示しなければならない（SHALL）。並びは `{status} {所要時間} {style}` の順で、status ラベルは `done` のとき出さず、`open` のとき「未着手」、`in_progress` のとき「作成中」と表示する（英語はそれぞれ `open` / `in progress`）。style ラベルはコースの `style` から取り、日本語は「独習 / 講義 / ハンズオン」、英語は小文字の `self-study` / `lecture` / `hands-on`。未設定なら style ラベルは出さない。ラベルの配色は種別ごとに一貫させなければならない（SHALL）: status=赤系・所要時間=緑系・style=青系。ラベル行の右端には「著者: {表示名}」（英語は `author: {表示名}`）を表示する（SHALL）。著者の表示名はレッスン `.meta.json` から双方向フォールバックで解決しなければならない（SHALL）: 日本語ページは `author` を優先し無ければ `author_en`、英語ページは `author_en` を優先し無ければ `author`。どちらも空なら出さない。

#### Scenario: レッスン本文の描画

- **WHEN** GFM 表・コードブロック・画像・GitHub アラートを含むレッスンページを開く
- **THEN** それぞれが整形されて表示され、HTML コメントは表示されない

#### Scenario: パンくずが1本だけ表示される

- **WHEN** レッスンページを開く
- **THEN** パンくずは「シリーズ / コース / レッスン」の1本だけ表示され、コース名をクリックするとコーストップへ遷移する
- **AND** パンくずとラベル行の間に余白がある

#### Scenario: トップページとシリーズトップにパンくずが無い

- **WHEN** 全体トップページとシリーズトップページをそれぞれ開く
- **THEN** どちらにもパンくずは表示されない

#### Scenario: ラベル行の表示

- **WHEN** `status: done`・`estimated_minutes: 15`・コース `style: lecture`・`author: Kitamura` のレッスンページを開く
- **THEN** ラベル行に「15分」（緑系）「講義」（青系）が並び（status ラベルは出ない）、右端に「著者: Kitamura」が表示される

#### Scenario: 未完成レッスンのラベル行

- **WHEN** `status: in_progress` のレッスンページを開く
- **THEN** ラベル行の先頭に「作成中」が赤系の配色で表示される

#### Scenario: 著者の双方向フォールバック

- **WHEN** `author_en` のみを持つレッスンの日本語ページと、`author` のみを持つレッスンの英語ページをそれぞれ開く
- **THEN** どちらのページでも、もう一方のフィールドの値が著者として表示される

### Requirement: 全 status を公開し、未完成にはバッジを出す

レッスンは `status` の値によらず公開しなければならない（SHALL）。`status` が `done` 以外のレッスンには、目次（コーストップの一覧）とレッスンページ本体のラベル行の両方で、Studio と同じ語彙の状態ラベル（`open`=未着手、`in_progress`=作成中。英語は `open` / `in progress`）を表示しなければならない（SHALL）。状態ラベルの配色は目次・ラベル行とも赤系で統一しなければならない（SHALL）。`done` のレッスンには状態ラベルを表示してはならない（SHALL NOT）。「執筆中」「準備中」という語を状態表示に使ってはならない（SHALL NOT）。

#### Scenario: 作成中レッスンの表示

- **WHEN** `status: in_progress` のレッスンをコーストップとレッスンページで見る
- **THEN** コーストップの一覧とレッスンページのラベル行の両方に「作成中」が赤系の配色で表示される

#### Scenario: 未着手レッスンの表示

- **WHEN** `status: open` のレッスンをコーストップで見る
- **THEN** 一覧に「未着手」が赤系の配色で表示される

#### Scenario: 完成レッスンには出ない

- **WHEN** `status: done` のレッスンを見る
- **THEN** 状態ラベルはどこにも表示されない

### Requirement: supergraphic 帯

サイトの全ページは、画面最上部に高さ 6px・全幅の supergraphic 帯を表示しなければならない（SHALL）。帯はページをスクロールしても画面最上部に留まり続けなければならない（SHALL）——スクロールで視界から外れてはならない（SHALL NOT）。画像はツール埋め込み資産として `mandala/app/` 直下（ファビコンと同じ場所）に置き、静的 import で参照しなければならない（SHALL）。正本 `images/` に置いてはならない（SHALL NOT）——正本はペイン4 の画像マネージャの管理下にあり、ユーザーが UI から削除できるため。

帯は通常フローから外れた要素として実現し、レイアウトの高さを一切占有してはならない（SHALL NOT）。ナビバーは帯と同じ高さ（6px）を上端に確保し、帯がナビバーの中身に重ならないようにしなければならない（SHALL）。確保はテーマのナビバー高さ変数（`--nextra-navbar-height`）を通じて行い、サイドバー・目次・モバイルナビの開始位置および高さの計算がそれに自動で追随しなければならない（SHALL）——それらの `top` や `height` を個別に上書きしてはならない（SHALL NOT）。

#### Scenario: 帯がナビバーの中身に重ならない

- **WHEN** 任意のページでナビバーと帯を見る
- **THEN** 帯はナビバーの上端 6px の余地に収まり、ロゴ・検索・アイコン類のいずれとも重ならない
- **AND** サイドバーと目次はナビバーの下辺と同じ位置から始まる

#### Scenario: 任意のページで帯が表示される

- **WHEN** サイトのいずれかのページを表示する
- **THEN** 画面最上部に高さ 6px・全幅の supergraphic 帯が表示される

#### Scenario: スクロールしても帯が残る

- **WHEN** ページを下方向へスクロールする
- **THEN** 帯は画面最上部に留まったままである
- **AND** ナビバーの下辺の位置は変わらず、サイドバーと目次の開始位置もずれない

#### Scenario: スクロール開始直後もヘッダーが動かない

- **WHEN** ページ最上部から帯の高さ（6px）に満たない量だけスクロールする
- **THEN** ナビバーの上辺・下辺は、スクロール前と同じ画面座標にある
- **AND** サイドバーと目次の開始位置も動かない

#### Scenario: 画面幅を変えても全幅を保つ

- **WHEN** ブラウザの横幅を変更する
- **THEN** 帯は常に全幅を占め、supergraphic の色帯の横方向の並びが保たれる

### Requirement: ナビバー右上ボタンの色とホバー挙動

ナビバー右上の3ボタン（GitHub リンク・全体曼陀羅ボタン・言語トグル）は、通常時に**サブ的なグレー**（テーマ前景の混色。実値は目視で確定する）で表示しなければならない（SHALL）。ホバー時は3ボタンとも**前景色**へ濃くなり、ブランド色（`--dxm-brand`）へ変えてはならない（MUST NOT）——青は本文リンクの語彙として残す。ボタンごとに異なるホバー挙動（opacity のみ変える・変化しない等）を持たせてはならない（MUST NOT）。Studio の GlobalHeader 右側ボタン群（操作色 → ホバーで前景色）と同じ振る舞いに揃える。

3ボタンはいずれもホバー時に `cursor: pointer` を示さなければならない（SHALL）——要素が `<a>` か `<button>` かによってカーソルが変わってはならない（MUST NOT）。曼陀羅ボタンは `<button>` なので、ブラウザ既定の `default` を明示的に上書きする。

#### Scenario: 通常時はグレーである

- **WHEN** 任意のページでナビバーを表示する
- **THEN** GitHub・曼陀羅・言語トグルの3ボタンがいずれも前景色よりグレーに表示される

#### Scenario: ホバーで3ボタンとも前景色になる

- **WHEN** GitHub・曼陀羅・言語トグルのそれぞれにマウスホバーする
- **THEN** いずれのボタンも前景色へ濃くなり、青（ブランド色）にはならない

#### Scenario: 3ボタンともポインタカーソルになる

- **WHEN** GitHub・曼陀羅・言語トグルのそれぞれにマウスホバーする
- **THEN** いずれもマウスカーソルがポインタに変わる

### Requirement: 3カラムの幅

3カラム帯（sidebar + 本文 + toc）の上限は **97rem**、サイドバーの展開時幅は **20rem**、toc の幅は **18rem** としなければならない（SHALL）。サイドバーの幅上書きは**展開状態だけ**を狙い、手動トグルで畳んだ状態（アイコン幅）を広げてはならない（MUST NOT）。navbar も同じ幅変数を共有し、ロゴと右上ボタンは帯と一緒に整列する（SHALL）。

#### Scenario: サイドバーが 20rem で表示される

- **WHEN** デスクトップ幅でページを開く
- **THEN** 展開状態のサイドバーは 20rem（320px）幅で表示される

#### Scenario: 畳んだサイドバーは広がらない

- **WHEN** サイドバーを手動トグルで畳む
- **THEN** 畳み時の幅（アイコン幅）は従来のままである

### Requirement: セグメントプリフェッチ用ファイルは平坦なファイル名で out/ に存在する

静的 export の成果物 `out/` において、クライアントルーターが要求するセグメントプリフェッチ用 `.txt`（`__next` で始まりドットでセグメントパスを連結した名前。例: `__next.$oc$mdxPath.__PAGE__.txt`）は、**ビルドを実行した OS を問わず**平坦な単一ファイルとして存在しなければならない（SHALL）。

Next.js 16.x は Windows 上でこれらを入れ子ディレクトリ（例: `__next.$oc$mdxPath/__PAGE__.txt`）として誤出力するため、`postbuild` は `out/` 配下の `__next.*` ディレクトリを検出し、内容物をドット連結の平坦なファイル名へ移動して当該ディレクトリを削除しなければならない（SHALL）。この修復は冪等でなければならず（SHALL）、対象が存在しないビルド（Linux 等）では成果物を変更してはならない（SHALL NOT）。

#### Scenario: Windows ビルドの入れ子ディレクトリを平坦化する

- **WHEN** `out/git/__next.$oc$mdxPath/__PAGE__.txt` が存在する状態で postbuild の修復を実行する
- **THEN** `out/git/__next.$oc$mdxPath.__PAGE__.txt` が単一ファイルとして存在する
- **AND** ディレクトリ `out/git/__next.$oc$mdxPath/` は存在しない

#### Scenario: 対象が無いビルドでは何もしない

- **WHEN** `out/` 配下に `__next.*` ディレクトリが存在しない状態で postbuild の修復を実行する
- **THEN** `out/` の内容は変更されない
- **AND** 修復は正常終了する

#### Scenario: 平坦化後は本番プレビューでプリフェッチが 404 にならない

- **WHEN** 平坦化済みの `out/` を静的サーバーで配信しページ遷移する
- **THEN** `/__next.$oc$mdxPath.__PAGE__.txt` 等へのリクエストが 200 または 304 で応答される
