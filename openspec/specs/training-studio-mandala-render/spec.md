## Requirements
### Requirement: 曼陀羅は React Flow で描画する

Studio の全体曼陀羅とミニ曼陀羅は React Flow（`@xyflow/react`）で描画しなければならない（SHALL）。レイアウトは dagre による上から下（TB）の階層配置としなければならない（SHALL）。

Mermaid の flowchart 文字列を生成して SVG を `dangerouslySetInnerHTML` で挿入する方式を用いてはならない（MUST NOT）。生成後の SVG の DOM を書き換えて選択状態を表現してはならない（MUST NOT）。

曼陀羅のグラフは正本（`contents/` の `.meta.json` を読んだ `Series[]`）から組み立てなければならない（SHALL）。辺の導出規則は公開サイトと同一とし、シリーズ内は `courses` 配列の隣接鎖（order 辺）、シリーズ跨ぎは `cross_series_prev` / `cross_series_next`（cross 辺、相手が実在するときのみ）としなければならない（SHALL）。

React Flow は遅延境界（`next/dynamic` の `ssr: false`）越しに読み込まなければならない（SHALL）——曼陀羅を開かない限り読み込まれないこと。

#### Scenario: 全体曼陀羅が React Flow で出る

- **WHEN** ユーザーが GlobalHeader の曼陀羅ボタンを押す
- **THEN** React Flow で描かれた全体曼陀羅がモーダルに表示される

#### Scenario: 跨ぎリンクが辺になる

- **WHEN** コース A の `cross_series_next` に別シリーズのコース B が設定されている
- **THEN** 曼陀羅に A から B への辺が描かれる

#### Scenario: 相手が存在しない跨ぎリンクは辺にならない

- **WHEN** コース A の `cross_series_next` に存在しないコース ID が設定されている
- **THEN** その辺は描かれず、描画は失敗しない

### Requirement: 全体曼陀羅とミニ曼陀羅でノード種別を出し分ける

全体曼陀羅はコースを compact ノード（コース名と受講形態のみ）で描き、シリーズごとに背景の枠（シリーズ枠）を敷かなければならない（SHALL）。

ミニ曼陀羅は当該コースとその隣接（シリーズ内の前後・跨ぎの相手）だけを描かなければならない（SHALL）。ミニ曼陀羅にシリーズ枠を表示してはならない（MUST NOT）。

ミニ曼陀羅の**サムネイル**は compact ノードで描かなければならない（SHALL）。情報量の多いカードノードをサムネイルで用いてはならない（MUST NOT）——縮小率が上がって文字が読めなくなるため。

**サムネイルのノードに受講形態のラベルを表示してはならない**（MUST NOT）——セルが小さく、ラベルがコース名の幅を奪って省略が早く始まるため。サムネイルが担うのは周辺の並びだけであり、受講形態は拡大モーダルと全体曼陀羅が担う（SHALL）。

サムネイルのノードは、ラベルを載せない密度に見合った幅としなければならない（SHALL）——全体曼陀羅と同じ幅を保ってはならない（MUST NOT）。ノードを必要より広く取ると、`fitView` がそのぶん縮小してコース名が小さくなるため。コース名は**ノードの幅方向の中央にそろえなければならない**（SHALL）。

⚠ サムネイルと全体曼陀羅はノード種別を分けなければならない（SHALL）——密度が違うため、同一種別に見た目の分岐を持たせると片方の変更が他方へ漏れる。

ミニ曼陀羅の**拡大モーダル**はカードノードで描かなければならない（SHALL）。

#### Scenario: サムネイルでコース名が読める

- **WHEN** ペイン2 のコースビューでミニ曼陀羅サムネイルを表示する
- **THEN** 各ノードはコース名だけの 1 行で描かれ、コース名が読める
- **AND** 受講形態のラベルは表示されない
- **AND** コース名はノードの中央にそろっている
- **AND** ノードの幅は全体曼陀羅の compact ノードより狭い

#### Scenario: 全体曼陀羅の compact ノードには受講形態が残る

- **WHEN** 全体曼陀羅を表示する
- **THEN** 各コースノードにコース名と受講形態のラベルが表示される

#### Scenario: ミニ曼陀羅にシリーズ枠が無い

- **WHEN** ミニ曼陀羅（サムネイル・拡大モーダルとも）を表示する
- **THEN** シリーズを囲う背景の枠は描かれない

#### Scenario: 全体曼陀羅にはシリーズ枠がある

- **WHEN** 全体曼陀羅を表示する
- **THEN** 各シリーズのコース群の背後にシリーズ枠が敷かれ、シリーズ名が読める

### Requirement: カードノードに載せる情報と並び

拡大モーダルのカードノードは、上から順に**シリーズ名**（補助テキスト）、**コース名**（主情報）、**レッスン数と合計所要時間**（補助テキスト）を表示しなければならない（SHALL）。受講形態のラベルはカードの**右端・高さ中央**に配置しなければならない（SHALL）。

カードにキャッチコピーを表示してはならない（MUST NOT）。

カードの寸法は上記の情報が収まる必要十分に留めなければならない（SHALL）。**実際のコース名で確認したうえで、余白を切り詰めた寸法にしなければならない**（SHALL）。ただし、**コース名が全角1文字だけ次の行へ落ちる幅にしてはならない**（MUST NOT）——1文字だけの折り返しは読み手の目を余計に往復させる。

**受講形態のラベルのために右端へ確保する逃げは、受講形態の語彙（`self-study` / `lecture` / `hands-on`）のうち表示上もっとも長いラベルが、本文へ重ならずに収まる幅でなければならない**（SHALL）——ラベルは絶対配置なので、逃げが足りないとコース名の上に重なる。語彙を増やしたときは逃げを測り直す（SHALL）。

**カードの寸法は、レイアウトへ渡すノード寸法の定義と、カードのスタイルの実寸とで一致していなければならない**（SHALL）——dagre はノード寸法を固定値で受け取って座標を出すため、片方だけを変えると辺の接続位置がノードの縁からずれる。この一致は**自動テストで固定しなければならない**（SHALL）——目視の申し合わせだけでは、片方だけを変える改修を止められない。

#### Scenario: カードの情報の並び

- **WHEN** ミニ曼陀羅の拡大モーダルでコースのカードを表示する
- **THEN** シリーズ名・コース名・「N レッスン・約 M 分」がこの順で縦に並ぶ
- **AND** 受講形態のラベルがカード右端の高さ中央に表示される

#### Scenario: キャッチコピーは出ない

- **WHEN** キャッチコピーが設定されているコースのカードを表示する
- **THEN** カードにキャッチコピーは表示されない

#### Scenario: 寸法の定義と実寸が一致する

- **WHEN** カードノードを描画する
- **THEN** カードの実際の寸法は、レイアウト計算へ渡したノード寸法と一致する

#### Scenario: 寸法の食い違いはテストで落ちる

- **WHEN** レイアウトへ渡すカードのノード寸法だけを変え、カードのスタイルの実寸を据え置く
- **THEN** 寸法の一致を検証するテストが失敗する

#### Scenario: 最長の受講形態ラベルが本文に重ならない

- **WHEN** 受講形態が `hands-on` のコースのカードを拡大モーダルで表示する
- **THEN** 受講形態のラベルはコース名・シリーズ名・レッスン数の文字に重ならない

### Requirement: 現在地は青枠とピンアイコンで示す

曼陀羅における現在地のコースは、ノードの枠色の変化（青系）と、ノードの**左外・高さ中央**に重ねたピンアイコン（`MapPin`）で示さなければならない（SHALL）。

「いまここ」等のテキストバッジで現在地を示してはならない（MUST NOT）。ピンはノードの内容としてインラインに配置してはならない（MUST NOT）——コース名の幅が縮み、省略位置が他ノードとずれるため。

**コースを選ばずシリーズだけを選んでいるときは、そのシリーズ枠が現在地となり、コースノードと同じ枠色とピンで示さなければならない**（SHALL）。ピンは枠の左外・高さ中央に置く（SHALL）。**現在地の印を同時に 2 つ出してはならない**（MUST NOT）——コースを選ぶと所属シリーズも選択状態になるため、コースの選択を優先する。シリーズが折りたたまれているときは、枠の代わりに集約ノードが印を引き取らなければならない（SHALL）。

#### Scenario: 現在地に枠とピンが付く

- **WHEN** あるコースを選択した状態で曼陀羅を開く
- **THEN** そのコースのノードは枠が青系に変わり、左外にピンアイコンが表示される

#### Scenario: シリーズを選ぶと印が枠へ移る

- **WHEN** 全体曼陀羅でシリーズ枠をクリックしてそのシリーズを選ぶ
- **THEN** そのシリーズ枠の枠線が実線の青系に変わり、枠の左外にピンアイコンが表示される
- **AND** コースノードには現在地の印が付かず、画面上のピンは 1 つだけである

#### Scenario: 選んだシリーズを折りたたむと印が集約ノードへ移る

- **WHEN** シリーズを選んだ状態で、そのシリーズをツールバーで折りたたむ
- **THEN** 集約ノードに青枠とピンが付き、画面上のピンは 1 つだけである

#### Scenario: テキストバッジを使わない

- **WHEN** 現在地のノードを表示する
- **THEN** 「いまここ」というテキストのバッジは表示されない

### Requirement: 辺は 1 種類のアニメーションする線とする

曼陀羅の辺は、シリーズ内（order）と跨ぎ（cross）を線種で区別してはならない（MUST NOT）。全ての辺を同一の見た目で、流れの向きが分かるアニメーション付きで描かなければならない（SHALL）。進む向きを示す矢印を辺の終端に付けなければならない（SHALL）。

辺に `stroke-dasharray` の種別ごとの上書きを行ってはならない（MUST NOT）。

シリーズ枠の破線は、辺とは用途が異なるため維持しなければならない（SHALL）。

**ゴーストノード（別シリーズの相手コース）の枠線に破線を用いてはならない**（MUST NOT）——1 枚の絵に破線の語彙が増えると読み取りが重くなるため。別シリーズであることは、カードノードではシリーズ名の行が、透明度の違いと併せて担う（SHALL）。

#### Scenario: 跨ぎ辺とシリーズ内辺が同じ見た目

- **WHEN** シリーズ内の辺と跨ぎの辺が同じ画面に描かれる
- **THEN** 両者の線の見た目は同一である

#### Scenario: ゴーストノードの枠は実線

- **WHEN** ミニ曼陀羅に別シリーズのコース（ゴースト）が表示される
- **THEN** そのノードの枠線は実線で描かれる
- **AND** カードノードではシリーズ名が併記される

### Requirement: ノードクリックでコースへ遷移する

曼陀羅のコースノードをクリックしたとき、そのコースを選択しなければならない（SHALL）。ミニ曼陀羅の拡大モーダルでノードをクリックして遷移したとき、モーダルは開いたまま遷移先コースのグラフに切り替わらなければならない（SHALL）。

**全体曼陀羅の展開中のシリーズ枠、および折りたたんだシリーズの集約ノードをクリックしたとき、そのシリーズを選択しなければならない**（SHALL）——展開時の枠と畳んだときの集約は同じシリーズの 2 つの姿なので、クリックの意味も揃える。枠の中でもコースノードの上ではコースの選択を優先しなければならない（SHALL）。枠には押せることが分かる手がかりとしてポインタカーソルを与えなければならない（SHALL）。枠は面積が大きいため、ホバーで地の色を変えてはならない（MUST NOT）。

Start / Goal の文字ノードを除き、遷移先を持たないノードにクリックによる遷移を割り当ててはならない（MUST NOT）。

「ノードをクリックするとそのコースに移動します」等の操作説明のキャプションを表示してはならない（MUST NOT）。

#### Scenario: ノードクリックで移動する

- **WHEN** ユーザーが全体曼陀羅のコースノードをクリックする
- **THEN** そのコースが選択され、ペイン2 がそのコースのビューに変わる

#### Scenario: モーダルは開いたまま切り替わる

- **WHEN** ユーザーがミニ曼陀羅の拡大モーダルで別のコースのノードをクリックする
- **THEN** モーダルは閉じず、遷移先コースを中心にしたグラフに切り替わる

#### Scenario: シリーズ枠から移動する

- **WHEN** ユーザーが全体曼陀羅で展開中のシリーズ枠の、コースノードが無い場所をクリックする
- **THEN** そのシリーズが選択され、ペイン2 がそのシリーズのビューに変わる
- **AND** モーダルは閉じない

#### Scenario: 枠の中のコースノードはコースへ移動する

- **WHEN** シリーズ枠の中にあるコースノードをクリックする
- **THEN** そのコースが選択される（シリーズではない）

#### Scenario: 折りたたんだシリーズの集約ノードから移動する

- **WHEN** ユーザーが折りたたんだシリーズの集約ノードをクリックする
- **THEN** そのシリーズが選択され、ペイン2 がそのシリーズのビューに変わる
- **AND** モーダルは閉じない

#### Scenario: 操作説明のキャプションが無い

- **WHEN** 全体曼陀羅またはミニ曼陀羅の拡大モーダルを表示する
- **THEN** 「ノードをクリックするとそのコースに移動します」という文言は表示されない

### Requirement: Studio は曼陀羅描画に Mermaid を用いない

曼陀羅の描画に Mermaid を用いてはならない（MUST NOT）。曼陀羅専用の Mermaid 補助（描画の直列化・テーマ設定・サムネイル SVG の縮小・選択状態の DOM パッチ）は削除しなければならない（SHALL）。

曼陀羅以外の用途で Mermaid を使っている箇所があれば、それは残してよい（MAY）。

#### Scenario: 曼陀羅から Mermaid が消える

- **WHEN** 全体曼陀羅とミニ曼陀羅を表示する
- **THEN** Mermaid による SVG は生成されない

### Requirement: 曼陀羅キャンバスの高さは絶対長か親いっぱいかを選べる

曼陀羅コンポーネントは、キャンバスの高さの決め方として次の 2 つを提供しなければならない（SHALL）。

- **絶対長**: 呼び出し側が CSS の長さ（`720px` / `min(74vh, 720px)` など）を渡す
- **親いっぱい**: 呼び出し側が「親の高さいっぱいに広がる」ことを明示的に指定する

親いっぱいを指定したとき、曼陀羅のラッパとキャンバスは親の高さを埋めなければならない（SHALL）。ツールバー（シリーズ折りたたみ）を伴う場合も、キャンバスは残りの高さに収まり、親を溢れてはならない（MUST NOT）。

高さの指定として `100%` などのパーセントを絶対長として渡す使い方をしてはならない（MUST NOT）——ラッパの高さが確定していない場合にパーセントが解決できず、キャンバスが 0px に潰れるため。

親いっぱいを指定したときも、キャンバスには下限の高さを与えなければならない（SHALL）——ビューポートが低い環境でキャンバスが潰れないこと。

#### Scenario: サムネイルが親のセルいっぱいに描かれる

- **WHEN** ペイン2 のコースビューでミニ曼陀羅サムネイルを表示する
- **THEN** サムネイルのキャンバスは親のセルの高さいっぱいに描かれ、ノードと辺が見える

#### Scenario: サムネイルが親のセルを押し広げない

- **WHEN** グラフのノード数が多いコースでミニ曼陀羅サムネイルを表示する
- **THEN** 左列 4 項目で決まるセルの高さは変わらず、グラフはセルへ縮んで収まる

#### Scenario: ツールバーがあってもキャンバスが溢れない

- **WHEN** 全体曼陀羅をシリーズ折りたたみのツールバー付きで表示する
- **THEN** ツールバーとキャンバスの合計が親の高さに収まり、親を溢れない

### Requirement: コンテナの寸法が変わったら曼陀羅を再フィットする

曼陀羅は、キャンバスのコンテナの寸法が確定したとき・変わったときに、表示位置を決め直さなければならない（SHALL）。初期化時の一度きりで済ませてはならない（MUST NOT）。決め直しの規則は曼陀羅の種別で異なる（SHALL）:

- **全体曼陀羅**（モーダル）: **既定のズーム倍率を保ったまま基準ノードを置き直す**。グラフ全体をキャンバスに収めるための縮小をしてはならない（MUST NOT）——コンテンツが増えるほどノードが縮み、地図として読めなくなるため。既定のズーム倍率は**等倍から 1 段階だけ縮小した固定値**とし、React Flow のズーム操作 1 回分（ズームインを 1 度押すとちょうど等倍になる倍率）としなければならない（SHALL）。グラフがキャンバスに収まらないときは**縦横とも切れてよい**（MAY）。基準ノードは、**現在地（`here`）のノードがあればそれをキャンバスの縦横中央**に、無ければ **`Start` ノードを横中央・上端（上に僅かな余白）**に置く。`Start` ノードも無いときはグラフ全体の外接箱の上端中央を同じ規則で置く。基準ノードの配置計算はズーム倍率を織り込まなければならない（SHALL）——倍率だけを変えて位置の式を等倍のままにすると基準がずれる
- **ミニ曼陀羅**（サムネイル・拡大モーダル）: 従来どおり**グラフ全体がキャンバスの中心へ収まるよう再フィット**する（ズーム倍率 1 が上限）——コース1件とその隣接だけを描くため大きさが増えず、収める挙動が適切である

**ただし全体曼陀羅は、曼陀羅をマウントした時点で全シリーズが折りたたまれていたときに限り、初回の表示と以後の置き直しをグラフ全体がキャンバスに収まる形で行わなければならない**（SHALL）。畳んだ姿はシリーズ数ぶんしか大きくならないため、収めても地図として読める。この収める表示には次が適用される:

- ズーム倍率は **1 を上限**としなければならない（SHALL）。ノードを実寸より拡大してはならない（MUST NOT）——ミニ曼陀羅と同じ規則にそろえる
- 収めるための縮小に**下限を設けない**（SHALL NOT）
- **シリーズを 1 つでも開閉したら収める表示を解除しなければならない**（SHALL）。解除後は同じマウントの間、**再び収める表示へ復帰してはならない**（MUST NOT）——畳み直したときに倍率が勝手に変わるのを避けるため
- マウント時点で 1 つ以上のシリーズが展開されていたとき（選択中のコースの所属シリーズが展開された場合、セッション内の記憶に展開が残っている場合）、および開閉を持たない面（ミニ曼陀羅・chrome 無しの全体曼陀羅）には、この例外を適用してはならない（MUST NOT）

この例外は閲覧者のズーム操作の**可動域**を変えてはならない（MUST NOT）——収める表示の上限は自動配置にのみ効き、ユーザーは従来どおりの範囲で拡大・縮小できる。

ただし**ユーザーがパン・ズームを開始したあとは置き直してはならない**（MUST NOT）——ユーザーの操作を巻き戻すことになるため。操作を受け付けないサムネイルはこの制限の対象外とする（MAY）。

置き直しの実行はブラウザの描画フレームに載せなければならない（SHALL）——寸法の観測と同一フレーム内で viewport を変更しないこと。

#### Scenario: 全シリーズが畳まれているときは全体が収まる

- **WHEN** 全シリーズが折りたたまれた状態で全体曼陀羅モーダルを開く
- **THEN** `Start` から `Goal` までグラフの外接箱が縦横とも視野に入る
- **AND** ズーム倍率は 1 を超えない

#### Scenario: 収める表示は一度開閉したら戻らない

- **WHEN** 全シリーズが畳まれた状態でモーダルを開いたあと、シリーズを 1 つ展開し、再び畳む
- **THEN** グラフ全体を収める表示は自動で行われない

#### Scenario: 全体曼陀羅は既定倍率で描かれる

- **WHEN** 1 つ以上のシリーズが展開され、グラフの高さがキャンバスの高さを超える状態で全体曼陀羅モーダルを開く
- **THEN** ズーム倍率は既定倍率（等倍より 1 段階小さい固定値）で、グラフ全体を収めるための追加の縮小は起きない
- **AND** キャンバスに収まらない部分は表示されない

#### Scenario: ズームインを 1 回押すと等倍になる

- **WHEN** 1 つ以上のシリーズが展開された全体曼陀羅モーダルを開き、Controls のズームインを 1 回押す
- **THEN** ズーム倍率はちょうど 1（等倍）になる

#### Scenario: コースを選んでいるときは現在地が中央に来る

- **WHEN** コースを選択した状態で全体曼陀羅モーダルを開く
- **THEN** そのコースのノードがキャンバスの縦横中央に置かれる

#### Scenario: 選択が無いときは Start が基準になる

- **WHEN** ホーム（全体）を選択し、1 つ以上のシリーズが展開された状態で全体曼陀羅モーダルを開く
- **THEN** `Start` ノードがキャンバスの横中央・上端付近に置かれる

#### Scenario: ペインのリサイズに追随する

- **WHEN** ミニ曼陀羅サムネイルを表示した状態でペインの幅を変える
- **THEN** サムネイルのグラフはセルの新しい寸法に合わせて収まり直す

#### Scenario: パンしたあとは勝手に戻らない

- **WHEN** ユーザーが全体曼陀羅をパンまたはズームしたあと、ウィンドウの大きさを変える
- **THEN** グラフの表示位置は置き直しで巻き戻されない

### Requirement: モーダルの曼陀羅は公開サイトと同じ構成で組む

全体曼陀羅モーダルおよびミニ曼陀羅の拡大モーダルは、公開サイトの曼陀羅モーダルと同じ構成で組まなければならない（SHALL）。

- **ダイアログは高さを持たず、中身なりに決まる**（SHALL）。ダイアログに固定高やフレックス配分を与えて曼陀羅の高さを配ってはならない（MUST NOT）
- **曼陀羅キャンバスだけが、ビューポート由来の絶対長（`vh` と上限の `min()`）を持つ**（SHALL）。値は、ダイアログの見出し・余白・ツールバーを足してもビューポートに収まるよう選ぶ（SHALL）
- **ダイアログはマウント時に寸法や変形が変わる開閉アニメーションを持ってはならない**（MUST NOT）

理由: React Flow はマウント時に一度だけコンテナを測って座標を確定する。ダイアログ側が高さを配る構成では、レイアウトが落ち着く前にマウントすると確定した座標と最終の寸法が食い違い、**モーダルを開き直すたびに中心がずれる**（初回だけ遅延読み込みでマウントが遅れ、偶然正しく見える）。キャンバスが絶対長ならマウントの時点で幾何が確定しており、マウントのタイミングに依存しない。親いっぱい（パーセント）モードをモーダルで使ってはならない（MUST NOT）——祖先のどこかで高さが不確定になった時点で 0px に潰れる（error #004）。

親いっぱいモード自体はサムネイル用に残す。そこでは React Flow のルートがパーセント高さに依存してはならず（MUST NOT）、祖先の高さが確定していなくても実寸を得られる方法（絶対配置など）で埋めなければならない（SHALL）。

#### Scenario: 開き直しても中心が合う

- **WHEN** 全体曼陀羅モーダルを開き、閉じ、すぐに開き直す
- **THEN** どの回でもグラフはキャンバスの中心に収まっている

#### Scenario: React Flow のルートが実寸を持つ

- **WHEN** 全体曼陀羅モーダル・ミニ曼陀羅の拡大モーダル・サムネイルをそれぞれ表示する
- **THEN** いずれも React Flow のルート要素は幅・高さともに 0 より大きい
- **AND** コンソールに「The parent container needs a width and a height」（error #004）は出ない

#### Scenario: ダイアログがビューポートに収まる

- **WHEN** ビューポートの高さが小さい環境で全体曼陀羅モーダルを開く
- **THEN** ダイアログ全体（見出し・ツールバー・キャンバス）がビューポートの中に収まる

### Requirement: ミニ曼陀羅に中心コース自身の Start / Goal を出す

ミニ曼陀羅（サムネイル・拡大モーダルとも）は、**中心コース自身**が入口（`is_start`）または出口（`is_goal`）を宣言しているとき、Start / Goal の文字ノードを描かなければならない（SHALL）。

中心コース以外のノード（シリーズ内の前後・跨ぎの相手・ゴースト）が持つ入口・出口の宣言を拾ってはならない（MUST NOT）——ミニ曼陀羅は中心とその隣接 1 段だけを映す地図であり、2 段先の情報を混ぜないため。

#### Scenario: 入口のコースを開くと Start が出る

- **WHEN** `is_start` を宣言しているコースを選択してミニ曼陀羅を表示する
- **THEN** そのコースの手前に Start の文字ノードが辺で繋がって描かれる

#### Scenario: 隣のコースの入口宣言は拾わない

- **WHEN** 入口のコースを 1 個前に持つ（自身は `is_start` でない）コースを選択してミニ曼陀羅を表示する
- **THEN** 1 個前のコースは描かれるが、そのさらに手前の Start は描かれない

#### Scenario: 出口のコースを開くと Goal が出る

- **WHEN** `is_goal` を宣言しているコースを選択してミニ曼陀羅を表示する
- **THEN** そのコースの先に Goal の文字ノードが辺で繋がって描かれる

### Requirement: 曼陀羅の配色は公開サイトの曼陀羅に合わせる

Studio の曼陀羅の配色は、ライトテーマにおいて公開サイトの曼陀羅と同じ見た目にならなければならない（SHALL）。

キャンバスの地は、曼陀羅を「特別な箱」に見せない薄さでなければならない（SHALL）。ページやカードの地と同じ不透明色を用いてはならない（MUST NOT）。

配色はテーマごとの上書きではなく、テーマの役割トークンに対する割合として 1 本のレシピで書かなければならない（SHALL）。曼陀羅の中で固定の色値をテーマ非依存で用いてはならない（MUST NOT）——暗い地で沈む、明るい地で浮くといった破れを避けるため。

受講形態のラベルは、ライト・ダーク・ピンクのいずれのテーマでも地と字のコントラストが保たれなければならない（SHALL）。

#### Scenario: ライトでサイトと同じ地に見える

- **WHEN** ライトテーマで Studio の曼陀羅とサイトの曼陀羅を並べて見る
- **THEN** キャンバスの地・ノードの枠・受講形態ラベル・Start / Goal の色は同じに見える

#### Scenario: キャンバスが箱に見えない

- **WHEN** 白いモーダルの中で曼陀羅を表示する
- **THEN** キャンバスの領域が塗られた矩形として浮かず、地続きに見える

#### Scenario: ダークでラベルが沈まない

- **WHEN** ダークテーマで曼陀羅を表示する
- **THEN** 受講形態のラベルは地に対して読めるコントラストを保つ

### Requirement: compact とサムネイルのノード名は折り返して全体を表示する

全体曼陀羅の compact ノード・折りたたみシリーズノード・ミニ曼陀羅のサムネイルノードは、名前を**折り返して全体を表示**しなければならない（SHALL）。`…` による切り詰めをしてはならない（SHALL NOT）。名前の全体を見せるためのツールチップ（`WorkspaceTooltip` 等）をノードに置いてはならない（SHALL NOT）——折り返しで全体が見えるため不要であり、ラッパを外すことで React Flow のノード計測に介在する DOM も減る。

compact ノードでは受講形態ラベルの居場所を残し、名前は残り幅で折り返す（SHALL）。各ノードの寸法と折り返し行数の上限は、翻訳契約の上限（半角 36 字）が収まる実測値でなければならない（SHALL）——ラベルの有無でタイトル領域の幅が変わるため、種別ごとに測って決める。サムネイルノードは全体曼陀羅の compact ノードより狭いことを保つ（SHALL）。寸法を変えるときは `Mandala.tsx` の `SIZES` と CSS を同時に変える（SHALL）。

#### Scenario: 英語モードの全体曼陀羅で長い名前が全部見える

- **WHEN** 英語モードで全体曼陀羅モーダルを開き、36 字のコース名のノードを見る
- **THEN** 名前は折り返されて末尾まで読め、受講形態ラベルは右端に残る
- **AND** ノードにホバーしてもツールチップは出ない

#### Scenario: サムネイルでも折り返す

- **WHEN** 英語モードのペイン2 コースビューでミニ曼陀羅サムネイルを見る
- **THEN** 36 字以内の名前は末尾まで読め、`…` は出ない

### Requirement: シリーズ枠は互いに重なってはならない

全体曼陀羅のシリーズ枠は、**どの 2 つを取っても矩形が重なってはならない**（MUST NOT）——枠が食い込むと、どのコースがどのシリーズに属するのかが読み取れなくなる。枠の非重なりは配置の副作用ではなく、レイアウトが保証しなければならない（SHALL）。

保証は**レイアウト段階でシリーズを 1 つのまとまりとして扱う**ことで得なければならない（SHALL）——配置後に枠をずらして回避してはならない（MUST NOT）。同じシリーズのコースは、レイアウト上ひとかたまりに配置されなければならない（SHALL）。

非重なりは**シリーズが横に押し出されることで実現してよい**（MAY）。グラフの横幅が増えて画面に収まらなくなることは許容する（MAY）——収まらない部分は閲覧者がパン・ズーム・ミニマップで見る。**段（rank）の間隔をシリーズのまとまり化のために変えてはならない**（MUST NOT）——縦に間延びすると 1 画面に入るコース数が減り、地図としての価値が下がる。

折りたたまれたシリーズはまとまり化の対象外とする（SHALL）——枠を持たない 1 つの集約ノードなので、囲う対象が無い。集約ノードは他のシリーズ枠の内側に置かれてはならない（MUST NOT）。

#### Scenario: 枝分かれしたシリーズの枠が重ならない

- **WHEN** あるシリーズのコースから別シリーズのコースへ辺が伸び、両者が同じ段に並ぶ全体曼陀羅を描画する
- **THEN** 2 つのシリーズ枠の矩形は重ならない

#### Scenario: シリーズが全体に跨っても重ならない

- **WHEN** 1 つのシリーズのコースが最上段と最下段の両方にあり、その間に他のシリーズが挟まる全体曼陀羅を描画する
- **THEN** どのシリーズ枠どうしも重ならない

#### Scenario: 一部を折りたたんでも重ならない

- **WHEN** 一部のシリーズを折りたたんだ状態の全体曼陀羅を描画する
- **THEN** 展開中のシリーズ枠どうしは重ならない
- **AND** 折りたたんだシリーズの集約ノードは、いずれのシリーズ枠の内側にも入らない

#### Scenario: まとまり化で段の間隔が変わらない

- **WHEN** シリーズをまとまりとして配置した全体曼陀羅と、まとまり化しない場合の配置を比べる
- **THEN** 段と段の縦の間隔は同じである

#### Scenario: 全て折りたたんでも段の間隔が変わらない

- **WHEN** すべてのシリーズを折りたたんだ（まとまりが 1 つも無い）全体曼陀羅を描画する
- **THEN** 段と段の縦の間隔は、展開時と同じである

### Requirement: 全体曼陀羅のシリーズの横順は折りたたみで変わらない

全体曼陀羅において、**縦の範囲が重なるシリーズどうしの左右の並びは、シリーズの正本順**（`contents.meta.json` の `order`）でなければならない（SHALL）。この並びは、どのシリーズを折りたたんでも・展開しても変わってはならない（MUST NOT）——畳むたびに地図が組み替わると位置の記憶が効かなくなる。折りたたまれたシリーズの集約ノードは、展開時にそのシリーズ枠があった側に置かれなければならない（SHALL）。

縦の範囲が重ならないシリーズの組（段で上下に積まれるもの）は横の順番を持たないため、本要件の対象外とする（SHALL）。

並びの保証は、シリーズの非重なり（「シリーズ枠は互いに重なってはならない」）を損なってはならない（MUST NOT）——並べ直すときはシリーズのブロックの幅と隙間を保ち、ブロック内の相対配置を変えてはならない（MUST NOT）。判定規則は公開サイトと一致していなければならない（SHALL）。

#### Scenario: シリーズを折りたたんでも左右が入れ替わらない

- **WHEN** 正本順で A、B の順に並ぶ 2 つのシリーズが同じ横帯にあり、A を折りたたむ
- **THEN** A の集約ノードは B のシリーズ枠より左に表示される

#### Scenario: 展開し直しても元の並びに戻る

- **WHEN** 折りたたんだ A を再び展開する
- **THEN** A のシリーズ枠は B のシリーズ枠より左に表示される

#### Scenario: 上下に積まれたシリーズは対象外

- **WHEN** シリーズ B のコースからシリーズ C のコースへ辺が伸び、C が B の下の段に置かれる
- **THEN** B と C の左右関係は規定されず、折りたたみで C の縦位置が保たれる

#### Scenario: 並べ直しても枠は重ならない

- **WHEN** 並びを正本順へ直す必要がある状態の全体曼陀羅を描画する
- **THEN** 展開中のシリーズ枠どうしは重ならず、各シリーズ内のコースの相対配置は並べ直す前と同じである

#### Scenario: ツールバーのチップと地図の並びが一致する

- **WHEN** 全体曼陀羅をツールバー付きで表示する
- **THEN** 同じ横帯にあるシリーズの左右の並びは、ツールバーのシリーズチップの並びと同じ順である

### Requirement: モーダルの全体曼陀羅はダブルクリックでシリーズを開閉できる

モーダルで開いた全体曼陀羅では、展開中のシリーズ枠または折りたたんだシリーズの集約ノードを**ダブルクリック**すると、そのシリーズの折りたたみ・展開がトグルされなければならない（SHALL）。1 回目のクリックでそのシリーズが選択されることは許容する（MAY）。コースノードのダブルクリックは開閉の対象としない（SHALL NOT）。ダブルクリックでキャンバスをズームしてはならない（MUST NOT）。

ミニ曼陀羅・サムネイルは本要件の対象外とする（SHALL）。

#### Scenario: 枠のダブルクリックで折りたたむ

- **WHEN** モーダルの全体曼陀羅で、展開中のシリーズ枠をダブルクリックする
- **THEN** そのシリーズが折りたたまれ、集約ノードになる
- **AND** ツールバーの当該チップは折りたたみ表示になる

#### Scenario: 集約ノードのダブルクリックで展開する

- **WHEN** モーダルの全体曼陀羅で、折りたたんだシリーズの集約ノードをダブルクリックする
- **THEN** そのシリーズが展開され、コースノードとシリーズ枠が表示される

#### Scenario: 1 回目のクリックで選択されてもモーダルは開いたまま

- **WHEN** モーダルの全体曼陀羅で、シリーズ枠をダブルクリックする
- **THEN** そのシリーズが選択され、かつモーダルは閉じずに開閉がトグルされる

### Requirement: モーダルの全体曼陀羅は開閉状態を記憶する

モーダルで開いた全体曼陀羅の**既定は全シリーズ折りたたみ**でなければならない（SHALL）——公開サイトの全体曼陀羅と同じ既定にする。

開閉状態は**閲覧セッションの間だけ**記憶しなければならない（SHALL）。モーダルの開き直しと日本語／英語ビューの切替を跨いで保持されなければならず（SHALL）、**Studio の起動・リロードでは既定（全折りたたみ）に戻ってよい**（MAY）。端末の永続保存領域（`localStorage` 等）に書いてはならない（MUST NOT）。

記憶するのは**展開しているシリーズ**の集合でなければならない（SHALL）。折りたたんでいる側を記憶してはならない（MUST NOT）——既定が全折りたたみであるため、記録の無いシリーズ（実行中に新しく作られたものを含む）は既定と同じ「折りたたみ」で現れる必要があるためである。記録に無いシリーズを掃除する処理を持つ必要はない（MAY 省略）。

日本語モードと英語モードは同じ記憶を共有しなければならない（SHALL）——開閉は編集言語の属性ではない。

**コースを選択した状態でモーダルを開いたときは、そのコースが属するシリーズを、記憶で折りたたまれていても展開して表示**しなければならない（SHALL）——現在地が集約ノードに隠れた地図を開いても役に立たない。この展開は記憶にも反映される（SHALL）。**シリーズだけを選択しているときは展開してはならない**（MUST NOT）——現在地の印は集約ノードが引き取る。

復元は**最初の描画に間に合わせ**なければならない（SHALL）——記憶と異なる姿が一瞬見えてから切り替わってはならない（MUST NOT）。

ミニ曼陀羅・サムネイルは記憶も既定の変更も対象外とする（SHALL NOT）。

#### Scenario: 開いた状態で次回も開く

- **WHEN** モーダルの全体曼陀羅でシリーズ A を展開し、モーダルを閉じて再び開く
- **THEN** A は展開された状態で表示され、他のシリーズは折りたたまれている

#### Scenario: 記憶が無いときは全シリーズが折りたたまれている

- **WHEN** Studio を起動して最初にモーダルの全体曼陀羅を開く
- **THEN** すべてのシリーズが集約ノードとして表示され、コースノードは1つも見えない

#### Scenario: 選択コースの祖先は展開される

- **WHEN** すべて折りたたまれた状態で、あるコースを選択してモーダルを開く
- **THEN** そのコースが属するシリーズは展開され、選択中のコースノードが現在地として強調されている
- **AND** モーダルを閉じてホームを選択して開き直しても、そのシリーズは展開されている

#### Scenario: シリーズだけの選択では折りたたまれたまま

- **WHEN** シリーズ A だけを選択してモーダルを開く
- **THEN** A は折りたたまれたままで、集約ノードが現在地として強調されている

#### Scenario: 編集言語を切り替えても記憶が残る

- **WHEN** 日本語モードでシリーズ A を展開し、英語モードへ切り替えてモーダルを開く
- **THEN** A は展開された状態で表示される

#### Scenario: リロードで既定に戻る

- **WHEN** シリーズ A を展開したあと Studio をリロードしてモーダルを開く
- **THEN** すべてのシリーズが折りたたまれた状態で表示される

#### Scenario: 最初の描画から記憶が反映されている

- **WHEN** シリーズ A を展開した記憶がある状態でモーダルを開く
- **THEN** 最初に描画された時点で A は展開されており、全折りたたみの状態は一度も表示されない

### Requirement: 現在地ピンの塗りは透過とする

現在地ピン（`MapPin`）の塗り（fill）は透過でなければならない（SHALL）——ピンはノードの左外＝キャンバス上に置かれるため、塗りが不透明だと背景や辺が隠れて浮いて見える。ピンの輪郭線の色・太さ・サイズ・配置はこの要件の対象外であり、従来どおりとする。

#### Scenario: ピンの背景が透ける

- **WHEN** 現在地のあるコースノードまたはシリーズ枠のピンを表示する
- **THEN** ピンの内側は塗りつぶされず、キャンバスの背景が透けて見える
