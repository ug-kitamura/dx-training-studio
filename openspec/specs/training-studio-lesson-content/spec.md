## Requirements
### Requirement: レッスンメタ編集モーダル

Pane3 ヘッダー最右の操作から、レッスンメタ編集ダイアログを開けなければならない（SHALL）。ダイアログは次の項目を提供しなければならない（SHALL）: シリーズ（読取・1件・日本語名）; コース（読取・1件・日本語名）; レッスン（編集可・単一行）; ステータス（`open` / `in_progress` / `done` から選択・アイコン表示・既定 `open`）; 説明＝講義内容（編集可・**3行の複数行入力**）; タグ（編集可・複数・各要素は小文字英字・数字・ハイフンのみ）; 推定所要時間（分）（0–180 の整数・既定 0）; 著者（編集可・単一行・既定空）。

編集フィールドの並び順は **レッスン名 → 講義内容 → スラッグ → タグ → 著者 → 所要時間・進捗** としなければならない（SHALL）。ステータス選択肢のアイコンはすべて `muted-foreground`（サブテキスト色）で表示しなければならない（SHALL）——状態ごとの色分け（緑・黄・グレー）は用いない。

メタ保存はレッスン `.meta.json` のみを更新しなければならず（SHALL）、`contents.md` を書き換えてはならない（SHALL NOT）。

#### Scenario: シリーズとコースは編集できない

- **WHEN** レッスンメタ編集ダイアログを開く
- **THEN** シリーズとコースは読取表示のみである
- **AND** 表示名はワークスペース上の親の日本語名である

#### Scenario: フィールドの並び順

- **WHEN** レッスンメタ編集ダイアログを開く
- **THEN** 上からレッスン名・講義内容・スラッグ・タグ・著者・所要時間／進捗の順に並ぶ
- **AND** 講義内容は3行分の高さの複数行入力である

#### Scenario: ステータスアイコンがサブテキスト色である

- **WHEN** ステータスの選択肢を開く
- **THEN** 未着手・作成中・完成のアイコンはいずれも `muted-foreground` のグレーで表示される

#### Scenario: メタ保存で Lesson と `.meta.json` が更新される

- **WHEN** ユーザーがメタを編集して保存する
- **THEN** 対応する `Lesson` のフィールドが更新される
- **AND** レッスン `.meta.json` に正規化された値が書き込まれ、`contents.md` は変更されない

### Requirement: Pane3 ヘッダーとモード切替

Pane3 のツールバー（高さ `h-12`）は、左に現在レッスンの日本語名（`lesson` フィールド）を表示しなければならない（SHALL）。モード切替（編集モード・プレビュー・差分）は右寄せで表示しなければならない（SHALL）。レッスンメタ編集の入口はツールバー最右に配置しなければならない（SHALL）。「ファイルを開く」操作を Pane3 に表示してはならない（MUST NOT）。編集モードの表示ラベルは「編集モード」とし、「Markdown」という表記を用いてはならない（MUST NOT）。

#### Scenario: ヘッダーにレッスン名とメタ編集がある

- **WHEN** レッスンが選択され Pane3 が表示される
- **THEN** ツールバー左にレッスン名が表示される
- **AND** ツールバー最右からメタ編集を開ける

#### Scenario: モードタブは右寄せ

- **WHEN** Pane3 ツールバーを表示する
- **THEN** 編集モード・プレビュー・差分のタブ群はレッスン名の右側（右寄せ）に配置される

#### Scenario: ファイルを開くがない

- **WHEN** Pane3 ツールバーを表示する
- **THEN** 「ファイルを開く」ボタンは存在しない

### Requirement: 編集モードの行番号

編集モードでは、エディタの左に 1 始まりの行番号を表示しなければならない（SHALL）。行番号は薄いグレーで視覚的に控えめとし、縦スクロールは編集領域と一体で同期しなければならない（SHALL）。

#### Scenario: 行番号が編集領域と同期スクロールする

- **WHEN** ユーザーが編集モードで縦スクロールする
- **THEN** 行番号ガターも同じスクロール位置に追随する

### Requirement: 編集モードの Markdown シンタックスハイライト

編集モードのエディタは、ライト時は VS Code または Cursor で Markdown を編集する場合と同等のシンタックスハイライトを提供しなければならない（SHALL）。ダーク時は **Cursor 現在のエディタ**に近い配色としなければならない（SHALL）。少なくとも次の要素を色分けして識別可能にしなければならない（SHALL）: ATX 見出し（`#` 〜 `######`）; 強調（`**` / `*`）; インラインコードとフェンスコードブロック; リストマーカー; リンク; GFM タスクリスト（`- [ ]` / `- [x]`）。

#### Scenario: 見出しとリストが色分けされる

- **WHEN** ユーザーが `## 見出し` と `- 項目` を含むレッスンを編集モードで開く
- **THEN** 見出し行とリスト行がプレーンテキスト1色のみでは表示されない

#### Scenario: ダークで Cursor 風のコントラスト

- **WHEN** テーマが `dark` である
- **AND** ユーザーが編集モードを表示する
- **THEN** 背景とシンタックス色のコントラストが Cursor のダークエディタと同程度に読める

### Requirement: 編集モードのドキュメント全体検索と置換

編集モードのエディタは、画面に描画されていない範囲を含むドキュメント全体を対象に検索できなければならない（SHALL）。仮想スクロールによって未描画となっている行のテキストも検索対象に含めなければならない（SHALL）。検索の起動はブラウザ純正の検索ではなく、エディタ自身が提供する検索パネルでなければならない（SHALL）。検索パネルの起動手段は Ctrl+F のみとし、ヘッダー等に検索ボタンを設けてはならない（MUST NOT）。

検索パネルは置換（Replace / Replace All）を提供しなければならない（SHALL）。置換の対象範囲はドキュメント全体（本文全体）としなければならない（SHALL）。

検索パネルの見た目（背景・border・角丸・ボタン・入力欄・チェックボックス）は、CodeMirror の OS 標準デザインのままではなく、ワークスペース全体のデザイントークンと統一されていなければならない（SHALL）。検索の挙動そのものはエディタ標準機能に委ね、自前の検索 UI を実装してはならない（MUST NOT）。

#### Scenario: スクロールしないと見えない箇所のテキストがヒットする

- **WHEN** ユーザーが長いレッスンを編集モードで開き、画面外にあるキーワードを Ctrl+F で検索する
- **THEN** 画面外のキーワードがヒットし、該当箇所へジャンプできる

#### Scenario: 画面内のテキストも引き続きヒットする

- **WHEN** ユーザーが現在画面に表示されているキーワードを Ctrl+F で検索する
- **THEN** 当該キーワードがヒットする

#### Scenario: 検索パネルの見た目がワークスペースのデザインと統一されている

- **WHEN** ユーザーが Ctrl+F で検索パネルを開く
- **THEN** パネルの背景・border・角丸・ボタン・入力欄が、ワークスペースの他の UI と調和した見た目になる

#### Scenario: ライトとダークの双方で見た目が破綻しない

- **WHEN** テーマが `light` または `dark` である
- **AND** ユーザーが Ctrl+F で検索パネルを開く
- **THEN** いずれのテーマでも背景色・文字色・border がテーマ側の値で解決され、文字が読めない状態にならない

#### Scenario: Replace 行は Find 行と別の行に表示される

- **WHEN** ユーザーが Ctrl+F で検索パネルを開く
- **THEN** Find 行（検索欄・next・previous・match case・regexp）と Replace 行（置換欄・replace・replace all）は別々の行に表示される

#### Scenario: all ボタンと by word オプションは表示されない

- **WHEN** ユーザーが Ctrl+F で検索パネルを開く
- **THEN** 「all」（全件選択）ボタンおよび「by word」（単語単位一致）チェックボックスは表示されない

#### Scenario: 検索パネルの開閉状態はレッスン切替をまたいで保持される

- **WHEN** ユーザーがレッスン A の編集モードで検索パネルを開き、レッスン B に切り替えたうえで A に戻る
- **THEN** レッスン A の検索パネルは開いた状態で復元される

#### Scenario: 検索パネルを閉じた後も通常の編集操作に影響しない

- **WHEN** ユーザーが検索パネルを閉じ、本文を編集する
- **THEN** 入力・undo/redo・自動保存は検索機能の追加前と同じように動作する

### Requirement: 編集モードの表示折りたたみ

編集モードは表示のみの折りたたみを提供しなければならない（SHALL）。折りたたみはソース文字列を変更してはならない（MUST NOT）。行頭 ATX 見出し `#` から `######` までの各見出しを折りたたみ可能にしなければならない（SHALL）。見出しを折りたたんだとき、当該見出し行自体はエディタ上に表示し続けなければならない（SHALL）。子孫見出しおよび本文行のみを非表示にしなければならない（SHALL）。見出しの折り範囲は、VS Code の Markdown 見出しフォールドと同等とし、見出しレベル L に対し次行から「レベルが L 以下の次の見出し」の直前までを隠すこととする（SHALL）。折りたたみ操作はガター上の折りたたみアイコン（`▶` / `▼`）で行えなければならない（SHALL）。

折りたたみ済みを示す `▶` は常に表示しなければならない（SHALL）。展開中の折りたためる見出しを示す `▼` は、**行番号列を含むガター全体（`.cm-gutters`）**のいずれかにマウスカーソルがある間、表示しなければならない（SHALL）。折りたたみ列だけをホバー条件としてはならない（MUST NOT）。ガターからマウスが外れたとき `▼` を隠さなければならない（SHALL）。

`▼` の表示条件は CSS で表現しなければならない（SHALL）。ホバー状態を JS で監視して class を付け外しする実装であってはならない（MUST NOT）。

折りたたみ**操作**の当たり判定は折りたたみ列に限る（SHALL）。行番号列のクリックで折りたたみを実行してはならない（MUST NOT）。

#### Scenario: 見出しを折りたたむと見出し行だけ残る

- **WHEN** ユーザーが `## セクション` の直下に本文があるレッスンで当該見出しを折りたたむ
- **THEN** `## セクション` の行は表示されたままである
- **AND** その直下の本文行は表示されない

#### Scenario: 子見出しは親見出しの折りたたみに含まれる

- **WHEN** ユーザーが `## 親` の下に `### 子` と本文がある状態で `## 親` を折りたたむ
- **THEN** `### 子` の行およびその本文も表示されない

#### Scenario: 初回表示はすべて展開

- **WHEN** ユーザーがレッスンを選択して編集モードを表示する、または別レッスンに切り替えて編集モードを表示する
- **THEN** すべての見出しは展開された状態である

#### Scenario: 行番号の上にマウスがあるとき折りたたみアイコンが見える

- **WHEN** ユーザーが編集モードで行番号列にマウスカーソルを乗せる
- **THEN** 折りたためる見出し行の `▼` が表示される

#### Scenario: 折りたたみ列の上でも従来どおり見える

- **WHEN** ユーザーが折りたたみ列にマウスカーソルを乗せる
- **THEN** 折りたためる見出し行の `▼` が表示される

#### Scenario: ガターから離れると隠れる

- **WHEN** ユーザーがマウスカーソルをガターの外（本文領域）へ移動する
- **THEN** `▼` は表示されなくなる
- **AND** 折りたたみ済みの `▶` は表示されたままである

### Requirement: Pane4 からの Markdown 挿入

編集モードが表示されているとき、Pane4 の画像挿入操作は、エディタの現在のカーソル（選択）位置に Markdown 文字列を挿入しなければならない（SHALL）。挿入する URL は data URL ではなく `images/<filename>` 形式の相対パスとしなければならない（SHALL）。`images/uploaded/`・`images/ai/`・`images/web/` を挿入 URL に用いてはならない（MUST NOT）。AI タブからの挿入では `alt` に生成 API が返した **短い説明** を用いなければならない（SHALL）。UP タブからの挿入では従来どおりファイル名等を alt に用いてよい（MAY）。選択範囲がある場合は当該範囲を画像 Markdown に置換し、選択がない場合はカーソル位置に挿入しなければならない（SHALL）。挿入後、カーソルは挿入文字列の直後に置かれなければならない（SHALL）。プレビューモード・差分モード表示中に挿入操作を行った場合、挿入は行われず、ユーザーに編集モードへの切替を促すフィードバックを表示してよい（MAY）。

挿入による本文変更と手入力による本文変更は、**同じ保存経路**（表示中の言語の本文）へ流れなければならない（SHALL）。片方だけが別の言語の本文へ流れてはならない（MUST NOT）——英語ビューでの挿入と手削除が別のファイルに分かれると、英語プレビューに旧画像と新画像が同時に残る。

#### Scenario: 編集モードで画像 Markdown が挿入される

- **WHEN** ユーザーが編集モードでレッスンを開き、Pane4 から画像を挿入する
- **THEN** カーソル位置または選択範囲に `![...](images/<filename>)` 形式の文字列が反映される
- **AND** エディタはフォーカスを維持する

#### Scenario: AI 挿入は短い alt を含む

- **WHEN** ユーザーが AI タブから alt `commit から push まで` の画像を挿入する
- **THEN** 挿入文字列は `![commit から push まで](images/…)` 形式である

#### Scenario: data URL では挿入しない

- **WHEN** ユーザーが Pane4 から画像を挿入する
- **THEN** 挿入文字列に `data:` で始まる URL は含まれない

#### Scenario: プレビュー中は挿入されない

- **WHEN** ユーザーがプレビューモードを表示している
- **AND** Pane4 から挿入操作を行う
- **THEN** エディタ content は変更されない

#### Scenario: 英語ビューでの挿入と手削除が同じ本文に反映される

- **WHEN** 英語ビューの編集モードで画像を挿入し、続けて既存の画像行を手で削除する
- **THEN** 英語プレビューには新しい画像だけが表示される
- **AND** `contents.md` は変更されない

#### Scenario: 編集モードで画像 Markdown が挿入される

- **WHEN** ユーザーが編集モードでレッスンを開き、Pane4 から画像を挿入する
- **THEN** カーソル位置または選択範囲に `![...](images/<filename>)` 形式の文字列が反映される
- **AND** エディタはフォーカスを維持する

#### Scenario: AI 挿入は短い alt を含む

- **WHEN** ユーザーが AI タブから alt `commit から push まで` の画像を挿入する
- **THEN** 挿入文字列は `![commit から push まで](images/…)` 形式である

#### Scenario: data URL では挿入しない

- **WHEN** ユーザーが Pane4 から画像を挿入する
- **THEN** 挿入文字列に `data:` で始まる URL は含まれない

#### Scenario: プレビュー中は挿入されない

- **WHEN** ユーザーがプレビューモードを表示している
- **AND** Pane4 から挿入操作を行う
- **THEN** エディタ content は変更されない

### Requirement: プレビューは本文を GFM で表示する

プレビューモードは `content`（本文）を `react-markdown` でレンダリングし、GitHub Flavored Markdown（タスクリスト等）を有効にしなければならない（SHALL）。Typography は読みやすい資料向けのスタイル（例: `prose`）を用いなければならない（SHALL）。

#### Scenario: プレビューに本文が表示される

- **WHEN** ユーザーがプレビューモードを開く
- **THEN** 本文の見出し・段落が表示される

### Requirement: プレビューは details 折りたたみを描画する

プレビューモードでは、本文中の `<details>` / `<summary>` タグを折りたたみ要素としてレンダリングしなければならない（SHALL）。`<details open>` の `open` 属性を尊重しなければならない（SHALL）。raw HTML の有効化はサニタイズを伴わなければならず（SHALL）、`<script>` 要素をレンダリングしてはならない（MUST NOT）。

#### Scenario: details が折りたたみとして表示される

- **WHEN** 本文に `<details><summary>答え</summary>本文</details>` を含むレッスンをプレビューする
- **THEN** 「答え」を見出しとする折りたたみ要素が表示される
- **AND** クリックで中身の「本文」が展開される

#### Scenario: script はレンダリングされない

- **WHEN** 本文に `<script>` タグを含むレッスンをプレビューする
- **THEN** script 要素は DOM に出力されない

### Requirement: プレビューは GitHub アラートを色分け描画する

プレビューモードでは、blockquote 先頭行が `[!NOTE]` / `[!TIP]` / `[!IMPORTANT]` / `[!WARNING]` / `[!CAUTION]` のいずれかである引用を、GitHub アラートとして種別ごとに識別可能な色付き囲み（NOTE=青 / TIP=緑 / IMPORTANT=紫 / WARNING=黄 / CAUTION=赤 の系統色）でレンダリングしなければならない（SHALL）。配色はライト・ダーク両テーマで成立しなければならない（SHALL）。アラート記法でない通常の blockquote の表示を変えてはならない（MUST NOT）。

#### Scenario: NOTE アラートが色付きで表示される

- **WHEN** 本文に `> [!NOTE]` で始まる blockquote を含むレッスンをプレビューする
- **THEN** 青系統の色付き囲みとしてレンダリングされる
- **AND** `[!NOTE]` の生テキストは本文として表示されない

#### Scenario: 5 種が識別可能に描画される

- **WHEN** 本文に 5 種のアラートをすべて含むレッスンをプレビューする
- **THEN** 各アラートが種別ごとに異なる色で表示される

#### Scenario: 通常の blockquote は従来どおり

- **WHEN** 本文にアラート記法でない `> 引用文` を含むレッスンをプレビューする
- **THEN** 従来と同じ引用スタイルで表示される

### Requirement: 全角約物に隣接する強調を描画する

プレビューモードでは、強調の閉じ記号が全角約物に隣接する CJK 文（例: `**3つの場所（三大エリア）**を`）についても、強調（太字）としてレンダリングしなければならない（SHALL）。

#### Scenario: 全角括弧で閉じる太字が成立する

- **WHEN** 本文に `この**3つの場所（三大エリア）**を地図として手に入れます` を含むレッスンをプレビューする
- **THEN** 「3つの場所（三大エリア）」が太字で表示される
- **AND** `**` の生テキストは表示されない

### Requirement: コードブロックは編集モードと同一のフォントで描画する

レッスン本文のコード用フォントスタックは 1 箇所（CSS カスタムプロパティ）で定義しなければならず（SHALL）、編集モード（CodeMirror）・プレビュー・差分ビューはいずれもその定義を参照しなければならない（SHALL）。プレビューのコードブロック（`pre code`）に、編集モードと異なるフォントスタックを指定してはならない（MUST NOT）。

このフォントスタックは、罫線素片・全角文字・半角文字が同一フォントから供給されるものでなければならない（SHALL）。ASCII だけが別フォントになるスタック（例: 罫線素片や日本語のグリフを持たない欧文フォントを先頭に置く指定）を用いてはならない（MUST NOT）。

#### Scenario: 編集モードで揃うアスキーアートがプレビューでも揃う

- **WHEN** 罫線素片と全角文字・半角文字が混在するアスキーアートをコードブロックに含むレッスンを開く

### Requirement: 差分モードは content 全文を表示する

差分モードでは、当該レッスンの `content` 文字列全体（フロントマターと本文）について、**現在のワークスペース状態（メモリ上の `lesson.content`）** を変更後側、**git HEAD 上の正本** を変更前側として unified diff を表示しなければならない（SHALL）。差分表示は追加行（`+`）・削除行（`-`）・コンテキスト行を識別可能な色分けで表示しなければならない（SHALL）。差分の取得は **ユーザーが差分タブを選択したとき** に行わなければならない（SHALL）。編集モード表示中にバックグラウンドで差分を更新してはならない（MUST NOT）。差分表示は読み取り専用でなければならない（SHALL）。

HEAD 上の正本は次の順序で解決しなければならない（SHALL）:

1. `contents/{series}/{course}/{lesson}.md`（`series` / `course` / `lesson` は当該 `Lesson` の日本語名フィールド。リポジトリ root からの相対パスはモノレポ時 `dx-training-studio/contents/...`）を **`git show HEAD:` で取得**する。パスに **スペースまたは日本語** が含まれる場合も正本を取得できなければならない（SHALL）。シェル文字列連結による `git show` で引数分割が起きない実装としなければならない（SHALL）。
2. (1) が存在しない場合、正本は空文字列とする（新規レッスン）

差分 API はクライアントから `lessonId`・`content`（現在全文）・パス解決用の `series` / `course` / `lesson` を受け取らなければならない（SHALL）。レスポンスは unified diff 文字列を含まなければならない（SHALL）。変更が無い場合は空 diff とし、UI は「差分なし」を表示しなければならない（SHALL）。

#### Scenario: フロントマター変更が差分に含まれる

- **WHEN** ユーザーがメタのみを変更して差分タブを開く
- **THEN** 差分出力にフロントマター行の変更が含まれる

- **THEN** 差分 API は呼び出されない

- **THEN** 現在の `lesson.content` を用いて diff が取得・表示される

#### Scenario: スペースを含むコース名でも HEAD 正本を取得する

- **WHEN** レッスンのコース名が `DX piyopiyo コース` のようにスペースを含む
- **AND** `contents/.../DX piyopiyo コース/{lesson}.md` が git HEAD に存在する
- **AND** 現在の `content` が HEAD 正本と一致する
- **WHEN** ユーザーが差分タブを開く
- **THEN** UI は「差分なし」を表示する
- **AND** 全行が追加行として表示されてはならない

#### Scenario: 部分変更が追加削除コンテキストで色分けされる

- **WHEN** ユーザーが本文の一部のみを編集して差分タブを開く
- **THEN** 変更のない行はコンテキスト行として表示される
- **AND** 削除された行と追加された行がそれぞれ識別可能に色分けされる

#### Scenario: HEAD に md が無いレッスンは全行追加 diff

- **WHEN** `contents/{series}/{course}/{lesson}.md` が HEAD に存在しない
- **AND** ユーザーが差分タブを開く
- **THEN** 現在の `content` 全文が追加行として diff に表示される

#### Scenario: 変更が無い場合

- **AND** ユーザーが差分タブを開く
- **THEN** UI は「差分なし」を表示する

### Requirement: 確認問題の記法

### Requirement: HTML コメント内カーソル時に AI タブプロンプトへ同期する

編集モードにおいて、CodeMirror のカーソル（または選択）が HTML コメント `<!-- … -->` **内** にある間、Pane4 AI タブのプロンプト入力欄は当該コメントの **内部テキスト**（`<!--` と `-->` を除く）で **常に** 更新されなければならない（SHALL）。カーソルがコメント外に移動した後も、プロンプト欄の内容は自動クリアしてはならない（MUST NOT）。AI タブが非表示でも、次回 AI タブ表示時にコメント内にカーソルがあれば同期されなければならない（SHALL）。

### Requirement: 編集モードで Ctrl とホイールによりフォントサイズを変更できる

ペイン2 の3ビュー（編集・プレビュー・差分）は、スクロール位置を **(レッスン, 編集言語, ビュー)** の組ごとにメモリ上で記憶しなければならない（SHALL）。同じ組へ戻ったとき、本文の描画が完了した後に記憶した位置へ復元しなければならない（SHALL）——本文を非同期に取得するビューでは、取得完了前のプレースホルダ表示で位置を失ってはならない（SHALL NOT）。記憶は Studio のページ読み込みをまたいで永続化しない（SHALL NOT）。日本語と英語は同じ仕組みで扱い、言語によって挙動を分けてはならない（SHALL NOT）。
