# 翻訳契約（translation-contract）

DX トレーニング教材の翻訳規則。**日本語が正本、英語は派生**——翻訳は常に日本語 → 英語の一方通行で行う。この文書は Studio の翻訳機能と翻訳スキル（dx-training-translate）が共通で読む唯一の規則書である（規則の複製を他所に持たない）。

## 英訳するもの

- 本文のすべての文章（見出し・段落・箇条書き・表のセル）
- 画像プロンプトコメント（`<!-- ... -->` に書かれた画像生成の骨子）——英訳されたプロンプトから英語テキストの画像を生成し、英語版だけ差し替える運用があるため
- GitHub アラート（`> [!TIP]` / `> [!NOTE]` / `> [!WARNING]` 等）の中身
- コードブロック内の**コメント文**（`#` や `//` に続く説明）
- 画像の代替テキスト（`![代替テキスト](path)` の角括弧内）

## 変えないもの

- URL・リンク先
- 画像などのファイルパス・ファイル名（`images/<file>` の参照を書き換えない）
- コード本体（コマンド名・変数名・出力例の実行結果部分）
- Markdown の構造（見出しレベル・箇条書きの階層・表の列数・アラート種別）
- `> [!TIP]` などのアラート記法そのもの（キーワードは英語の仕様どおり維持）
- 執筆者向けの空欄マーカー（`> **社内**:` / `> **社内画像**:` のブロック）——訳すと空欄が埋まったように見え、社内情報を埋める工程が拾えなくなる

## 迷ったときの作法

判断に迷う箇所（訳すと意味が壊れそうな固有名詞・社内用語・仮称など）は**無理に訳さず**、直後に執筆者向けコメントを残す:

```markdown
<!-- 訳注: 「DX Tools Training」は仮称のため原文のまま残した。確定後に差し替え -->
```

訳注はレビューで人が拾う前提の逃げ道であり、乱発しない。明らかに訳せるものは訳す。空欄マーカーは数があっても訳注は**1ファイルに1本**——マーカーごとには付けない。

## 触ってはならないもの

- `.meta.json` の `author` / `author_en`——人名のローマ字表記は本人の流儀。翻訳が書いてはならない（英語版の著者表記が必要なら人が `author_en` を手で入れる）
- `.meta.json` の `id` / `order` / `slug` / `cross_series_*` / `is_start` / `is_goal`——構造情報は翻訳の対象外
- 原文ハッシュ（本文1行目の `<!-- source: sha256:… -->` と `.meta.json` の `en_source_hash`）——翻訳の実行機構が計算して書く。モデルが生成・変更してはならない

## トーン

- 教材らしい平易な英語（学習者に語りかける、簡潔で親しみやすい文体）
- 原文の「です・ます」の丁寧さは、英語では自然なニュートラルさに置き換える（過度にフォーマルにしない）
- 原文の比喩・声かけ（RPG フレーム、セーブポイントのたとえ等）は意味が通る形で活かす
- **身体・物理の慣用句は直訳しない。** 骨・手を動かす・目を通す・腑に落ちる・嫌な顔をする等——直訳は "Three bones to this lesson." のように英語として読めない文になる。字面ではなく働きを英語の言い方に置き換える（`手を動かして確かめます` → *Let's check it for yourself*）。同じ慣用句が文ごとに違う英語になってよい——揃えるのは用語集の語と章の定型句だけで、既訳が揃っていないことを理由に統一しない
- **`〜側` は落とす。** 位置ではなく日本語の言い回し——`GitHub 側` → *in GitHub*、`使う側のファイル` → *the file that uses it*。例外はコンフリクトの両側を指すときだけ（`your side` / `the incoming side` は Git の語彙。同じレッスン内でも `共有保管庫の側で` は *in the shared vault*）
- 見出しは Title Case にせず Sentence case（先頭のみ大文字）

## 名前（`name_en`）の規則

**シリーズ名とコース名は Title Case**（各語の頭を大文字）で、階層語を含める——シリーズは `… Series`、コースは `… Course`（日本語の「〜シリーズ」「〜コース」に対応する）。曼陀羅のノードやカードで固有名として出るため。

**レッスン名は Sentence case**（先頭のみ大文字）で、階層語は付けない——レッスン名はページの見出しとして出るので、見出しの規則に従う。

**シリーズ・コース・レッスン名は半角 36 字以内。** 名前は幅の決まった場所（曼陀羅のノード・サイドバー・カード）に出るため、超えた分は表示されない。

## 既存の英語表記に合わせる

**訳すものの種類を問わず**——レッスン本文・`changelog.en.md`・`.meta.json` の `_en` フィールド——すでに `.meta.json` にある英語表記が正である。強さは3段に分かれる。**一段に均さないこと**：固有名を「参考にする」まで弱めると、表記の食い違いを許す規則になる。

**1. 固有名（`name_en`）は表記をそのまま使う。** シリーズ・コース・レッスンを固有名として参照するときは、その `.meta.json` の `name_en` を一字一句そのまま書く。大文字小文字も階層語（Series / Course）も落とさない——サイドバー・曼陀羅・変更履歴には `name_en` が出るので、訳文が `the Git Basics series` のように崩すと、受講者は同じものを2つの名前で見ることになる。⚠ 訳文を1本ずつ読んでも見つからない壊れ方で、複数を並べたときだけ現れる。

総称（`this series` / `the next course` / `the previous lesson`）はこの規則の対象外——固有名ではないため。

**2. 固有名以外の英語表記は語彙と言い回しを合わせる。** `description_en` / `catch_en` / `target_en` に既に英語があるときは、その語彙と言い回しに寄せる。**丸写しはしない**——説明文と本文では文脈が違う。

**3. 参照先にまだ英語表記が無いときは、自分で訳したうえで訳注を残す。** 翻訳はユニット単位で進み、1ユニットの中でも本文がメタより先に書かれる。参照先のシリーズ・コースが今回の範囲外なら、そのメタは未翻訳のままである——つまり「参照すべき英語表記がまだ無い」は例外ではなく通常の状態。訳注は「迷ったときの作法」の書式を使う（新しい書式を作らない）。

## 既訳があるときの規則（差分翻訳）

既に英訳が存在するユニットを再翻訳するときは、**既訳を読み取り、原文の変更に対応する箇所だけを更新する**:

- 変わっていない段落の訳文は一語も変えない（言い回しの一貫性と差分の小ささのため)
- 原文で追加・変更された箇所だけ訳し直す
- 用語集と既訳の言い回しが食い違う場合は用語集を優先し、その箇所だけ直す

## 用語集

訳語は以下で統一する（運用で育てる。追加は人が行う）。**この契約を実行スキルが書き換えてはならない**——翻訳の実行中に気づいた訳語や規則は、抽象化して報告に候補として載せるだけにする。更新は人が行う:

| 日本語 | 英語 | 備考 |
|---|---|---|
| シリーズ | series | 教材の最上位階層 |
| コース | course | |
| レッスン | lesson | |
| 曼陀羅（曼荼羅） | Mandala | サイト名 DX Training Mandala に合わせ大文字 |
| 受講対象者 | intended audience | メタ表示は "For: ..." |
| 受講形態 | course style | self-study / lecture / hands-on は値のまま |
| 変更履歴 | changelog | |
| セーブポイント | save point | Git 比喩の中核語 |
| 三大エリア（Git） | the three areas | working tree / staging area / repository |
| 学習目標 | Learning goals | 章見出し。全レッスン共通 |
| やってみる | Try it | 章見出し。全レッスン共通 |
| まとめ | Summary | 章見出し。全レッスン共通 |
| 確認問題 | Check your understanding | 章見出し。全レッスン共通 |
| 前提 | Given | 「やってみる」の定型句（`- Given: …`） |
| 考えなくてよいこと | Don't worry about | 「やってみる」の定型句（`- Don't worry about: …`） |
| 解答例 | Sample answer | `<details>` の `<summary>` |

⚠ **章見出しと定型句はレッスンをまたいで同じ語にする。** 章立ては全レッスン共通の構造なので、レッスンごとに `Learning objectives` / `Try it yourself` / `Comprehension check` のように揺れると、同じ教材に見えなくなる。
