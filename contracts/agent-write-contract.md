# Agent 書込契約（dx-training-studio ペイン4）

ペイン4 agent がファイルへ書き込むときの境界と作法、およびペイン4 向けにスキルを書く／直すときに従う契約。**このファイルが正本**であり、スキルや system プロンプトは制約の内容を再掲せず本契約を参照する。

> [!NOTE]
> ⚠ **「ペイン4」は旧4ペイン構成の名残の呼び名**で、画面の番号とは対応しない。現在の Studio は**3ペイン**（左からツリー・エディタ／メタ・Agent／画像）で、ここでいうペイン4 は**一番右の Agent ペイン**を指す。スキル・spec からの参照が広いため名前は変えていない（案内文書の呼び方は spec `project-layout` を参照）。

スキルはペイン4 以外（Cursor・Claude Code 等）でも動かす前提で書く。**ペイン4 の都合でスキルの機能を落とさない。** ペイン4 で使えない機能はホストが検出して代替へ倒す。

## 用語

- **計画置き場** — 計画書の置き場（`contents-work/plans/`）。git 管理下。
- **run ディレクトリ** — スキル 1 実行分の作業ファイル置き場（`contents-work/runs/<yyyymmdd>-<slug>/`）。直下に設計メモと曼陀羅案、`reviews/` にレッスンごとのレビューが入る。git 追跡外。**識別子はディレクトリ名が持ち、中のファイル名は役割だけを表す。** 実行ごとに件数が増えるものだけをサブディレクトリに畳む。
- **正本ツリー** — レッスンの正本（`contents/`）。git 管理下。アプリのエディタ（ペイン3）が編集する対象。
- **スキル同梱ファイル** — `SKILL.md` と同じフォルダ配下（`references/`、`assets/`、`scripts/`）のファイル。スキル相対パスで参照する。

## 書込境界（2 ルート）

agent の書込は次の 2 箇所のみ許可される。それ以外（`data/` `app/` `lib/` `docs/` `images/` 等）への書込はツールがエラーとして拒否する。

1. **作業ツリー**（`contents-work/` 配下） — 計画書は計画置き場へ、中間生成物・付随文書は現在の run ディレクトリへ
2. **正本ツリー**（`contents/` 配下） — レッスン草稿の直接着地のみ。着地後はユーザーがペイン3 で作り込む

読取は広い（リポジトリ内と実行中スキルの同梱ファイル）。書込だけが狭い。

明示プレフィックスのない相対パスは、**フォーカス中のコンテンツフォルダ**（ペイン1〜3 の選択階層に対応する `contents/` 配下のフォルダ）を基準に解決される。作業ツリーへ書くときは `contents-work/...` と明示する。

正本ツリーでは、**アプリが管理するファイルと予約名だけが書込を拒否される**（→「正本ツリーへの書込に関する注記」）。

## 確認フロー

次の操作は実行前にユーザーの承認ダイアログが入る。拒否・タイムアウト（無応答）は実行見送りとなり、agent は作業を継続する。

- ファイルの書込（新規・上書き。同一セッションで承認済み／AI 作成済みのパスは再確認なし）
- 正本ツリーに**新しいシリーズ・コース・レッスンのフォルダが生まれる書込**（新しく作られる階層をまとめて 1 回提示する。すべて既存なら確認は入らない）
- スクリプト実行（`run_script` / `run_skill_script`）
- 生成書込（`generate_and_write`）・独立タスク（`run_isolated_task`）
- web 検索（検索キー未設定時は人手フォールバック: ユーザーが結果を貼るか、スキップして続行）

## スキル作者の作法

### ホストが吸収する制約（書いてよい・落とされても破綻しない形にする）

- **サブエージェント**: ペイン4 では起動できず、同一セッションの順次実行（`run_isolated_task`）へ倒す。並列前提の制御を書かない。
- **web 検索**: 結果が得られない場合に手順が止まらないようにする（ユーザー貼付またはスキップ続行の経路を持つ）。
- **画像・マルチモーダル**: 非対応。飛ばされても成果物が成立する主線を持つ。
- **ファイル削除**: 削除ツールは無い。「一時ファイルを消す」を完了条件にしない。中間ファイルは run ディレクトリに残ってよい。
- **MCP・外部コネクタ**: 利用できない。必須にせず、run ディレクトリ内の資料か人手入力の代替経路を併記する。

### どのホストでも守る作法（必ず守る）

- **プレースホルダー**: 短スロットは `{{XXX}}`、可変長ブロックは `<!-- XXX_START -->`〜`<!-- XXX_END -->`（大文字スネークケース）。挿入位置をモデルの判断に委ねず、決定的に埋められる形にする。残留があるうちは完了にしない。区間マーカー名はファイル内で一意にし、同じ字面をマーカー以外に書かない。
- **大きな成果物**: 巨大な本文を 1 回のツール引数に載せない。テンプレートがあるならコピーしてから差し込み、創作長文は分割生成（sections）にする。大量レコードはスクリプト変換にする。
- **書込先の書き方**: 場所は物理パスでなく役割で書く（「計画置き場」「run ディレクトリ」「正本ツリーの当該レッスン」）。操作は意図の動詞で書き、ツール名を本文に書かない。
- **スクリプトとネットワーク**: その場のスクリプトに通信を書かない（ブロックされる）。npm / シェル実行を前提にしない。読取はスキル同梱基準の相対パスで書く。書込は、素の相対パスならフォーカス中のコンテンツフォルダ基準、run ディレクトリへ置くなら `contents-work/runs/...` と明示する。

### スキルの自動発火はできない

ユーザーが `/` で明示指定したときだけ起動する。スキルから別スキルを呼ぶ連鎖を前提にしない。

### 後処理はユーザーに可否を尋ねる

主成果物ができた後の工程（レビュー・変換等）に入る前に、実施するかスキップするかを 1 つずつ尋ねる。

## 作業ツリーへの書込に関する注記

`contents-work/plans/` は git 管理下、`contents-work/runs/` は **git 追跡外**。run ディレクトリに置いたファイルはコミットされないため、他の環境へ渡す手段は git 以外になる。**ただしファイルとして残すこと自体は必須** — チャットに流しただけの成果物は残らない。

run ディレクトリ内のファイル名は役割で固定する。対象名・範囲・実行回数をファイル名に含めない（それらはディレクトリ名が表す）。同じ対象を同じ日に再実行する場合は、既存ディレクトリのファイルに連番を付けるのではなく別の run ディレクトリを作る。

## 正本ツリーへの書込に関する注記

`contents/` への書込はレッスン草稿の着地に使う。**ファイルは階層を問わず自由に置ける**が、次の名前だけは拒否される。

- **セッションファイル**（アプリが管理） — agent が書き換えると会話が壊れる
- **全体・シリーズ・コース階層のメタ情報ファイル** — agent が書き換えると安定 id や表示順が壊れる。**レッスン階層のメタ情報ファイル（レッスンフォルダ直下の `.meta.json`）だけは検査つきで書ける**——JSON として妥当・スキーマに適合（未知キー不可）・`id` は既存値が保護される（agent の値は無視）。追記では書けないので全体を書く
- **レッスン本文の予約名を、レッスン階層以外に置くもの** — 偽の本文になる

とはいえ、正本ツリーは受講者に届く成果物の置き場である。**中間生成物は run ディレクトリへ置く**のが原則で、レッスンに付随する素材（図など）だけをレッスンフォルダに同居させる。

新しいシリーズ・コース・レッスンを作ること自体は正当な書込であり、実行前にユーザーの承認が入る（→「確認フロー」）。承認画面には新しく作られる階層の名前がそのまま並ぶので、**名前の打ち間違いはそこで気づける**。レッスンより深いフォルダは構造を作らないので承認は入らない。

レッスンの `contents.md` は**本文のみ**で書く——frontmatter を書かない。レッスンのメタ（slug・status・description・tags・所要時間・著者）はレッスンフォルダの `.meta.json` に書く。`.meta.json` を書かなくても、アプリが読み込み時に既定値で作り id を採番する。

レッスンの並び順は書込では変えられない（順序を持つのは親階層のメタ情報ファイルで、書込対象外）。新しいレッスンは末尾に並ぶので、順番はアプリ側の画面でドラッグして直す。
