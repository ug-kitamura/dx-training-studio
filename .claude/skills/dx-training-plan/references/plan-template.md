# 計画書テンプレート

出力する計画書の章立てと記述例。実例は `dx-training-studio/contents-work/plans/` 配下の既存の計画書を参照。

## 目次

- 章立て
- 命名規則
- 各章の書き方
- 記述例

## 章立て

| # | 章 | 必須 | 内容 |
|---|---|:---:|---|
| — | ヘッダ | ✓ | 作成日・対象・決定手段・ステータス |
| 1 | 前提 | ✓ | 目的 / 受講者像 / ゴールの定義 / 分量方針 |
| 2 | 全体構造 | ✓ | シリーズ → コース → レッスンのツリー（アスキーアート） |
| 3 | 曼陀羅構成 | ✓ | 依存グラフ / 辺の一覧 / チェック結果 / 進行ルール |
| 4 | シリーズ仕様 | ✓ | ゴール / 対象 / レッスン数と時間 / 前提 / 設計意図 |
| 5 | コース仕様 | ✓ | slug・style・レッスン数・時間・受講対象の一覧表 |
| 6 | レッスン仕様 | ✓ | slug・時間・学習目標・演習の要旨 |
| 7 | 時間予算 | ✓ | シリーズ別集計と総計、目標内かの判定 |
| 8 | 公開とデータの方針 | | 公開形態・識別子・メタフィールド |
| 9 | 制作体制 | | 誰がどう作るか、人手が要る画像素材の積算、既存コンテンツの扱い |
| 10 | 未決事項 | ✓ | 決めきれなかった論点と、それが何に影響するか |
| 11 | 決定の根拠と却下した案 | ✓ | 採用案・却下案・却下理由 |

**7 と 11 を省略しない。** レッスンを1本足すたびに総時間は崩れるので集計が要る。却下理由が残っていないと、数ヶ月後に同じ議論を最初からやり直すことになる。

8・9 は対象トレーニングに公開や制作の論点があるときだけ書く。

## 命名規則

シリーズ名・コース名・レッスン名は**計画書が決める**。ここで決めた名前がそのまま `contents/` のディレクトリ名と受講者に見える表示名になるため、後から変えるのは高くつく。

| 対象 | 規則 | 強度 |
|---|---|---|
| シリーズ名 | 「シリーズ」で終える | 必須 |
| シリーズ名 | 題材がツール・技術なら、その名前を含める | 必須 |
| コース名 | 「コース」で終える | 必須 |
| コース名 | 題材の名前を含める（文脈で自明なら省いてよい） | 推奨 |
| レッスン名 | 「レッスン」で終えない | 必須 |
| すべて | 一覧で見て中身を想起でき、選ぶ動機になる名前にする | 方針 |
| すべて | ファイル名に使えない文字を入れない（下記） | 必須 |

**ファイル名に使えない文字を入れない。** 名前はそのままフォルダ名になり、使えない文字は `_` に置換される——置換後の文字列がそのまま受講者に見える表示名になるので、`リポジトリを作る / clone` は `リポジトリを作る _ clone` として公開される。避けるのは次のとおり。

| 種類 | 具体 |
|---|---|
| 禁止文字 | `/` `\` `:` `*` `?` `"` `<` `>` `\|` |
| 末尾のドット・前後の空白 | Windows が作成時に落とし、`order` の文字列と実体がずれる |
| 制御文字 | U+0000–U+001F |
| 予約デバイス名 | `CON` `PRN` `AUX` `NUL` `COM1`–`COM9` `LPT1`–`LPT9`（拡張子を付けても同じ） |
| 大文字小文字だけの違い | 同じ階層に `Git` と `git` を置かない。Windows・macOS では衝突し Linux では別物になるため、CI でだけ壊れる |

区切りを表したいときは**全角スラッシュ `／`** か**中黒 `・`** を使う（`リポジトリを作る／clone`）。

**素っ気ない名前を採らない。** `概念` `基本操作` のような一語は、一覧に並んだとき何のコースか分からない。

```
シリーズ  Git完全マスターシリーズ / Web開発実践シリーズ
コース    Git概念マスターコース / Git環境構築コース / チーム開発コース
レッスン  Git世界一周ツアー / 世界の合流（マージ） / 旅立ちの準備（The Finale）
```

レッスン名には接尾辞その他の形式上の縛りを課さない。**一番自由に付けてよいのがレッスン名**で、シリーズ・コースが階層を示す役割を負っているぶん、ここで読み手を惹きつける。

slug は別の関心事（URL 用の ASCII）なので、この規則の対象外。

## 各章の書き方

### 1. 前提

対話のフェーズ1で確認した内容をそのまま落とす。受講者像は表にして、項目ごとに前提レベルを明示する。「初心者」の一語で済ませず、何ができて何ができないかまで書く。

ゴールの定義は「修了時に何ができていれば成功か」を具体物で書く。抽象的な到達目標だけにしない。

### 2. 全体構造

アスキーアートのツリーで示す。各レッスンに **slug と目安時間を併記**する。シリーズには通し番号と slug、コースには slug と `style`（受講形態）を付ける。

凡例を図の下に置く。

### 3. 曼陀羅構成

依存グラフのアスキーアート、辺の一覧表、チェック結果、進行ルールの4点を書く。

辺の一覧は From / To / シリーズペアの3列。チェック結果は `references/mandala-guide.md` のチェック項目に対する判定を表にし、補足があれば図の下に書く。

### 4. シリーズ仕様

シリーズごとに表を1つ。**設計意図**の欄を必ず設ける。「なぜこのシリーズを立てたか」「なぜこの範囲か」が後から読んで分かるようにする。

シリーズ名は「命名規則」に従う。

### 5. コース仕様

全コースを1つの表にまとめる。列は「シリーズ / コース / slug / style / レッスン数 / 時間 / 受講対象」。受講対象は「〜を知らない人」「〜ができる人」のように、前提スキルで書く。

シリーズ名・コース名は「命名規則」に従う。**この表の名前が `contents/` のディレクトリ名になる。**

### 6. レッスン仕様

シリーズごとに表を分ける。列は「ID / レッスン / slug / 時間 / 学習目標 / やってみる」。

レッスン名は「命名規則」に従う。形式の縛りが最も緩いので、ここで読み手を惹きつける。

**本文の詳細や解答の中身は書かない。** ここの責任範囲は大まかな構成まで。中身はレッスン草稿作成スキルの担当。

#### 画像素材の印

レッスン名に印を付け、**人手が要る素材**を区別する。`☆`（集合形式）と同じ扱いで、列は増やさない。

| 印 | 意味 | 例 |
|---|---|---|
| `【撮】` | 社内ツールの画面。スクリーンショットの撮影が要る | 申請システム、社内 GitHub、社内AIチャット |
| `【録】` | 社内ツールの動作。短い画面録画が要る | 一連の操作手順を見せる場面 |
| （印なし） | AI 生成・フリー素材で埋まる | 概念図、作業フロー、一般ツールの画面、抽象概念 |

```markdown
| L11 | GitHubとは・アカウント申請 【撮】 | ... | 10分 | ... | ... |
| L20 | 変数と型 | ... | 15分 | ... | ... |
```

**個々の画像の指示内容は書かない。** 構図・プロンプト・枚数はレッスン草稿作成スキルの担当。計画側が知りたいのは「AI で埋まるか、人手が要るか」だけで、そこだけが工数に効く。

### 7. 時間予算

シリーズ別の集計と総計。自己学習分と集合セッション分を分けて集計する。目標時間・上限時間に対してどうかを明記し、**調整枠が何分残っているか**まで書く。

### 9. 制作体制

草稿生成でどこまで埋まるかを書く。あわせて、**第6章で `【撮】` `【録】` を付けたレッスンの本数を積算する。**

社内ツールの画面素材は AI 生成では埋まらず、人手の作業になる。ここを書かないと「草稿生成を前提にすれば間に合う」という見積りが崩れる。

```markdown
- 【撮】が要るレッスン: 11本
- 【録】が要るレッスン: 1本
- 計12本は AI 草稿生成では埋まらず、素材の用意が人手になる
```

### 10. 未決事項

「項目」と「影響」の2列。影響の欄には、それが決まらないと何が確定しないかを書く。単に「未定」と書かない。仮置きしている箇所は、何を仮置きしたかを明記する。

### 11. 決定の根拠と却下した案

主要な分岐ごとに、採用案・却下案・却下理由を書く。**却下理由が本体**なので、そこを省略しない。

制約が理由で却下した場合は、その制約の内容も書く。読んだ人が「なぜその案が駄目なのか」を再調査せずに済むようにする。

## 記述例

### ヘッダ

```markdown
# <トレーニング名> コンテンツ計画（シリーズ → コース → レッスン）

- 作成日: YYYY-MM-DD
- 対象: <対象範囲>
- 決定手段: 対話セッション（本書末尾に決定の根拠と却下案を記載）
- ステータス: 構成確定 / 一部仮置きあり（→「未決事項」参照）
```

### 全体構造のツリー

```
<トレーニング名>
│
├─ ① <シリーズ名>  [slug]  ......................... N レッスン / NN分
│   └─ <コース名>  [slug]  《self-study》
│       └─ L01 <レッスン名>                          NN分
│
├─ ② <シリーズ名>  [slug]  ......................... N レッスン / NN分
│   ├─ <コース名>  [slug]  《self-study》
│   │   ├─ L02 <レッスン名>                          NN分
│   │   └─ L03 <レッスン名>                          NN分
│   └─ <コース名>  [slug]  《self-study》
│       └─ L04 <レッスン名>                          NN分
│
└─ ③ <シリーズ名> ☆  [slug]  ...................... N レッスン / NN分
    └─ <コース名>  [slug]  《hands-on》 ☆
        └─ L05 <レッスン名>                          NN分

凡例:
- [slug] … 公開URLに使うスラッグ
- 《self-study》《hands-on》 … コース .meta.json の style（受講形態）
- ☆ … 集合形式のコース
```

### 曼陀羅の依存グラフ

```
                    ┌──────────────────┐
                    │ ① <シリーズ名>    │
                    │   <コース名>      │
                    └──┬─────┬─────┬───┘
         ┌─────────────┘     │     └─────────────┐
         ▼                   ▼                   ▼
  ┌────────────┐      ┌────────────┐      ┌────────────┐
  │ ② …        │      │ ③ …        │      │ ④ …        │
  └─────┬──────┘      └─────┬──────┘      └─────┬──────┘
        └───────────┬───────┴────────────────────┘
                    ▼
         ┌────────────────────┐
         │ ⑤ <最終シリーズ> ☆ │
         └────────────────────┘
```

### 辺の一覧

```markdown
| # | From（コース） | To（コース） | シリーズ間ペア |
|---|---|---|---|
| 1 | ① / <コース名> | ② / <コース名> | slug1 → slug2 |
```

### チェック結果

`references/mandala-guide.md` のチェック項目をそのまま行にして、判定と根拠を書く。

```markdown
| 規則 | 判定 |
|---|---|
| <チェック項目> | ✓ <そう言える根拠> |
```

判定だけ書いて根拠を省かない。「✓」だけでは、後から読んだ人が再検証することになる。

### レッスン仕様の表

```markdown
| ID | レッスン | slug | 時間 | 学習目標 | やってみる |
|---|---|---|---|---|---|
| L01 | <レッスン名> | `series/course/lesson` | 15分 | <何ができるようになるか> | <5分以内の課題> |
```

### 時間予算

```markdown
| シリーズ | レッスン数 | 時間 |
|---|---:|---:|
| ① … | 1 | 10分 |
| ② … | 6 | 85分 |
| **自己学習 合計** | **N** | **NNN分（N時間NN分）** |
| ③ …（集合） | 1 | 120分 |
| **総計** | **N** | **NNN分** |

- 目標は N 時間、上限 N 時間。自己学習は **N時間NN分** で上限内
- 残り NN 分が調整枠
```

### 却下した案

```markdown
### <論点名>

- **採用**: <採用案>
- **却下**: <却下案> — <却下理由>
- **却下**: <却下案> — <却下理由>
```

制約が絡む場合は、理由の中に制約の内容も書く。

```markdown
  **理由**: <制約の内容>。この案だと <何が起きるか>。
  加えて <教育上の理由>。
```
