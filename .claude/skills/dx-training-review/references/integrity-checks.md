構成をいじると壊れる箇所を点検する。**深さの選択に関わらず必ず通る。**

## 検査項目と分類コード

コードは指摘の分類に使う。**指摘には必ずコードと名称を併記する**（書式は `SKILL.md` の出力規約）。

| コード | 名称                               | 確かめ方                                           |
| ------ | ---------------------------------- | -------------------------------------------------- |
| A      | シリーズ・コース・レッスン名の整合 | 機械                                               |
| B      | レッスン `.meta.json`              | 機械（記入と形式のみ。値の妥当性は公開前レビュー） |
| W      | コース `.meta.json`                | 機械                                               |
| C      | 画像                               | 機械                                               |
| D      | 社内データ                         | 機械                                               |
| E      | 出典                               | 機械（形式）                                       |
| F      | リンク生存                         | 機械                                               |
| G      | 次・前参照の整合                   | 抽出 → 局所照合                                    |
| H      | 受講順                             | 心の声ウォークスルー                               |
| I      | シリーズのストーリー               | 心の声ウォークスルー                               |
| J      | 読者体験                           | 心の声ウォークスルー                               |
| S      | 英語版の名前（重複・長さ）         | 機械                                               |
| T      | 翻訳の鮮度・未訳・欠落フィールド   | 機械（走査スクリプトの実行）                       |

S・T と、A / C / E / F / G の訳文への適用は**英語版が存在するときだけ**通る（→ 英語版の検査）。

公開前レビューで足すコード（K 以降）は [`quality-checks.md`](quality-checks.md)。

## 機械で確かめる

決定的に判定できるものは検索で拾う。**AI の読みに任せない**——見落としが揺れるし、再実行のたびに結果が変わる。

### A. シリーズ・コース・レッスン名の整合

3つの名前が一致しているかを見る。

| 突き合わせる相手                                                    | ずれたときに起きること                                                                                                                                 |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 親の `.meta.json` の `order` ⇔ 実在するディレクトリ                 | 並びが崩れる。`order` に無い実体は末尾に流れる                                                                                                         |
| シリーズ・コースの `.meta.json` の `slug` / `description` / `catch` | 公開サイトの URL とトップページの文面になる。`slug` 欠落・形式違反・兄弟間の重複は**リリース前は blocking**、`description` / `catch` の欠落は advisory |
| 本文中の固有名 ⇔ 実在するシリーズ・コース・レッスン名               | 受講者が存在しない名前を探しに行く                                                                                                                     |
| 計画書の名前 ⇔ 実体                                                 | 意図とのずれ。**advisory**（改名は正当な運用）                                                                                                         |

**本文中の固有名は、次の抽出で拾う。**

```
[^\s、。「」（）：・*`]*(?:シリーズ|コース|レッスン)
```

拾ったものは4つに仕分ける。

- **固有名参照**（「Git概念コース」「はじめにシリーズの開発環境準備コース」）— 実在を照合する
- **相対参照**（「次のレッスン」「前のコース」）— G の検査へ回す
- **記述的な短縮**（「三大エリアのレッスン」）— **完全一致では拾えない。** 正式名（「Gitの三大エリア」）と対応づくかを読んで判断する。改名で最も壊れやすいのがここ
- **自己言及・総称・数量**（「このレッスン」「他のシリーズ」「1レッスン」）— 検査対象外

改名の後は、**旧名がどこかに残っていないか**を旧名そのもので検索する。上の抽出は現名・旧名を区別しないので、これを別に回す。

### B. レッスン `.meta.json`（機械で見る範囲）

キーの集合の正本は `lib/schema.ts` の `lessonMetaFileSchema`、タグの形式は `lib/lesson-tags.ts`、値の選び方は `dx-training-create/references/lesson-template.md`。ここで見るのは**記入されているか・形式が通るか**だけ。あわせて `contents.md` の先頭に frontmatter（`---` 区切り）が残っていないかを見る——残っていれば本文として公開されてしまうので **blocking**。

- `author` が空でないか
- `status` — 全レッスンが `done` になっているか。**リリース前は blocking、それ以外は advisory**（執筆途中は `in_progress` が正常）
- `tags` — 形式に通るか。通らない値は読み込み時に黙って捨てられるので、原稿に残っていても消えている
- `description` — 空でないか、改行を含んでいないか
- `slug` — 記入されているか、形式（小文字英数とハイフン。正本は `lib/schema.ts` の `SLUG_PATTERN`）に通るか、**同じコース内で重複していないか**。公開サイトの URL になるため、**リリース前は blocking**
- `id` — 記入されているか（`lsn-` 始まり）。無ければ loader が自動採番して書き戻す。**advisory**

値が妥当かどうか（所要時間・説明の内容）は公開前レビューで見る。

### W. コース `.meta.json`

レッスンではなく**コース**のメタを見る。ここで見るのは記入と語彙だけで、値が妥当か（本当に独習の内容か）は見ない。

- `style`（受講形態）— **キーがあるか**、**値が語彙にあるか**。どちらも欠ければ **blocking**
  - 語彙の正本は `studio/lib/schema.ts` の `COURSE_STYLES`。**ここに一覧を書き写さない**——語彙が増えたときに二重管理になる
  - 未設定・語彙外は曼陀羅のノードでラベルが**黙って消える**。原稿を読んでも気づけず、曼陀羅を開いて初めてわかるので blocking にする
  - 計画書に記載があるのに `.meta.json` と食い違う場合も挙げる（正は計画書）

### C. 画像

`contracts/image-slot-contract.md` の制作フローに照らして、**止まっているスロット**を探す。

**必ず節ごとに対応づける。** レッスン単位でコメント数と画像数を数えると欠落が隠れる——ある節でコメントと画像が揃っていれば、別の節で両方落ちていても数の上では健全に見える。見出しで区切り、**コメントと画像参照が同じ節で対になっているか**を見る。

- プロンプトコメントがあるのに、その節に画像参照が無い → 生成・挿入がまだ
- 画像参照があるのに、その節にコメントが無い → 執筆時にコメントが置かれなかった。作り直すときの手がかりが残らない
- 画面を見せる前提の本文なのに、コメントも画像も無い → 図が落ちている
- 参照先のファイルが実体として解決できない → 挿入の失敗

同じ節が並ぶレッスンどうし（各レッスンの「VSCode ではこう見える」など）は横に並べて見る。**1本だけ図が無い**のは、意図した省略ではなく落ちていることが多い。

### D. 社内データ

空欄の記法は `dx-training-create/references/lesson-template.md`。

- 空欄が残っていないか。**リリース前は blocking**
- `context-outbox.json` を持つ run があり、社内コンテキストへ未登録のまま残っていないか
- 空欄の周りに一般論が書かれていないか——埋め忘れても文章として自然に読めてしまう箇所

### E. 出典（形式）

形式の正本は `dx-training-create/references/lesson-template.md` の「出典」。

- 裸の URL が本文に露出していないか
- 斜体1行の書式か。脚注や巻末リストになっていないか
- 出典が付くべき記述に付いているか——Web の事実・社内コンテキスト由来の記述

### F. リンク生存

本文中のリンクへ到達できるかを確かめる。**短いタイムアウトで1回だけ試す。**

- 到達失敗は「要再確認」の **advisory**。ネットワークの一時障害と区別できないため、これを blocking にしない
- リンク切れは、元情報が動いた・消えた合図でもある。内容の鮮度を疑う手がかりとして報告する

## 次・前参照の整合（G）

**壊れ方が3種類ある。** 見分けないと、直し方を人に渡せない。

| 種類     | 例                                           | 壊すもの | 直し方                       |
| -------- | -------------------------------------------- | -------- | ---------------------------- |
| 名前参照 | 「Git概念コースで学び」                      | 改名     | 名前の置換で済む             |
| 相対参照 | 「前のレッスンで」                           | 順序変更 | 前後関係を確かめて言い換える |
| 内容結合 | 「前のレッスンで作った練習リポジトリを使う」 | 順序変更 | **本文の書き直しが要る**     |

内容結合は事故ではなく、`dx-training-create` が意図してレッスンを結んだ結果（二重説明を避け、演習を引き継ぐ）。**疎結合にせよという指摘を出さない**——教材の質が落ちる。順序を変えたなら本文を直す、というのが正しい指摘。

### 手順

1. A と同じ抽出で相対参照を集める
2. 参照1件ごとに、`.meta.json` から**実際の前後**を引く（前後のレッスン名・`description`、コース境界なら隣接コース、シリーズ境界なら `cross_series_prev` / `cross_series_next`）
3. **その参照文と、引いた前後の情報だけ**を並べて整合を見る

**全コーパスを1つの文脈に載せない。** 参照ごとに必要な範囲だけを見る方が精度が出るし、対象が増えても破綻しない。

位置を主張する表現（「このコースの最後のレッスン」「最初のレッスンで出てきた」）も同じ扱いで照合する。相対参照の一種として見落としやすい。

シリーズ間の辺がまだ張られていない状態で「次のシリーズで」と書かれている場合は **advisory**——人がこれから張る前提の記述でありうる。

## 心の声ウォークスルー（H / I / J）

受講者が受講順に歩いたときの体験を見る。**独立した文脈で実行する**（サブエージェント。使えない環境では同じ入力で順次実行する）。

### 渡すもの

- シリーズ → コース → レッスンのタイトル階層
- 各レッスンの `.meta.json` から `description`・`estimated_minutes` と、コースの `target`
- `.meta.json` が示す受講順（シリーズ間の接続を含む）

### 渡さないもの

**レッスン本文。** 1本ごとの中身は `dx-training-create` が執筆時に精査している。ここで見るのは**並べたときに立ち上がる流れ**だけで、本文を入れるとレッスン単位の粗探しに引きずられ、流れの問題が埋もれる。

### 出させるもの

受講者ペルソナ（`target` から起こす）が受講順に歩き、**心の声を時系列で**出す。まとめた講評にしない——俯瞰すると、順番に読んだときの引っかかりが消える。

出てきた心の声を指摘に変換する。

- 供給より先に要求が来ている（未導入の概念を前提にしている）→ **H: 受講順**
- 話が飛ぶ・つながりが切れる → **I: シリーズのストーリー**
- 分量や難度の落差、期待とのずれ → **J: 読者体験**

計画書の曼陀羅とずれていても、それだけを理由に指摘にしない（→ `SKILL.md` の受講順の正本）。

## 英語版の検査

**英語版（`contents.en.md`・`_en` フィールド・`changelog.en.md`）が存在するときだけ通る。** 存在しなければこの節ごと飛ばす。

### 既存項目を訳文にも通す

A（名前の整合）・C（画像）・E（出典の形式）・F（リンク生存）・G（次・前参照）は、`contents.en.md` と `_en` に対しても同じ規則で見る。**訳文だけで壊れることがある**——画像パスやリンクは翻訳のとき写し間違えやすく、相対参照は訳したときに前後関係を取り違えやすい。

⚠ **`slug` が `name_en` と一致しないことを指摘しない。** `slug` は構造キーで翻訳の対象外であり、英語 URL が日本語由来のままなのは仕様。

### S. 英語版の名前（重複・長さ）

**`name_en` の重複 → blocking。** 同じ階層のなかに同じ `name_en` が2つ以上あれば、サイドバーと曼陀羅で区別が消える。

```
Git の基本   → Git Basics
Gitの基礎    → Git Basics   ← 日本語では違うものが英語で潰れた
```

⚠ **これは訳文を1本ずつ読んでも絶対に見つからない。** 別々に訳した結果として衝突するので、並べて突き合わせる機械検査でしか拾えない。指摘には両方のユニットと日本語名を並べる。

**`name_en` が契約の上限を超えている → blocking。** 曼陀羅のノードは名前を折り返して全体を見せる設計で、ノードの寸法と行数の上限は**契約の上限がちょうど収まるよう実測で決めてある**。超えた分は行数上限で黙って隠れる（表示は壊れず、情報だけが消える）。英語は同じ内容で日本語より長くなるのが普通なので、翻訳が新しく持ち込む壊れ方。

- 上限の字数は **`contracts/translation-contract.md` の「名前の規則」** を読んで使う。⚠ **review 側に別の目安を持たない**——数字が2か所にあると、寸法を見直したときに片方が古くなる
- 対象はシリーズ・コース・レッスンの `name_en` すべて（契約が3階層に同じ上限を課しているため）
- 指摘には対象ユニットと実際の字数を添える

### T. 翻訳の鮮度・未訳・欠落フィールド

判定は **`dx-training-translate` の走査スクリプトを実行して得る**。

```bash
node --experimental-strip-types .claude/skills/dx-training-translate/references/scan-freshness.mts
```

⚠ **判定ロジック・ハッシュの計算規則・階層ごとの `_en` キー対応をここに書き写さない。** 正本は `studio/lib/translation/freshness.ts` で、スクリプトはそれを import している。写すと第3の実装ができて必ずずれる。

出力から指摘に変換する:

| 出力 | 指摘 | 重さ |
|---|---|---|
| `units[].meta` / `.body` が `stale` | 原文が進んでいるのに訳が追随していない | blocking |
| `units[].meta` / `.body` が `untranslated` | 未訳（サイトでは `Coming soon`） | **advisory** |
| `missingEnFields` | 翻訳済みに見えるのにフィールドが空 | **advisory** |

**未訳と欠落を blocking にしない。** 公開サイトは未訳ページを `Coming soon` ＋日本語版リンクとして設計どおり扱い、名前・説明・キャッチ・受講対象者は日本語へフォールバックする。受講者に壊れたものは届かない。実害が出るのは「**英訳が存在するが間違っている**」側で、そちらが blocking の対象。

⚠ `missingEnFields` は鮮度が `fresh` のユニットにも出る。鮮度は「原文に追随しているか」、欠落は「フィールドが埋まっているか」で**別の軸**——どちらか一方だけ見ても取りこぼす。
