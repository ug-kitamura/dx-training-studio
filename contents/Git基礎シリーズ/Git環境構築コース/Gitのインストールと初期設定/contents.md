# Gitのインストールと初期設定

## 学習目標

ここからは、冒険の装備を整える回です。Git概念コースで手に入れた地図の上を、ここから実際に歩きます。このレッスンのゴールは、**Git の導入申請を出し、承認後にインストールと初期設定を済ませて、`git` コマンドが打てる状態にする**ことです。

> [!IMPORTANT]
> **Git の申請は承認までにおよそ1日かかります。** レッスン自体は15分ですが、実時間は日をまたぎます。**いますぐ申請だけ出して、承認を待つ間に他のシリーズを進めてください。** 承認の連絡が来たら、このレッスンに戻ってきます。

```text
申請を出す ────約1日──── 承認 ───── インストール ───── 確認 ───── 名前の設定
   ↑ いまここ（数分）                 └── ここから先は合わせて10分ほど ──┘
```

時間の数字は目安です。**「申請だけ先に出す」と「承認後にまとめてやる」の2つのかたまりに分かれている**、その形だけ見てください。

## Git は申請から始まる

Git は、はじめにシリーズの開発環境準備コースで入れた Chocolatey とは**別の申請**が必要です。Git は Chocolatey 経由では入らず、IT Service Portal から導入します。申請の窓口は Chocolatey のときと同じ IT Service Portal ですが、申請は別に出します。申請の型も Chocolatey のときと同じ「申請 → 承認待ち → 承認後の実作業」なので、2回目のいまは要領が分かっているはずです。忘れていても、下の手順どおりに進めば大丈夫です。

> **社内**: IT Service Portal での Git 導入申請の手順を書く。答えるべき問い —
>
> - IT Service Portal のどのメニューからたどるか（Chocolatey の「SW install」と同じ入口か）
> - 申請フォームで何を入力・選択するか（ソフト名の正式表記・バージョン・申請理由の書き方の例）
> - 承認の目安時間と、承認されたことは何で分かるか（メール通知か、画面上の表示か）
> - 承認後、インストールはどう実行するか（自動配布か、自分で実行ボタンを押すのか）
>   形式: 番号付き手順4〜6ステップ / 300字程度

> **社内画像**: IT Service Portal で Git の申請フォームを開いた状態のスクリーンショット。ソフト名の入力欄と申請ボタンが写る画角で撮る。申請者名・社員番号・所属はマスクする

申請が済んだら、承認が来るまでこのページは閉じてかまいません。

## SourceTree はどうする

導入の途中で SourceTree という別の道具についての選択肢が出たときの方針だけ、先に決めておきます。

> **社内**: インストール時の SourceTree 同梱の選択肢について書く。答えるべき問い —
>
> - 同梱の選択肢は、どの画面で・どの文言で出るか
> - 選択肢が出ない場合はどうなるか（既定で入る／入らない）
>   形式: 1〜2文 / 80字程度

方針: **同梱できるなら選んでおく。ただしこのトレーニングで SourceTree の使い方は扱いません。** Git の操作はコマンドと VSCode に統一して学びます。

## 入ったことを確認する

承認とインストールが済んだら、本当に使える状態かを確認します。コマンドを打つ場所は **VSCode のターミナル**です。

1. VSCode を開く
2. 上部メニューの **「ターミナル」→「新しいターミナル」** を選ぶ
3. 画面の下側に、文字を入力できる黒っぽい領域（ターミナル）が開く

ここに次のコマンドを打って、Enter キーを押してください。

```bash
git --version
```

`git version 2.x.x` のような行が表示されれば、インストールは成功です。数字は環境によって違ってかまいません。

> [!TIP]
> 「`git` は認識されません」というエラーが出たら、**まず VSCode をいったん閉じて開き直してください。** インストール前から開いていた VSCode は、新しく入った Git に気づけないことがあります。

それでも直らないときは、エラーが出ている画面をそのまま撮って、社内AIチャット（使い方は AI基礎シリーズで扱っています）に貼って聞いてみてください。この「画面を撮ってAIに聞く」は、この先ずっと使える詰まったときの定石です。

## プレイヤー名を設定する

最後に、初回だけの設定を2つ行います。Git のセーブデータ（コミット）には、**誰がセーブしたか**が毎回記録されます。ゲームで最初にプレイヤー名を入れるのと同じで、その名前をここで設定します。

ターミナルで次の2行を、1行ずつ実行してください（`--global` は「このPC全体で1回設定すれば以後ずっと有効」という意味です）。

```bash
# "名前"と"メールアドレス"は差し替えてください
git config --global user.name "名前"
git config --global user.email "メールアドレス"
```

> **社内**: `user.name` と `user.email` に何を設定するかの部署ルールを書く。答えるべき問い —
>
> - `user.name` はどの表記にするか（例: ローマ字か、姓名の順か、社員IDか）
> - `user.email` は社用メールアドレスをそのまま使ってよいか
>   形式: 設定例2行＋補足1文 / 100字程度

設定できたかは、次のコマンドで確認します。

```bash
git config --list
```

表示された一覧に、いま設定した `user.name=...` と `user.email=...` の行があれば完了です。一覧には他にも見慣れない行がたくさん並びますが、**読む必要はありません**。自分の2行が見つかればそれで十分です。

## やってみる

このレッスンの「やってみる」は2段階です。

1. **いますぐ**: IT Service Portal から Git の申請を出す
2. **承認後**: VSCode のターミナルで `git --version` と `git config --list` を実行し、バージョンと自分の名前・メールが表示されることを確認する

- 前提: VSCode が導入済み（開発環境準備コースの内容）
- 考えなくてよいこと: 表示されるバージョン番号が最新かどうか

<details>
<summary>解答例</summary>

`git version 2.x.x` と、`user.name` / `user.email` の2行が確認できれば完了。

## まとめ

このレッスンの流れは4つでした。

1. **申請**を出す（承認まで〜1日。待ち時間は他のレッスンへ）
2. 承認後に**インストール**
3. `git --version` で**確認**
4. `git config` で**プレイヤー名を設定**（初回だけ）

次のレッスンから、いよいよ最初のセーブ（コミット）を作ります。装備は整いました。あとは冒険に出るだけです。

## 確認問題

1. `user.name` と `user.email` は何のための設定でしょうか。「セーブデータ」という言葉を使って1文で説明してみてください。
2. このレッスンの4つの流れ（申請・インストール・確認・名前の設定）のうち、日をまたぐ可能性があるのはどこで、その間あなたは何をしていればよいでしょうか。
