# 最初のコミット

## 学習目標

お待たせしました、ここからが本番です。地図（三大エリア）とコマンドを打つ環境が揃いました。このレッスンではいよいよ、**最初のセーブ（コミット）を自分の手で作ります**。ゴールは、ファイルを add して commit できること、そして**セーブしたくないファイルを `.gitignore` で除外できる**ことです。

先に言っておくと、ここで作るコミットは失敗してもまったく問題ありません。練習用のフォルダで、何度でも作り直せます。「間違えたら戻す」方法もこのコースの最後のレッスンで扱うので、いまは思い切って手を動かしてください。

## 練習用フォルダをリポジトリにする

まず練習の場所を作ります。

1. 好きな場所（ドキュメントフォルダなど）に `git-practice` という新しいフォルダを作る
2. VSCode の「ファイル」→「フォルダーを開く」でそのフォルダを開く
3. 「ターミナル」→「新しいターミナル」でターミナルを開く

このフォルダを Git のリポジトリにするのが、シリーズの最初のレッスンで約束した7つの基本操作の1つ目、`init` です。

```bash
git init
```

`Initialized empty Git repository in ...` と表示されれば成功です。これで何が起きたかというと、このフォルダの中に **`.git` という隠しフォルダ＝セーブデータの保管庫**が作られました。三大エリアのレッスンで学んだ「リポジトリ」の実体がこれです。

> [!CAUTION]
> **`.git` フォルダの中を開いたり消したりしないでください。** 消すと、このフォルダの履歴が全部消えます。

## いまの状態を聞く

次に、ファイルを1つ作ります。VSCode の左側のファイル一覧の上にある**「新しいファイル」アイコン**を押し、`memo.txt` と入力して Enter。開いたファイルに「Git の練習」とでも1行書いて、Ctrl+S で保存してください。

ここで、2つ目の操作 `status` を打ちます。

```bash
git status
```

```text
Untracked files:
        memo.txt
```

（実際の画面には `On branch ...` などの行がもう少し並びますが、このレッスンの表示例はどれも要点だけ抜き出しています。）

`Untracked files`（未追跡）の下に、いま作った `memo.txt` が出てきます。「まだ一度もセーブに含めたことがないファイル」という意味ですが、この英単語は覚えなくて大丈夫です。大事なのは、**status に聞けばいつでも今の状態を教えてくれる**こと。この先、迷ったらとにかく `git status` を打つ——これを口癖にしてください。

## 選んで、セーブする

三大エリアの地図の通り、セーブは2段階です。まず**セーブに含める変更を選び**（add）、それから**セーブします**（commit）。

```bash
git add memo.txt
```

何も表示されなければ成功です（Git は成功時に沈黙することが多い道具です）。`LF will be replaced by CRLF` のような warning が出ることがありますが、改行文字の扱いについてのお知らせで、失敗ではありません。気にせず進んでください。ここで `git status` を打ち直すと、`memo.txt` が `Changes to be committed`——ステージに載った状態——に移っているのが確認できます。三大エリアのレッスンで見た status の表示が、いま自分の画面で起きています。

続いてセーブ本番です。

```bash
git commit -m "メモを追加"
```

`-m` の後ろの `"..."` は**セーブデータに付けるひとことメモ**で、コミットメッセージと呼びます。後から履歴を見たときに「何のセーブか」が分かるよう、**やったことを短く**書きます。うまい書き方はまだ考えなくてよいです——「メモを追加」程度で十分です。

最後にもう一度 `git status` を打つと、こう返ってきます。

```text
nothing to commit, working tree clean
```

「セーブすべきものは何もない」——つまり**全部の変更がセーブ済み**という意味です。三大エリアのレッスンで「表示されない＝リポジトリのセーブと同じ状態」と予告しましたが、その実物がこの表示です。おめでとうございます、最初のコミットが完成しました。

_出典: [Pro Git 日本語版「変更内容のリポジトリへの記録」](https://git-scm.com/book/ja/v2/Git-%E3%81%AE%E5%9F%BA%E6%9C%AC-%E5%A4%89%E6%9B%B4%E5%86%85%E5%AE%B9%E3%81%AE%E3%83%AA%E3%83%9D%E3%82%B8%E3%83%88%E3%83%AA%E3%81%B8%E3%81%AE%E8%A8%98%E9%8C%B2)（2026年8月取得）_

## セーブしないものを決める

最後に、実務で必ず出てくる話です。ツールを作ると、**スクリプトが出力するファイル**（集計結果・ログなど）がフォルダに生まれます。これらは「作れば何度でも出てくるもの」なので、セーブデータに含めません。ソースコードはセーブする、生成物はセーブしない——これが基本ルールです。

そのための仕組みが **`.gitignore`**（セーブ対象外リスト）です。フォルダ直下に `.gitignore` という名前のファイルを作り、除外したいファイル名を1行ずつ書くだけ。書かれたファイルは status に現れなくなり、add もされなくなります。

なお、`.gitignore` ファイル自体は**コミットします**。「何を除外するか」はチーム全員で共有したいルールだからです。

## やってみる

生成物を除外する流れを、実際に手を動かして確かめます。

1. `git-practice` フォルダに `output.json` というファイルを作る（スクリプトの出力ファイルのつもり。中身は空でよい）
2. `git status` で `output.json` が表示されることを確認する
3. `.gitignore` というファイルを作り、`output.json` と1行書いて保存する
4. もう一度 `git status` を打ち、`output.json` が**表示されなくなった**ことを確認する

- 前提: 本文で作った練習リポジトリの続きで行う
- 考えなくてよいこと: `output.json` の中身、`.gitignore` の高度な書き方（ファイル名を1行書くだけでよい）

## まとめ

このレッスンで増えた操作は `init`・`status`・`add`・`commit` の4つ。持ち帰りは次の4点です。

1. `git init` — フォルダをリポジトリにする（最初に1回だけ）
2. `git status` — 迷ったらこれ。今の状態を聞く
3. `git add` → `git commit -m "メモ"` — 選んで、セーブする
4. `.gitignore` — セーブ対象外リスト。**生成物はセーブしない**

次のレッスンでは、たまっていくセーブデータを**読む**側——履歴と差分——を扱います。初めてのセーブ、おめでとうございます。ここがいちばん大きな一歩でした。

## 確認問題

1. 次の操作のうち、セーブデータ（コミット）が増えるのはどれでしょうか——「ファイルを編集して保存する」「git add する」「git commit する」。理由も1文で。
2. スクリプトの出力ファイルをコミットしないのはなぜでしょうか。「生成物」という言葉を使って自分の言葉で説明してみてください。
