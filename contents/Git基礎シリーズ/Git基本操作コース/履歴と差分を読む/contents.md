# 履歴と差分を読む

## 学習目標

基本操作コースも折り返しに入りました。前のレッスンでセーブデータを**作る**側を通しました。このレッスンは**読む**側です。ゴールは、`status`・`log`・`diff` の3つを使い分けて、**「いま何がどうなっているか」を人に聞かずに自分で確かめられる**ようになること。

作業を中断して翌日に戻ってきたとき、「昨日どこまでやったんだっけ」と手が止まる——この場面で使うのが今日の3つです。詰まったときに状況を自分で確認できることが、この先ずっと効く基礎体力になります。

## 状態を聞く3つのコマンド

まず役割の地図から。3つのコマンドは、それぞれ**時間の向き**が違います。

| コマンド | 時間の向き | 分かること                       |
| -------- | ---------- | -------------------------------- |
| `status` | **いま**   | セーブしていない変更が「あるか」 |
| `log`    | **過去**   | どんなセーブが積まれてきたか     |
| `diff`   | **違い**   | 何が「どう」変わったのか         |

`status` は前のレッスンで口癖にしたもの。今日は残りの2つ、`log` と `diff` を足します（7つの操作のうち、これで6つ目まで到達です）。

## セーブデータ一覧を見る

練習リポジトリ（`git-practice`）を VSCode で開き、ターミナルで打ってみてください。

```bash
git log
```

```text
commit 3f2a1c9... (HEAD -> main)
Author: 自分の名前 <メールアドレス>
Date:   Tue Aug 11 10:00:00 2026

    メモを追加
```

前のレッスンで作ったセーブデータが、新しい順に表示されます（`.gitignore` もコミットした人は2件、していない人は1件です。どちらでも正常）。このたまったセーブデータの一覧を、Git の言葉で**履歴**と呼びます——このレッスンのタイトルの「履歴」です。1件のセーブに、**誰が・いつ・何をしたか**が記録されているのが分かります。Author の行に自分の名前が入っているはずです——Git環境構築コースで設定したプレイヤー名は、ここに使われていたわけです。

読み飛ばしてよいものを2つ言っておきます。`commit` の右の長い英数字はセーブデータの通し番号のようなもので、**読める必要はありません**（実物は例よりずっと長く、日時の書式も環境で少し違います。このレッスンの表示例も要点だけ抜き出しています）。`(HEAD -> main)` の `main` は「ブランチ」という仕組みの名前で、**GitHub基礎シリーズで扱います**。いまは無視してください。

> [!TIP]
> ログが長くなると画面が切り替わって、入力が効かなくなったように見えることがあります。**`q` キーを押せば戻れます。** 初めての人がいちばん焦るポイントなので、先に覚えておいてください。

毎回この表示は長すぎるので、実務では1行表示をよく使います。

```bash
git log --oneline
```

セーブ1件が「番号＋メッセージ」の1行になります。コミットメッセージを「やったことを短く」書いた理由が、ここで効いてきます——一覧をざっと眺めるだけで作業の流れが追えるのです。

## いまの状態とセーブを見比べる

`log` が過去の一覧なら、`diff` は**いまのプレイ状態と直前のセーブの違い**を見せてくれます。たとえば `memo.txt` に1行書き足した状態で `git diff` を打つと、こう表示されます。

```diff
diff --git a/memo.txt b/memo.txt
index ddc1c4c..d834c01 100644
--- a/memo.txt
+++ b/memo.txt
@@ -1 +1,2 @@
 Git の練習
+diff の練習
```

ごちゃっとして見えますが、読み方は1つだけ覚えれば十分です。**行の先頭の `+` が「増えた行」、`-` が「消えた行」、記号なしが「変わっていない行」。** 上の4行（`diff --git` から `+++` まで）は「どのファイルの話か」という前置き、`@@` で始まる行はファイル内の位置情報で、どちらも読み飛ばしてかまいません（`index` の数字は人によって違います）。

つまりこの例は「`Git の練習` という行はそのまま、`diff の練習` という行が増えた」と読めます。行を書き換えた場合は、古い行が `-`、新しい行が `+` として**2行セット**で表示されます。

なお、`git diff` がそのまま見せるのは「まだ add していない変更」です。厳密にはもう少し細かい種類があるのですが、**最初は「セーブに入っていない変更を見るコマンド」で十分**です。add 済みの変更を見たい場面が来たら `git diff --staged` と打ちます（いまは覚えなくてよいです）。

## VSCode ではこう見える

VSCode では、ソース管理ビューで変更されたファイル名を**クリックするだけ**で、変更前と変更後が左右に並んだ比較画面が開きます。`+`/`-` の記号の代わりに、増えた行は緑、消えた行は赤の背景で示されます。読み方の考え方はコマンドと同じです——**何が増え、何が消えたか**。

## やってみる

自分のリポジトリで、変更 → 差分確認 → セーブ → 履歴確認、を一周します。

1. `memo.txt` に好きな1行を書き足して保存する
2. `git diff` で、その行が `+` 付きで表示されることを確認する
3. `git add memo.txt` → `git commit -m "1行追加"` でセーブする
4. `git log --oneline` で、いまのセーブが一覧の先頭に増えたことを確認する

- 前提: 前のレッスンの練習リポジトリを使う
- 考えなくてよいこと: 足す1行の内容。メッセージの上手な書き方

## まとめ

今日の持ち帰りは**3つのコマンドの時間の向き**です。

1. `status` — **いま**。セーブしていない変更があるか
2. `log` — **過去**。セーブデータの一覧（長くなったら `q` で抜ける）
3. `diff` — **違い**。`+` が増えた行、`-` が消えた行

次のレッスンはこのコースの仕上げ、「間違えたときに**戻す**」を扱います。7つの操作の最後の1つです。ここまで来れば、ゴールは目前です。

## 確認問題

1. 「昨日の自分がどこまで作業したか思い出したい」。まず打つのは status・log・diff のどれでしょうか。選んだ理由も1文で（答えは1つとは限りません）。
2. `log` と `diff` の役割の違いを、「セーブ」という言葉を使ってそれぞれ1文で説明してみてください。
