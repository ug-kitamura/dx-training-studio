# バージョン管理ってなに？

## 学習目標

ここから **Git基礎シリーズ**の旅が始まります。このシリーズで学ぶのは、バージョン管理という考え方と、7つの基本操作。最後のレッスンを終えたとき、「自分の作業をいつでもセーブして、安全に元へ戻せる」という武器があなたのものになっています。

「報告書\_最終版.docx」「報告書\_最終版2.docx」「報告書\_最終版\_修正.docx」——どれを開けばいいのか分からず、更新日時をにらんだ経験はないでしょうか。このレッスンでは、なぜこうなってしまうのかを入口にして、**バージョン管理が必要な理由を3つ挙げられる**ようになります。

Git のコマンドはまだ1つも出てきません。道具の操作より先に、「何のための道具か」だけを持ち帰ってください。

上の図の左側が、ファイルコピーで版を残すやり方です。細かい文字は読まなくてかまいません。**同じ資料がどんどん増えていく**、その形だけ見てください。

なぜ増えるのでしょうか。ファイルの上書き保存は、**前の状態を消してしまう**からです。「修正する前にも戻れるようにしたい」と思ったら、上書きの前にコピーを取って別の名前を付けるしかありません。これはゲームで言えば、**セーブ枠が1つしかないので、怖くて上書きセーブできない**状態です。仕方なくコピーという手作業でセーブ枠を増やしているわけです。

このやり方は、すぐに3つの壁に当たります。

- **どれが最新か分からない。** 「最終版2」と「最終版\_修正」はどちらが新しいのか、名前からは判別できない
- **何を変えたか分からない。** 「最終版2」で何を直したのかは、開いて見比べない限り分からない
- **戻るのが怖い。** 古い版を消してよいのか誰にも判断できず、フォルダにはファイルが増え続ける

チームで共有フォルダを使っていれば、これが人数分同時に起こります。

## バージョン管理は何をしてくれるのか

バージョン管理とは、この「コピーで版を残す手作業」を道具に任せる仕組みです。ゲームのたとえを続けると、**セーブ枠が無限にあり、過去のセーブが全部残る**ようになります。ファイルは1つのまま、その裏に「いつ・誰が・何を変えたか」の記録が積み重なっていきます。「どれが最新か」の迷いはここで消えます——最新は常に、いま開いているその1つです。

ファイルが1つのままで、どうやって過去の状態を全部持てるのか。その仕組みは次のレッスン「Gitの三大エリア」で扱います。いまは「そういう道具がある」で大丈夫です。

これで何が変わるのかが、このレッスンで持ち帰ってほしい**3つの理由**です。

1. **いつでも戻れる。** どの時点の状態にもロードし直せるので、コピーを取っておく必要がない
2. **変更の記録が残る。** いつ・誰が・何を変えたかが一覧で見られるので、「最終版2で何を直したっけ」がなくなる
3. **安心して変えられる。** 壊してもロードすれば戻れると分かっているから、思い切った修正に挑戦できる

3つ目がいちばん効きます。バージョン管理は「記録を取る事務作業」ではなく、**失敗しても戻れるという安心を作る道具**です。この安心が、これから学ぶプログラミングでは特に大事になります。コードは「動いていたのに、直したら動かなくなった」が日常的に起きるからです。

## なぜ Git なのか

バージョン管理の道具は Git だけではありません。ただ、いま新しく学ぶなら Git 一択です。社内ではバージョン管理の主役が Git に変わりつつあるからです。このトレーニングで学ぶのも Git だけで、他の道具の名前を覚える必要はありません。

もう1つ、**GitHub** という似た名前を見かけたことがあるかもしれません。GitHub は「Git をチームで使うためのサービス」で、次の GitHub基礎シリーズで扱います。いまは **Git と GitHub は別物**、とだけ覚えておけば十分です。

## このシリーズで覚えること・覚えないこと

「Git はコマンドが多くて大変そう」と感じているかもしれません。実際、Git のコマンドは全部数えると膨大にあります。でも安心してください。**このシリーズで覚える操作は7つだけ**です。

```text
init   status   add   commit   log   diff   restore
```

1レッスンに新しく出てくるのは多くても4個です。それぞれが何をするかは次のレッスン以降で1つずつ扱うので、いまこの7つを覚える必要はありません。「7つで足りる」ことだけ持ち帰ってください。

また、Git を調べると **push・pull・ブランチ** という言葉が頻繁に出てきますが、これらは**このシリーズでは扱いません**（GitHub基礎シリーズの担当です）。検索や AI の回答にこれらの言葉が出てきても、いまは読み飛ばして問題ありません。

## やってみる

手元の作業フォルダ（個人フォルダでも共有フォルダでも可）から、「最終版」「\_v2」「\_0811」のように**版をファイル名で管理しているファイル**を探し、同じ資料が何通りあるか数えてください。

- 前提: 業務で使っているフォルダならどれでもよい。個人の作業フォルダが手元になければ、部署の共有フォルダを1つ開いてみる
- 考えなくてよいこと: どれが本当に最新かの判定。中身は開かなくてよい

## まとめ

持ち帰るのはこの3つだけです。

1. バージョン管理があると**いつでも戻れる**
2. **いつ・誰が・何を変えたか**の記録が残る
3. だから**安心して変えられる**

## 確認問題

1. ファイルコピーで版を残すやり方の困りごとを、自分の経験から1つ挙げてください。
2. 「バージョン管理があると、思い切った修正に挑戦できるようになる」のはなぜでしょうか。ゲームのセーブにたとえて、1文で説明してみてください。
