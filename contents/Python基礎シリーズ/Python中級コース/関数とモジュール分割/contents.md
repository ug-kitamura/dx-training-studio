# 関数とモジュール分割

## 学習目標

ここからは中級コース。文法基礎コースでそろえた部品を、**道具として組み上げていく**段です。

このレッスンでは、処理のまとまりに名前を付ける**関数**と、手順書をファイルごとに分ける**モジュール分割**を扱います。終わる頃には、長い一本のスクリプトを「読める・直せる・使い回せる」形に切り分けられるようになっています。

このレッスンも、`python-practice` にファイルを作って動かしながら読み進めてください。

## なぜ切るのか

まず、そもそもの疑問に答えます。**「動いているのに、わざわざ分ける意味はあるのか？」**

たとえば備品リストを読み込んで、在庫の少ないものを絞り込んで、結果を表示するスクリプトを想像してください。全部をベタ書きしても動きます。しかし2週間後に「絞り込みの条件を変えたい」となったとき、**どの行が絞り込みなのか**を数十行の中から探すことになります。

図の右側のように、処理を**名前の付いたかたまり**に分けておくと、直したい場所へ名前で飛べます。このかたまりが**関数**です。分けておく利点は3つあります。

| 利点 | どういうことか |
| --- | --- |
| 読める | 処理の流れが「読み込み → 絞り込み → 出力」と名前で追える |
| 直せる | 変更が1つのかたまりに閉じる。他を壊す心配が減る |
| 使い回せる | 同じ処理を2箇所で使うとき、コピペせず名前で呼べる |

## 関数を書く

関数は `def`（define：定義する、の略）で作ります。新しいファイル（`kansu.py` など）に書いて動かしてみてください。

```python
def greet(name):
    return f"{name}さん、お疲れさまです"

message = greet("佐藤")
print(message)
print(greet("鈴木"))
```

```text
佐藤さん、お疲れさまです
鈴木さん、お疲れさまです
```

形を分解します。

| 部品 | この例では | 役割 |
| --- | --- | --- |
| 関数名 | `greet` | 呼び出すときの名前 |
| **引数**（ひきすう） | `name` | 関数に渡す材料。呼ぶたびに変えられる |
| **戻り値** | `return` の右側 | 関数が返す結果 |

`def` の行末に `:`、中身はインデント——`if` や `for` と同じルールです。定義しただけでは動かず、`greet("佐藤")` と**呼び出したときに初めて実行される**ことに注意してください。

もう1つ、初学者がよく混ざるのが `return` と `print` の違いです。`print` は**画面に表示するだけ**、`return` は**結果を呼び出し元に手渡す**。上の例で `message` に値を入れられたのは、`greet` が return で結果を手渡しているからです。手渡された結果は、変数に入れずそのまま別の関数に渡しても構いません——最後の行の `print(greet("鈴木"))` がその形で、greet の結果を直接 print に渡しています。表示して終わりでよいときは print、結果を後の処理で使うときは return——この使い分けは中級コースの残りでずっと効いてきます。

## ファイルを分ける——モジュール

関数が増えてきたら、今度は**ファイルごと**分けます。分けたファイルを**モジュール**と呼びます。手順書が厚くなってきたら分冊にする、というだけの話です。

試しに、判定の関数を `helpers.py` という別ファイルに置いてみます。

```python
# helpers.py
def is_low_stock(item):
    return item["stock"] < 5
```

`<` の比較の結果は `True` / `False`——「変数と型」のレッスンで名前だけ覚えた **bool** です。この関数はそれをそのまま返しているので、後で `if` の条件にそのまま置けます。

使う側のファイルでは、`import` で分冊を取り寄せます。

```python
# report.py
from helpers import is_low_stock

items = [
    {"name": "モニター", "stock": 4},
    {"name": "キーボード", "stock": 12},
]
for item in items:
    if is_low_stock(item):
        print(item["name"])
```

実行するのは**取り寄せる側**です。`uv run report.py` と打つと——

```text
モニター
```

`helpers.py` のほうを実行しても何も表示されません。定義しただけでは動かない、と学んだとおりです（壊れたわけではありません）。

`from helpers import is_low_stock` は「`helpers.py` という分冊から、`is_low_stock` という手順を取り寄せる」という意味です。**同じフォルダにあるファイルなら、`.py` を除いた名前で取り寄せられます。** `ModuleNotFoundError` が出たら、ファイル名の綴りと、2つのファイルが同じフォルダ（`python-practice`）にあるかを確認してください。

いま分冊にする実感が湧かなくても大丈夫です。1人で書く短いスクリプトなら1ファイルで足ります。ただ、ざっくり言えば**世の中のライブラリはこの仕組みで配られています**——外部ライブラリのレッスンで `import pandas` と書くとき、あなたは「誰かが書いた分冊を取り寄せて」います。ここでは自作の分冊で仕組みを見ておく、というレッスンです。

## やってみる

前のレッスンの `stock.py`（辞書を f-string で表示するスクリプト）の表示部分を、関数に切り出してください。

- やること: `format_item(item)` のような関数を定義して表示の文を return させ、`print(format_item(item))` の形で呼び出す
- 前提: `python-practice` の中で行う。`stock.py` が無ければ、本文の `items` の中の辞書を1つコピーして `item = {...}` の形で使う
- 考えなくてよいこと: 関数名の付け方。動詞っぽい英単語なら何でも構いません

## まとめ

このレッスンの骨は3つです。

1. 関数は**名前を付けた手順のかたまり**。`def` で定義し、呼び出して初めて動く
2. **引数で材料を渡し、`return` で結果を受け取る**。print は表示するだけ
3. ファイルを分けたものが**モジュール**。`from ファイル名 import 関数名` で取り寄せる

処理を切り分ける道具が手に入りました。次のレッスンでは、いよいよファイルを読み書きします——「読む → 加工する → 書き出す」の形が、ここから現実のデータにつながります。
