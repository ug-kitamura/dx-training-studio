# はじめてのスクリプトを動かす

## 学習目標

調達係（uv）を雇ったので、いよいよ最初のスクリプトを動かします。このレッスンでは、練習用のプロジェクトを作り、スクリプトを1本書いて実行するまでを通します。前のレッスンで予告した「uv が Python 本体を手配する瞬間」も、ここで実際に見られます。

終わる頃には、「書く → 実行する → 結果を見る」の一周を自分の手で回せるようになっています。この一周が、このあとの全レッスンの基本動作になります。

## プロジェクトを作る

まず、練習用の**プロジェクト**を作ります。プロジェクトとは、スクリプトと、それが使う道具ひとそろいをまとめておく作業場のフォルダです。

ターミナルで、プロジェクトを置きたい場所へ移動し、次を実行します。以降は Documents（ドキュメント）に作る例で進めますが、**別の場所でも構いません**——その場合、画面に出るパスが本文の例と違っても正常です。

```powershell
cd Documents
uv init python-practice
```

`cd` が失敗したときは、いまいる場所がプロンプトのパス表示（`C:\Users\...>` の部分）で分かるので、そこから移動し直してください。

```text
Initialized project `python-practice` at `C:\Users\（あなたのユーザー名）\Documents\python-practice`
```

`python-practice` というフォルダが生まれ、中にいくつかファイルが入っています。

```text
python-practice/
├─ main.py           サンプルのスクリプト（あとで消してもよい）
├─ pyproject.toml    このプロジェクトの設定メモ（uv が読み書きする）
├─ README.md         プロジェクトの説明を書く場所
└─ .python-version   使う Python のバージョンのメモ（uv が読む）
```

**いまはファイルの名前だけ知っていれば十分です。** 中身を編集するのは `main.py` のようなスクリプトだけで、他のファイルは uv が面倒を見ます。なお、名前が `.` で始まる隠しファイル（`.gitignore` など）も一緒に作られますが、これらは Git基礎シリーズの担当分野なので、ここでは触れません。見えていなくても、あっても、どちらでも大丈夫です。

## スクリプトを書く

作業場ができたので、手順書（スクリプト）を1枚書きます。サンプルの `main.py` をそのまま使ってもよいのですが、**ゼロから自分の手でファイルを作る体験**のために、新しく1枚作ります（`main.py` は触らず残しておいて構いません）。

エディタ（VSCode が入っていればそれが便利です）で `python-practice` フォルダを開き、`hello.py` という名前のファイルを作って、次の1行だけ書いて保存してください。

```python
print("Hello, Python!")
```

`print()` は「カッコの中身を画面に表示する」命令です。文字を `"..."`（引用符）で囲む理由は文法基礎コースで扱うので、いまは決まり文句だと思ってください。この1行が、あなたの最初の作業手順書です。

## 動かす

ターミナルで `python-practice` フォルダに移動して、実行します（VSCode でこのフォルダを開いてターミナルを出した場合は、すでに中にいるので `cd` は不要です）。

```powershell
cd python-practice
uv run hello.py
```

初めての実行では、結果の前に数行のメッセージが流れます。

```text
Using CPython 3.12.13
Creating virtual environment at: .venv
Hello, Python!
```

この最初の2行が、前のレッスンの答え合わせです。**uv が Python 本体（CPython）を用意し、このプロジェクト専用の道具置き場（`.venv` というフォルダ）を作った**——調達係が仕事をした痕跡です。環境によっては Python 本体のダウンロード行が出ることもありますし、バージョンの数字が違うこともありますが、どれも正常です。

最後の行に `Hello, Python!` が出ていれば成功です。もう一度 `uv run hello.py` を実行してみてください——今度は手配が済んでいるので、結果の1行だけが即座に返ります。

> [!NOTE]
> `uv.lock` というファイルも新しく生まれています。これは道具置き場の中身の**管理簿**で、uv が書き換えます。**開いて編集することはありません**。名前だけ見覚えを作っておいてください。

## エラーを恐れない

ここで、わざと1回壊してみます。`hello.py` の行末の `)` を消して保存し、もう一度実行してください。

```text
  File "C:\...\python-practice\hello.py", line 1
    print("Hello, Python!"
         ^
SyntaxError: '(' was never closed
```

英語の文字の塊に見えますが、読む場所は2つだけです。**どのファイルの何行目か**（1行目）と、**最後の行のエラー名と説明**（`(` が閉じられていない）。英語ですが、この2箇所を拾えれば原因のそばまでは案内してもらえます。

それでも意味が取れないときは、**エラーメッセージをそのまま社内AIチャット（AI基礎シリーズで扱っているチャットツール）に貼って「このエラーの意味を教えて」と聞く**のが早道です。エラーは失敗ではなく、Python からの返事です。このシリーズでは何度も出るので、いまのうちに「出ても壊れない」ことを体験しておきましょう。

確認したら `)` を戻して保存し、もう一度 `uv run hello.py` を実行してください。`Hello, Python!` が戻ってくるはずです——**壊しても、直せば戻る**。これを自分の目で見たことが、このレッスンいちばんの収穫です。

## やってみる

`hello.py` に2行目を足して、2つのメッセージが順に表示されるようにしてください。

- やること: `print()` の行をもう1つ書き足し、`uv run hello.py` で実行する
- 前提: 本文で作った `python-practice` プロジェクトの中で行う
- 考えなくてよいこと: メッセージの中身。好きな文でかまいません

<summary>解答例</summary>

`print("2行目です")` を足して実行し、2行表示されれば成功です。

</details>

## まとめ

持ち帰るのはこの3つです。

1. `uv init 名前` でプロジェクト（作業場）を作る。設定ファイルの面倒は uv が見る
2. **`uv run ファイル名` で実行する**。初回に Python 本体と道具置き場（`.venv`）が自動で用意される
3. エラーが出たら**ファイル名・行番号と最後の行**を読む。分からなければ社内AIチャットに貼る

「書く → 実行する → 結果を見る」の一周が回りました。環境構築コースはこれでクリアです。次の文法基礎コースからは、手順書に書ける命令を増やしていきます。

## 確認問題

1. `uv run` の初回実行で `.venv` というフォルダが作られました。これは何のための場所か、自分の言葉で説明してみてください。
2. エラーメッセージが出たとき、最初に読むべき2箇所はどこでしたか。
