# ハンズオンの準備

## 学習目標

ここまでのシリーズで、あなたはセーブ（コミット）と共有保管庫、別ルートと合流の申し込み、そして Python の道具ひとそろいを手に入れてきました。ツール開発実践シリーズは、その集めた武器を**全部使う**クエストです。集合ハンズオン2日間で課題を解く Python スクリプトを1つ完成させ、終わったとき、あなたの手元には「自分で作り、自分の言葉で説明し、レビューを経てマージまで通した」動くツールが残ります。

このレッスンは、その当日を**全部実装に使える状態**にしておくための事前準備です。到達点は2つ。

- 環境が動くことを確かめてある
- 課題に取り組むための**自分のリポジトリ**が用意できている

なお、**課題の中身はここでは明かされません**。1日目の開始と同時に公開されます。ここで済ませるのは器の準備だけです。

## 当日の流れを頭に入れる

ハンズオンは1時間 × 2回、間に3〜4日をはさみます。「60分で完成まで行けるのか」と不安になるかもしれませんが、**課題はこれまでのレッスンで学んだ道具だけで解けるように作られています**。新しい文法を当日覚える場面はありません。

```text
  1日目（60分）              3〜4日               2日目（60分）
┌────────────────────┐   ┌──────────────┐   ┌────────────────────┐
│ 課題の公開          │   │ 応用課題の    │   │ 実装の仕上げ        │
│ → 実装             │   │ 自主考察      │   │ → PR・相互レビュー  │
│ → PR・相互レビュー  │──▶│ （仲間・AI に │──▶│ → 全員が2分ずつ発表 │
│ → 動くツール完成    │   │   相談OK）    │   │ → 修了             │
└────────────────────┘   └──────────────┘   └────────────────────┘
```

いま知っておいてほしいのは4つだけです。

| 決まりごと | 中身 |
|---|---|
| ペアは当日決まる | 2人一組。相方は**相互レビューの相手**で、実装は各自が自分のリポジトリで行う |
| PR とレビューを使う | GitHubブランチ・PRコースでやった「別ルート → 合流の申し込み → レビュー → 合流」を、相方と本番で回す |
| AI は使ってよい | 社内AIチャット（隣の席の相談相手）にいくら聞いても構わない。**ただし発表で自分のコードを自分の言葉で説明できること** |
| 未完成でも発表する | できたところまでと、何に詰まったかを話す。詰まりの共有そのものが仲間の学びになる |

日程と場所は Teams チャンネル **DX Tools Training** で案内されます。

## 環境を最終確認する

当日「動かない」から始めると、実装の時間がそのまま溶けます。次の4つを**いま**確かめてください。1つでも通らなければ、右の列のレッスンに戻れば直せます。

| 確認すること | 通っている状態 | 詰まったら戻る先 |
|---|---|---|
| VSCode が開く | フォルダを開いてファイルを編集できる | はじめにシリーズの開発環境準備コース |
| Git が入っている | ターミナルで `git --version` がバージョンを返す | Git環境構築コース |
| 社内GitHub に入れる | サインインすると右上に自分のアイコン（ユーザー名）が出る | GitHub入門コース |
| uv が入っている | ターミナルで `uv --version` がバージョンを返す | Python環境構築コース |

```bash
git --version
uv --version
```

## 自分のリポジトリを用意する

当日の課題は、運営が用意した**テンプレートリポジトリ**から始めます。テンプレートリポジトリは「ひな形になるリポジトリ」で、複製すると同じ中身で自分の新しいリポジトリが作れます。中身は README とサンプル CSV だけ——**課題文は入っていません**。

> **社内**: テンプレートリポジトリの名前と場所を書く。答えるべき問い —
>
> - 社内GitHub 上のリポジトリ名と URL（またはたどり着き方）
> - 受講者に閲覧権限が最初からあるか、申請が要るか
>   形式: リポジトリ名＋リンク1本＋補足1文 / 50〜100字

複製の手順は次のとおりです。GitHubリモート連携コースで作った New repository とは入口が違い、**テンプレート側の画面から**始めます。

1. テンプレートリポジトリのページを開く
2. **Use this template** ボタンを押し、**Create a new repository** を選ぶ
3. Owner に**自分のアカウント**を選び、リポジトリ名を入れる（例: `dx-handson`。自分が分かる名前でよい）
4. **Private** を選んで **Create repository** を押す（課題の作業は自分用なので Private でよい）

_出典: [GitHub Docs「Creating a repository from a template」](https://docs.github.com/en/enterprise-server@latest/repositories/creating-and-managing-repositories/creating-a-repository-from-a-template)（2026年8月取得）_

> **社内画像**: 社内GitHub のテンプレートリポジトリのトップ（Use this template ボタンが見える状態）と、Create a new repository の入力フォーム。画面が変わるごとに1枚を目安に撮影する。組織名・ユーザー名・実在のリポジトリ名はマスクする

```text
テンプレートリポジトリ ──[Use this template]──▶ 自分のリポジトリ ──[git clone]──▶ 手元
     （運営のひな形）                       （社内GitHub 上・Private）        （作業する場所）
```

言い分けるなら、**複製は社内GitHub 上に自分の保管庫を新しく作る操作、clone はその保管庫の中身を手元に写す操作**です。

できあがった自分のリポジトリを、GitHubリモート連携コースと同じ手順で手元に clone します。**Code** ボタンから HTTPS の URL をコピーし、置き場所のフォルダ（リモート連携コースで clone したときと同じ親フォルダでかまいません）を VSCode で開いてターミナルから実行してください。

```bash
git clone <コピーした URL>
```

## 動作確認する

clone したフォルダを VSCode で開いてください。**README とサンプル CSV が見えていれば clone は成功**です。続けて、ターミナルで Python が動くことだけ確かめます。

```bash
uv run python -c "print('ready')"
```

```text
ready
```

`-c` は「この1行だけを実行する」というオプションです。ここではそのまま貼ればよく、覚えなくてかまいません。`ready` が表示されれば、調達係（uv）が Python を手配できています。初回は Python 本体の準備で少し待つことがありますが、正常です。
