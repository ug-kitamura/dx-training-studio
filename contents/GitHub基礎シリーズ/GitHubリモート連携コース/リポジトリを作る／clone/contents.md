# リポジトリを作る／clone

## 学習目標

鍵は手に入りました。ここからは手を動かします。このレッスンのゴールは、**社内GitHub の上に自分の共有保管庫を1つ作り、それを手元に複製する**ことです。

Git基礎シリーズでは、手元のフォルダに `git init` で保管庫を作りました。今回は逆で、**先に共有保管庫を作ってから、手元に持ってきます**。実務ではこちらの順が多くなります——チームのリポジトリはたいてい先にあり、自分はそこへ参加する側だからです。

このレッスンで増える操作は1つ、`clone` だけです。

## 社内GitHubにリポジトリを作る

社内GitHub をブラウザで開き、サインインした状態から始めます。

1. 画面の右上、**「＋」ボタン**をクリックして **「New repository」** を選ぶ
2. **Owner** が自分のユーザー名になっていることを確認する（組織が選べる場合があるが、練習では自分を選ぶ）
3. **Repository name** に `github-practice` と入力する
4. 公開範囲は **Private**（自分と、自分が招いた人だけが見られる）を選ぶ
5. **「Add a README file」** にチェックを入れる
6. **「Create repository」** をクリックする

作成されると、リポジトリのトップページが開きます。`README.md` が1つだけ入った、ほぼ空の保管庫です。

> **社内画像**: 社内GitHub でリポジトリを作る流れ。①New repository の入力画面（Owner・名前・Private・Add a README にチェックが入った状態） ②作成直後のリポジトリトップページ（README.md が1つ表示された状態） ③緑の「Code」ボタンを押してポップオーバーが開き、**HTTPS の URL とコピーアイコンが見えている状態**。画面が変わるごとに1枚を目安に撮る。組織名・ユーザー名・URL のホスト部分はマスクする

手順5の「Add a README file」にチェックを入れたのには理由があります。**中身が空のリポジトリを clone すると警告が出て、初めてだと不安になる**ためです。ファイルが1つでも入っていれば、この後の手順がすっきり通ります。

> [!NOTE]
> 公開範囲には Private のほかに Public（誰でも見られる）などの選択肢が並びますが、**このトレーニングでは Private だけ使います。** 社内GitHub でどの範囲が許されるかは、GitHub入門コースの最初のレッスンで確認した制約に従ってください。

_出典: [GitHub Docs「Hello World」](https://docs.github.com/ja/get-started/start-your-journey/hello-world)（2026年8月取得）_

## clone する

**clone は、共有保管庫をまるごと手元に複製する操作**です。ファイルだけでなく、**これまでのセーブの履歴ごと**コピーされます。ここが「ZIP でダウンロード」との決定的な違いです。

まず、複製元の住所（URL）を調べます。

1. リポジトリのトップページで、緑色の **「Code」** ボタンをクリックする
2. 開いたポップオーバーで、**HTTPS** のタブが選ばれていることを確認する
3. 表示されている URL の右にある**コピーアイコン**を押す

次に、**clone したフォルダを置きたい場所**を VSCode で開きます。ここが大事です——`git clone` は**いま開いている場所の中に**フォルダを作るので、`git-practice`（Git基礎シリーズの練習フォルダ）を開いたまま打つと、**保管庫の中に保管庫ができてしまいます**。

1. VSCode の「ファイル」→ **「フォルダーを開く」** で、**ドキュメントフォルダ**（`git-practice` の親にあたる、ふだんの置き場）を開く
2. 「ターミナル」→ **「新しいターミナル」** でターミナルを開く

> [!IMPORTANT]
> **フォルダーを開き直したら、ターミナルも開き直してください。** 前に開いたままのターミナルは、古いフォルダを指し続けます。

```bash
git clone <コピーした URL>
```

`<コピーした URL>` の部分は、貼り付けで置き換えます（山かっこごと消します）。

```text
Cloning into 'github-practice'...
remote: Enumerating objects: 3, done.
Receiving objects: 100% (3/3), done.
```

（表示は要点だけ抜き出しています。）いま開いている場所に **`github-practice` というフォルダが作られ**、その中に README.md と `.git`（手元の保管庫）が入りました。

初回だけ、**認証を求める画面が出ることがあります**。ブラウザが開いたら、いつもどおり会社のアカウントでサインインしてください。特別な設定は要りません。一度通れば、次からは聞かれなくなります。

うまくいったか確かめます。VSCode で「ファイル」→「フォルダーを開く」から `github-practice` を開き、**新しいターミナル**で次を打ってください。

```bash
git log --oneline
```

```text
a1b2c3d Initial commit
```

コミットが1件表示されるはずです。**自分では一度もコミットしていないのに、履歴がある**——これが「履歴ごと複製された」ということです。README.md を作ったときのコミットが、そのまま手元にコピーされています。

## 仲間を招く（見るだけ）

Private のリポジトリは、作った本人しか見られません。仲間に見てもらうには、**collaborator（共同作業者）として招きます**。ハンズオンで相方をレビュアーとして招くときに、この操作をします。

1. リポジトリのページで **「Settings」** タブを開く
2. 左のメニューから **「Collaborators」** を選ぶ
3. **「Add people」** をクリックし、相手の**ユーザー名**を入力して追加する
4. 相手に招待の通知が届き、相手が承諾すると参加が完了する

手順3の「ユーザー名」は、GitHub入門コースでプロフィールから控えたものです。相手にもそれを聞くことになります。

> [!NOTE]
> **ここは読むだけで、いまは操作しません。** 自己学習の段階では招く相手がいないためです。ハンズオン当日、ペアが決まってから実際にやります。「Settings → Collaborators から、相手のユーザー名で招く」——場所だけ覚えておいてください。

## やってみる

練習用リポジトリを作り、手元に clone します。

1. 社内GitHub で `github-practice` という Private リポジトリを作る（README にチェック）
2. Code ボタンから HTTPS の URL をコピーする
3. **置き場所のフォルダ**を VSCode で開き、新しいターミナルで `git clone <URL>` を実行する
4. できた `github-practice` フォルダを VSCode で開き、`git log --oneline` でコミットが1件あることを確認する

- 前提: 社内GitHub のアカウントが承認済みであること。まだなら、承認を待つ間に他のシリーズを進める
- 考えなくてよいこと: リポジトリの説明文（Description）、ライセンス、`.gitignore` テンプレートの選択。すべて空のままでよい

<details>
<summary>解答例</summary>

`git log --oneline` に `Initial commit`（または README 追加のメッセージ）が1件出れば成功。

</details>

## まとめ

このレッスンで増えた操作は `clone` の1つだけ。持ち帰りは3つです。

1. **共有保管庫は GitHub の画面で作る**（New repository → 名前 → Private → README にチェック）
2. **`git clone <URL>` で手元に複製する。** ファイルだけでなく**履歴ごと**——ここが ZIP ダウンロードとの違い
3. 仲間を招くのは **Settings → Collaborators**。使うのはハンズオン当日

手元と共有保管庫が、これでつながりました。次のレッスンでは、この線の上を実際にデータが行き来します——push と pull です。

## 確認問題

1. `clone` と「ZIP でダウンロード」の違いを、**履歴**という言葉を使って1文で説明してみてください。
2. Git基礎シリーズでは `git init` でリポジトリを作りました。今回の `git clone` と、何がどう違うでしょうか。「どちらが先にあるか」に注目して言い換えてみてください。
