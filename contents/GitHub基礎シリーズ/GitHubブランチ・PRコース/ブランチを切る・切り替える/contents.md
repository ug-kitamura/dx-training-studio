# ブランチを切る・切り替える

## 学習目標

ここまでで、手元と共有保管庫の間を行き来できるようになりました。ただ、いまのやり方には1つ弱点があります。**コミットした瞬間から、それが「本編」の履歴に積まれる**ことです。試しに書いてみたコードも、書きかけの文章も、セーブすれば同じ1本の道の上に並びます。

このレッスンのゴールは、**本編から分かれた別ルートを作り、そこで作業できるようになる**こと、そして**なぜ分けるのかを自分の言葉で言えるようになる**ことです。この別ルートを **ブランチ** と呼びます。

Git基礎シリーズで「名前だけ出てくる」と言い、ずっと先送りにしてきた言葉が、ここで実体になります。

## なぜ別ルートを作るのか

先に、あなたが思っているであろうことを言葉にします。**「一人で作業しているのに、分ける意味があるのか」**——もっともな疑問です。実際、ここまでのレッスンはブランチ無しで成立していました。

理由は3つあります。

| 理由 | 中身 |
|---|---|
| **本編を、いつでも動く状態に保てる** | `main`（本編）には完成したものだけを入れる。作りかけを別ルートに置けば、途中で誰かが本編を見ても壊れていない |
| **失敗を捨てやすい** | 別ルートで試して、うまくいかなければルートごと捨てる。本編には最初から何も起きていない |
| **合流の前に見てもらえる** | 別ルートを本編に合流させる手前で、仲間に中身を確認してもらえる。この仕組みが次のレッスンの Pull Request |

3つ目が、実務ではいちばん効きます。そして**ハンズオンでは、ペアの相方にコードを見てもらう手順そのものがこれ**です。いま一人で練習しておくと、当日ペアと組んだときに迷いません。

図にすると、こういう形です。

```text
                                    ここで合流させる
                                          │
  main（本編）         ──●───●───────────●──▶
                             \          /
  add-greeting（別ルート）     ●───●────┘
                             ↑
                        ここで分かれる
```

`main` が本編、下の枝が別ルートです。**別ルートで何をしても、本編の `●` は増えも減りもしません。** これが「壊さずに試せる」の中身です。

_出典: [Pro Git 日本語版「ブランチとは」](https://git-scm.com/book/ja/v2/Git-%E3%81%AE%E3%83%96%E3%83%A9%E3%83%B3%E3%83%81%E6%A9%9F%E8%83%BD-%E3%83%96%E3%83%A9%E3%83%B3%E3%83%81%E3%81%A8%E3%81%AF)（2026年8月取得）_

> [!NOTE]
> ブランチの中身は、厳密には「コミットを指す目印」です。ただ、**最初の理解としては「別ルート」で十分**で、この先の操作もそれで通ります。目印の話は、必要になったときに調べれば足ります。

## 切る・移る・戻る

`github-practice` フォルダを VSCode で開いた状態で始めます。**ここからは実際に打ちながら読んでください。** 使う操作は3つです。

**いまどこにいるかを見る**

```bash
git branch
```

```text
* main
```

`*` が付いているのが、**いま自分がいるルート**です。まだ `main` しかありません。

**別ルートを作って、そこへ移る**

```bash
git switch -c add-greeting
```

```text
Switched to a new branch 'add-greeting'
```

`-c` は create（作る）の頭文字で、**作ると同時にそのルートへ移る**という意味です。`add-greeting` はルートの名前で、自分で決めます。**何をするルートかが分かる名前**にしてください（`test` や `aaa` だと、3日後の自分が困ります）。

**本編に戻る**

```bash
git switch main
```

戻るときは `-c` を付けません。`-c` は「新しく作る」ときだけです。

自分がどこにいるかは `git status` の1行目にも出ます。

```text
On branch add-greeting
```

Git基礎シリーズで「迷ったら `git status`」と言いました。ブランチが増えてからは、**この1行目を見る**のがいちばん確実です。

## 別ルートで編集すると本編はどうなるか

「本編は無傷」と言われても、実感がわかないはずです。**手を動かして確かめます。** 3分で終わります。

1. `git switch -c add-greeting` で別ルートへ移る（すでに作ってあれば `git switch add-greeting`）
2. `README.md` の末尾に `- 別ルートで書いた行` を足して保存する
3. `git add README.md` → `git commit -m "別ルートで1行足した"`
4. `git switch main` で本編に戻る
5. **VSCode で `README.md` を開く**

手順5で、**さっき足した行が消えています。** 驚かなくて大丈夫です、消えたのではなく、**その行は別ルートの上にしか無い**というだけです。

6. `git switch add-greeting` で別ルートに戻る
7. もう一度 `README.md` を開く——**行が戻っています**

これが「別ルートで何をしても本編は無傷」の実物です。ブランチを切り替えると、**フォルダの中身そのものが、そのルートの状態に入れ替わります**。

> [!WARNING]
> 切り替える前に、**編集中のファイルは commit しておいてください。** コミットしていない編集を抱えたまま切り替えようとすると、Git が止めてくることがあります。止められたら「まず commit」と覚えておけば足ります。

## やってみる

別ルートに**コミットが1つ乗った状態**を作ります。次のレッスンはこの状態から始めます。

1. `git branch` で、いまあるブランチを確認する
2. **一覧に `add-greeting` が無ければ** `git switch -c add-greeting`、**すでにあれば** `git switch add-greeting` で移る
3. `git status` の1行目が `On branch add-greeting` になっていることを確認する
4. `README.md` に1行足して保存し、`git add README.md` → `git commit -m "別ルートで1行足した"`（本文の手順で済ませてあれば飛ばしてよい）
5. `git switch main` で本編に戻り、VSCode 左下が `main` に変わり、足した行が消えることを確認する
6. `git switch add-greeting` で別ルートに戻る

- 前提: `github-practice` フォルダで行う。編集中のファイルがあれば先に commit しておく
- 考えなくてよいこと: ブランチ名の付け方の流儀（`feature/` を付けるなどの決まりは、実務のチームごとに違う）

## まとめ

このレッスンで増えた操作は `branch` と `switch` の2つ。持ち帰りは3つです。

1. **ブランチは、本編から分かれた別ルート。** 本編（`main`）を壊さずに試せる
2. **`git switch -c 名前`** で作って移る、**`git switch main`** で戻る。`git branch` で一覧
3. **切り替えるとフォルダの中身が入れ替わる。** 迷ったら `git status` の1行目か、VSCode の左下

まだ別ルートは手元にしかありません。次のレッスンで、これを共有保管庫へ送り、**本編への合流を申し込みます**——Pull Request です。

## 確認問題

1. ブランチを切り替えると、フォルダの中のファイルはどうなるでしょうか。「別ルート」という言葉を使って1文で説明してみてください。
2. 一人で作業しているときにブランチを切る理由を、3つのうち**自分がいちばん納得したもの**を1つ選んで、自分の言葉で説明してみてください。
