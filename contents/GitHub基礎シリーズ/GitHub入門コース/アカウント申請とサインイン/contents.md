# アカウント申請とサインイン

## 学習目標

前のレッスンで、社内GitHub は申請制だと分かりました。このレッスンのゴールは、**社内GitHub のアカウント申請を出し、承認後にサインインして、最初の設定を済ませる**ことです。ここを通ると、共有保管庫の鍵が手に入ります。

> [!IMPORTANT]
> **アカウントの承認にはおよそ3日かかります。** レッスン自体は10分ですが、実時間は日をまたぎます。このトレーニングの申請の中でいちばん長く待つので、**いますぐ申請だけ出して、承認を待つ間に他のシリーズを進めてください。** 承認の連絡が来たら、このレッスンの「サインインして自分のページを見る」に戻ってきます。

```text
申請を出す ────約3日──── 承認 ───── サインイン ───── プロフィールの確認
   ↑ いまここ（数分）              └──── ここから先は合わせて5分ほど ────┘
```

Git のインストールと同じ形です。「申請だけ先に出す」と「承認後にまとめてやる」の2つのかたまりに分かれている、その形だけ見てください。

## 申請を出す

窓口は、Chocolatey と Git のときと同じ **IT Service Portal** です。申請はこれで3回目なので要領は分かっているはずですが、今回は**費用（月 16€）のかかる申請**である点だけが違います。忘れていても、下の手順どおりに進めば大丈夫です。

> **社内**: IT Service Portal での社内GitHub アカウント申請の手順を書く。答えるべき問い —
>
> - IT Service Portal のどのメニューからたどるか（Chocolatey・Git の「SW install」と同じ入口か、別のカテゴリか）
> - 申請フォームで何を入力・選択するか（サービス名の正式表記・申請理由の書き方の例・費用の承認者を誰にするか）
> - 承認の目安時間と、承認されたことは何で分かるか（メール通知か、画面上の表示か）
> - 承認後、アカウントはどう渡されるか（初回サインインの案内が届くのか、会社アカウントでそのまま入れるのか）
>   形式: 番号付き手順4〜6ステップ / 300字程度

> **社内画像**: IT Service Portal で社内GitHub の申請フォームを開いた状態のスクリーンショット。画面が変わるごとに1枚を目安に、メニューの入口からフォーム送信までを撮る。申請者名・社員番号・所属・承認者名はマスクする

申請が済んだら、承認が来るまでこのページは閉じてかまいません。

## サインインして自分のページを見る

承認の連絡が来たら、社内GitHub を開きます（開き方は前のレッスンの「社内GitHubと GitHub.com」にあります）。サインインは**会社のアカウントでのシングルサインオン**（SSO）です。普段の社内システムと同じ ID で入るので、GitHub 専用のパスワードを新しく作ることはありません。

サインインすると、ホーム画面が開きます。まだリポジトリが1つも無いので、ほとんど空の画面です。それで正常です。

1. 画面の**右上にある丸いアイコン**（自分のアバター）をクリックする
2. 開いたメニューの一番上に **「Signed in as ○○○」** と出る。この `○○○` が**ユーザー名**
3. 同じメニューから **「Your profile」** を選ぶと、自分のプロフィールページが開く。表示名（本名）のすぐ下に、同じユーザー名が薄い文字で並んでいる

> **社内画像**: サインイン直後のホーム画面と、右上アイコンのメニューを開いてプロフィールページに着いたところ。画面が変わるごとに1枚を目安。ユーザー名・メールアドレス・所属・アバター画像はマスクする

**ユーザー名は控えておいてください。** 仲間に「自分のリポジトリに招くね」と言われたとき、相手に伝えるのはこのユーザー名です（ハンズオンで実際にそうなります）。

## 最初に整えておく2つ

2つだけ確認しておきます。**見る場所が別々**なので、先に書いておきます——表示名はプロフィールページの **「Edit profile」**、メールは右上メニューの **「Settings」→ 左メニューの「Emails」** です。どちらも後から直せるので、完璧にする必要はありません。

| 確認すること | どこで | なぜ |
|---|---|---|
| **表示名（Name）が本名になっているか** | Edit profile | 仲間があなたを探すとき、ユーザー名だけでは誰か分からない |
| **メールアドレスが、Git に設定した `user.email` と同じか** | Settings → Emails | Git のセーブデータ（コミット）は `user.email` で「誰のセーブか」を記録している。GitHub 側のメールと一致していれば、コミットがあなたのアカウントに紐づいて表示される |

2つ目は、Git基礎シリーズの「Gitのインストールと初期設定」で `git config --global user.email` に設定したものです。忘れていたら、VSCode のターミナルで確認できます。

```bash
git config --global user.email
```

ここで表示されたメールアドレスと、GitHub の Settings → Emails にあるアドレスが同じならそれで完了です。違っていても、この段階で困ることはありません——コミットの横にアバターが出ないだけです。気づいたときに揃えてください。

> [!NOTE]
> 「同じメールを入れたのにアバターが出ない」ときは、GitHub 側でそのメールが確認済み（verified）になっているかを見てください。届いた確認メールのリンクを押すだけです。

## やってみる

このレッスンの「やってみる」は、本文の手順そのものです。

1. IT Service Portal から社内GitHub のアカウントを申請する（**早いほどよい。承認に約3日かかる**）
2. 承認後、サインインしてプロフィールページを開き、自分のユーザー名を控える

- 前提: 申請の承認を待つ間は、他のシリーズへ進んでよい
- 前提: 社内GitHub を業務で使う予定が無く、上司に相談中の人は、**その結果が出てから**手順1に進む（前のレッスンの「申請と費用」参照）
- 考えなくてよいこと: アバター画像や自己紹介文。空のままでよい

## まとめ

申請は3回目、でも今回は待ち時間がいちばん長い回でした。持ち帰りは3つです。

1. 社内GitHub の申請は **IT Service Portal** から。承認まで**約3日**、だから**先に出す**
2. サインインは**会社アカウントの SSO**。新しいパスワードは作らない
3. プロフィールで**表示名**と**メール**を確認する。メールは Git の `user.email` と揃えると、コミットが自分のものとして表示される

これで共有保管庫の鍵が手に入りました。次のコースでは、いよいよ自分の保管庫を社内GitHub の上に作り、手元とつなぎます。

## 確認問題

1. Git の `user.email` と GitHub に登録したメールが違っていると、何が起きるでしょうか。「コミット」と「アカウント」という言葉を使って1文で説明してみてください。
2. このレッスンで「申請だけ先に出す」のはなぜでしょうか。Git のインストールのときと比べて、自分の言葉で言い換えてみてください。
