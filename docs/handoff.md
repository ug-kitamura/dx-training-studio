**観測すること**（次のシリーズで効きを見る）:

| 観測対象 | 見かた |

| コース単位への縮小の効き | 1コース ≈ 15分の見積もりが実態と合うか。承認ゲート・レビュー採否に人が付き合えたか |
| run またぎの引き継ぎ | 同一シリーズの2コース目で、用語表とたとえが実際に引き継がれたか |
| 社内コンテキストの3段梯子 | 段1（DB 検索）が届くか。届かないとき段2→段3へ自然に降格するか。`context-outbox.json` が書かれるか |
| 名前確認ゲート | 提示された名前でそのまま進めたか。止めて計画書を直す判断が要ったか |
| 画像コメントの出力保証 | 図を置くと決めた節に必ずコメントが出たか |

**模範解答**（`.claude/skills/dx-training-create/references/model-answer/`）は「Gitの三大エリア」1本。⚠ **コピーであって参照ではない**——レッスン本体を直しても追従しないので、**本体に手を入れたら再コピーする**。0本でも壊れない設計。

担わせるもの／担わせないものの線引き:

| 担わせる（規則で書けないもの） | 担わせない（実例から読み取れないもの） |
|---|---|
| **トンマナ** — 文体・語りかけ方・断定の強さ・専門語を出す間合い | **フェーズとゲート**（AI は手順を平気で飛ばす） |
| **密度** — 1節あたりの分量・図と文の比率・たとえの長さ | **出力規約**（パス・`.meta.json`・命名。1本から一般則は導けない） |
| **空欄の書きぶり** — 「答えるべき問い」の具体度 | **制約**（既存を変更しない等。実例には「やらなかったこと」が写らない） |
| マークダウンの運用（太字の当て方・箇条書きの使い分け） | **禁止事項**（負の制約は実物から読み取れない。→ `design-principles.md`） |

⚠ **スリム化できるのは `lesson-template.md` の一部だけ。** `SKILL.md` のフェーズ・出力規約・制約は削らない——削ると「飛ばし」が悪化する。

| レッスンの赤字は本文とメタの鮮度を合成して出す（`worstFreshness`） | **面ごとに独立**。ヘッダー＝本文 / モーダル＝メタ |

#### 英語ビューの赤字1行（2026-08-23）

赤字は**常に1行だけ**。文言は2つで、優先順位は **空欄 ＞ 古い ＞ 無し**。

| 状態 | 文言 |
|---|---|
| 空欄のブロックが1つ以上 | 翻訳がまだ出来ていません |
| 空欄は無く鮮度が `stale` | 翻訳が古い可能性があります |

- **「不在」と「空白」は同じ。** `.meta.json` にキーが無い／`""`／空白のみ、`changelog.en.md` や `contents.en.md` のファイル不在——全部「訳が入っていない」
- **原文が空のブロックは対象外。** 訳しようがないものを責めない（書きかけの日本語メタを誤検出しない）
- **日本語混入は見ない。** 判定は空白かどうかだけ
- ⚠ **面ごとに独立。** ペイン2 ヘッダー＝レッスン**本文**、レッスンメタモーダル＝レッスン**メタ**、ホーム＝全体メタ＋`changelog`。**合成して1つの値にしないこと**——本文の話をしたい場所にメタの空欄が漏れる（`worstFreshness` はこの理由で削除した）
- ⚠ **`author_en` の非対称は意図的。** 欠落判定には**入れる**（空欄が意図か入れ忘れか区別できないので手入力を促す）が、翻訳ボタンは**触らない**し `en_source_hash` にも**入れない**。人名を機械に訳させると `Andreas → Andrew`（英語の対応語があるので「正しく」変換される）や `タトワ → Tatwa / Tatva / Tattva`（カタカナからの逆転写は一意に決まらない）が入り、日本語話者のレビューでは見抜けない。**つまり赤字が出ても翻訳ボタンでは消えないことがある**
- ⚠ **ハッシュの入力（対象フィールドとその並び）を変えないこと。** 変えると `en_source_hash` を持つ全ユニット（現在17件）が一斉に「翻訳が古い」へ落ち、既存の英訳を全フィールド再生成してレビューし直すことになる。`studio/__tests__/lib/translation-freshness.test.ts` の「メタ原文ハッシュの固定値」がこれを止める——**落ちたら直すのは期待値ではなく実装のほう**
- 対応表の正本は `studio/lib/translation/freshness.ts` の `EN_FIELDS`（`{ enKey, jaKey, translated }`）。`translated: true` だけがハッシュ入力・メタ英訳 API の許可リスト・「英訳が1つでもあるか」に入る。**書き写さずここから引くこと**
- 判定はサーバ（`/api/content/translation-status`）で行う。**空欄を埋めても保存するまで赤字は消えない**——`freshness.ts` が `node:crypto` を持つためクライアントへ出せない

#### 言語はアプリのモード（Studio）

- **切替の入口は GlobalHeader に1つだけ**（曼陀羅ボタンの左・テキスト表記「英語ビューに切り替える」/「日本語ビューに戻る」・**ツールチップ無し**）。⚠ **ペイン2 の面に戻さないこと**——常時見えていることが「選択を変えてもモードが保たれる」の説明になっている
- ⚠ **選択階層が変わってもリセットしない。** 以前は `requestSelectionChange` が `ja` へ戻していたが撤廃した。戻すと「面ごとの設定」に逆戻りする

#### 鮮度・進捗

- **鮮度はハッシュ方式**（spec `translation-freshness` が正本）: 本文は `contents.en.md` 1行目の `<!-- source: sha256:… -->`、メタは `.meta.json` の `en_source_hash`、changelog は日英の先頭エントリ日付比較。⚠ **ハッシュを書くのは翻訳の実行だけ**——手編集の保存は既存ハッシュを維持する（触らない）。**「最新として扱う」は廃止した**ので、手直し後に警告を消したければ「原文から翻訳」を実行し直す
- ⚠ **欠落フィールド（`_en` の未記入）は鮮度とは別の軸。** 鮮度が `fresh` でも出る——`hasEnValues` は「1つでも埋まっていれば真」なので、部分的な記入は鮮度から見えない。判定の正本は `studio/lib/translation/freshness.ts` の `listMissingEnFields` / `EN_META_KEYS`（階層→`_en` キーの対応表もここ。⚠ 走査スクリプトや UI に書き写さない）。原文が空のフィールドは欠落に数えない
- **翻訳が古いことの伝え方は1か所だけ**: **Studio ペイン2 英語ビュー本文上部の赤字1行**（`StaleTranslationNotice`）。日本語ビューには出さない。**公開サイトには一切出さない**——受講者は対処できないから（鮮度維持はトレーナーの責務）。⚠ サイトの鮮度判定ミラーと parity テストは**残してある**（`stale` が未使用でも消さないこと。ハッシュ形式のズレを検知する安全網）
- **未翻訳ページは `Coming soon` ＋日本語版リンク**（`emit.mts` の `untranslatedPlaceholder`）。⚠ **日本語本文へフォールバックしない**——Pagefind が索引するのは生成 HTML なので、ファイルに日本語を書いた時点で英語索引が汚染される（実行時のコンポーネント分岐では直せない）。⚠ **名前・説明・キャッチ・受講対象者は日本語フォールバックを維持**（止めると曼陀羅とサイドバーが同じ文字列だらけになりナビが死ぬ）

#### スキル（translate / review）

- ⚠ **鮮度は処理対象を決めるゲートではなく参考情報**（2026-08-23 に転換。「最新は触らない＝冪等」の要件は撤回済み）。未翻訳と古いものは常に処理し、**範囲内に最新があるときだけ**「含めるか」を1回確認する（既定は含めない）。含めた場合に直すのは**現行の契約に違反している箇所だけ**で、訳し直しはしない。契約（用語集・名前の規則）は運用で育つのに、ハッシュ方式では既訳へ届かない——その穴を人の判断で埋める仕組み
- **走査（`scan-freshness.mts`）は引数によらず常に `contents/` 全体。** 範囲引数は「今回処理する対象」の印（各ユニットの `inScope`）で、⚠ **走査を絞らない**——絞ると「あと何件残っているか」の分母が範囲ごとに変わって進捗が読めない
- **集計は本文とメタを分ける。** ⚠ 合算しない（本文1本と `name_en` 1個では作業量が桁違い）
- **完了報告は実行前後の進捗比較を出す**（フェーズ3 の走査出力を保持し、フェーズ5 の再走査と並べる。走査を追加実行しない）
- ⚠ **受講者目線の通し読みには原文を渡さない。** `contents.en.md` **だけ**を渡す——原文・`translation-contract.md`・用語集を渡した瞬間、「原文がこうだからこの英語で正しい」と読めてしまい不自然さに気づけなくなる。**渡さないことが検査の設計そのもの**
- **`dx-training-review` が英語版も検査する。** 言語は聞かず、英語版があれば自動で対象。⚠ **`name_en` の重複は blocking**（別々に訳した名前が英語で潰れる事故は訳文単体からは見えない）／長さ超過・未訳・欠落は **advisory**。**リリース可否は言語別**に出す
- **キャッチ（`catch`）の通し整合は review の検査 X が見る**（2026-08-26 新設）。判定は1点だけ——**受講順で前のキャッチが獲得・完了を宣言したものを、後のキャッチが未獲得の前提で語っていないか**。⚠ **語彙の台帳・メタファーの定義ファイルは作らない**（機械に先回りさせると run ごとの創造性が死ぬ）。同じ語の使い回し（`セーブ` `手に入れる`）も、シリーズとコースの抽象度の勾配も見ない——**縛るのは獲得の時制だけ**。対象は**レビュー範囲によらず `catch` 全件**（矛盾の相手が範囲外だと永久に検出できない。全21件なら1つの文脈に載る）。重さは **advisory 固定**——キャッチは感情のフックで、blocking にすると安全側の無難な一言へ寄る圧力になる
- ⚠ 鮮度・未訳・欠落の判定は review 側に書き写さず、**`scan-freshness.mts` を実行して得る**
- **翻訳規則の SSoT は `contracts/translation-contract.md`**（英訳する/変えない・訳注 `<!-- 訳注: … -->`・**名前の規則**・用語集）。Studio の翻訳 API とスキルの両方が読む——**規則をどちらかに複製しないこと**
- ⚠ **実行スキル（plan / create / review / translate）は契約も自身の `SKILL.md` も他スキルの文書も書き換えない**（spec の MUST NOT）。勝手に育つ規約は同じ入力でも結果を変えてしまう。translate は気づきを**抽象化した「規約候補」として報告に載せるだけ**（最大3件・0件が正常）で、採否と反映は人が `creating-skills` / `openspec-explore` で行う

#### そのほか

- ⚠ **`author` / `author_en` は翻訳が触らない**（英語ビューで手編集のみ。フォームに「著者名は自動翻訳出来ません」の注記あり）。構造キー（id/order/slug/cross_series/is_start/is_goal）も不可侵。agent 書込ガードは `en_source_hash` を `id` と同じ既存値保護にしてある（鮮度偽装防止）

- ⚠ **英語ビューの保存は専用経路 `PUT /api/content/meta-en`**。既存 save-course は target/cross 系を常時明示送信する規約なので流用すると日本語側を壊す
- **ホームの保存は1つだけ**で、全体メタと changelog をまとめて確定する。⚠ **dirty なものだけ書く**——触っていない changelog へ PUT を投げると、楽観ロックのせいで「名前を直しただけなのに履歴の競合で失敗する」になる
- ⚠ **`/en` の `<html lang>` は postbuild（`mandala/scripts/set-en-lang.mts`）が書き換える**。Pagefind はこれで言語別索引を分離するので、**postbuild の順序（lang 書き換え → Pagefind）を崩さないこと**。検索 UI の索引言語は「最初に検索を開いた時点の lang」で決まる既知の限界あり（README）。**サイドバー最上部の更新日行も `<html lang>` で日英を切り替える**（CSS 変数2本を body に注入し `html[lang="en"]` で選ぶ。JS を足さない）
- **状態は日英共有**（status に `_en` は無い）——未完成レッスンの英語版は自動で「作成中 / in progress」表示。未完成も翻訳対象（スキルは status で絞らない）
- **ヒーロー画像の編集 UI は消したが `hero` フィールドは生きている**——`.meta.json` に手で書けば公開サイトに効く（PUT の「省略＝保全」規約で消えない）

#### 曼陀羅のレイアウト（2026-08-23・両アプリ共通）

- ⚠ **シリーズ枠は dagre の compound graph（クラスタ）で重なりを防いでいる。** 枠は配置後にメンバーの外接箱から描くだけなので、dagre にシリーズを教えないと同じシリーズのコースが他シリーズを挟んで置かれ、枠が食い込む（実測 140×120px）。`layoutFlow` の `clusterOf` がその教え役
- ⚠ **クラスタを使うと dagre が各クラスタの上下に境界の段を挿し、段間が `ranksep` の3倍になる。** 実測 72→288 / 36→180 / 24→144。だから**クラスタが1つ以上あるときだけ** `ranksep` を 1/3 にする。クラスタ0個（全シリーズ折りたたみ・ミニ曼陀羅）では境界の段が入らないので**補正してはならない**（無条件に割ると段が詰まる: 144→96px）
- `FRAME_PADDING.x`（22px）と dagre のクラスタ間隔は**暗黙に結合**している。クラスタ間のクリアランスは実測 44px で、パディングをそれ以上にすると再び重なる。`mandala-layout.test.ts`（両アプリ）が非重なりを固定している
- **既定ズームは `1 / 1.2`。** React Flow の Controls のステップが 1.2 倍なので、ズームイン1回でちょうど等倍へ戻る。`anchoredViewport` の位置の式は**倍率を掛けている**——掛け忘れると基準ノードがずれる。⚠ **例外が1つある**（全シリーズ折りたたみで開いたときだけ収める。→ 下の「収める初期表示」）
- ⚠ **`layout.ts` / `viewport.ts` は Studio と mandala の2コピー**（互いに依存しない規約）。**片方だけ直すと同じ `contents/` から違う地図が出る**
- **シリーズの横順は正本順で固定**（2026-08-24・`mandala-modal-behaviors`）。⚠ **dagre は交差最小化の同点を挿入順で決める**——集約ノードを末尾に回して渡すと、畳んだシリーズが右端へ移る（実機で AI基礎が Git基礎の右へ跳んだ）。対策は2段: `Mandala.tsx` が `entries` をシリーズ初出順に並べ替え（これだけで実データは直る）＋ `layoutFlow` に `seriesOf` / `seriesOrder` を渡すと配置後に `orderSeriesColumns` が**縦範囲の重なるシリーズ同士だけ**ブロック単位で正本順へ詰め直す（安全網。段で上下に積まれた Git→GitHub は横順を持たないので触らない。真下の従属シリーズは一緒に動く。隙間が縮むなら元の配置を返す）
- ⚠ **「段（派生ランク）」方式は 2026-08-24 に試して撤回した。同じ案をそのまま再実装しないこと。** シリーズ跨ぎの辺から派生 DAG を作り、最長路で段を付けて「**同じ段のシリーズだけ中心 x が正本順**」を唯一の制約にする案（`computeSeriesRanks` ＋ 重なり時は右へ押し広げる安全網）。狙いどおり **AI基礎 と Git基礎 の左右はどの折りたたみ状態でも不変**になったが、実機では次の2点でかえって悪くなった:
  - **段が違うペア（はじめに vs AI）は無制約のまま**なので、畳み方によって AI基礎 が はじめに の左にも右にも来る。**「入れ替わって見える」という元の不満は消えなかった**
  - シリーズ枠が左右に散り、**辺が長い斜めになって縦の流れが読めなくなった**（押し広げが効くほど横へ広がる）
  - 設計記録は `openspec/changes/archive/2026-08-24-mandala-series-rank-order/`（⚠ git 追跡外・`REVERTED.md` つき）。**再検討するなら「ランク違いのペアの横位置をどう決めるか」と「辺の直線性をどう保つか」を先に決めること**——この2つを空けたまま横順だけ固定しても、体験は良くならない
- **開閉の記憶**: 詳細は下の「曼陀羅の開閉記憶」。⚠ **ツリーと違い `useState` の初期化関数で読んでよい**——曼陀羅はクライアントでマウントされ SSR に関わらないので、最初の描画から記憶どおりの姿で出る（ツリーの cookie 化の教訓はここには当てはまらない）。モーダルの印は Studio が `showChrome`、サイトが `modal` prop——`currentLocation` の有無で推測しない。⚠ **`modal` にぶら下げるのはクリックの割り当てとダブルクリックだけで、記憶はホームも持つ**

#### 曼陀羅の開閉記憶（2026-08-26・両アプリ共通）

**既定は3面とも「全シリーズ折りたたみ」。** 記憶は `lib/mandala/collapse-memory.ts`（サイト2スロット `site-home` / `site-modal`、Studio 1スロット `studio-modal`）。

- ⚠ **保存層を持たない。** モジュールスコープの `Map` だけ。「リロードで既定に戻ってよい」が仕様なので、**保存層を持たないことがそのまま実装**になっている。`localStorage` へ戻さないこと
- ⚠ **記憶するのは「展開しているシリーズ」。** 畳んでいる側ではない。既定が全折りたたみなので、記録の無いシリーズ（新しく増えたものを含む）が「記録に無い＝折りたたみ」で既定と一致する必要がある。**この極性のおかげで実在しない ID の掃除が要らない**（一致しない記録は自然に無視される）
- ⚠ **ツリーの開閉（cookie）とは極性が逆。揃えようとしないこと。** ツリーは畳んだ側を保存する——あちらは**リロードを跨いで復元する必要があり**、サーバーが HTML を描くので事情が違う（→ 2.3）
- ⚠ **モーダルは閉じると unmount する**（サイト `{open && …}` / Studio `{mandalaOpen ? … : null}`）。ホームの埋め込みもページを離れれば unmount する。**記憶をコンポーネントの state に置くと開き直しで消える**
- **日英共通は追加の仕掛け不要。** サイトの `MandalaModal` は `SiteShell`（レイアウト）にあり `LanguageToggle` は `Link` なので、ja↔en はクライアント遷移でモジュール state が生き残る。Studio の `editLanguage` は prop でリマウントしない
- **現在地による自動展開**: `findCurrentLocation()` が `/git → kind:"series"` / `/git/concepts(/lesson) → kind:"course"` を返し、**`kind === "course"` のときだけ**そのシリーズを展開する。Studio も同型（`currentCourseId` だけを見て `currentSeriesId` は見ない）。⚠ **シリーズトップを現在地に加えないこと**——印は集約ノードが引き取るので開く必要がない
- **クリックの割り当て**: ホームはシリーズ枠・集約ノードが**シングルクリックでトグル**（遷移しない）／**コースノードは遷移を維持**。モーダルは**現在地がそのシリーズトップのときだけ**トグルし、それ以外は遷移（Studio ツリーの2段構えと同型）
- ⚠ **`isModal` でないときは畳んだ集合を空にすること**（Studio）。展開側の空集合をそのまま反転すると「全部畳む」になり、開閉を持たないはずのミニ曼陀羅が空になる

#### 収める初期表示（2026-08-26・3面共通）

**マウント時に全シリーズが畳まれていたときだけ**、初期表示を `fitView`（上限 1・下限なし）にする。それ以外は従来どおり固定倍率＋基準ノード配置。

- **条件は片道の札**（`fitCollapsed`）。⚠ **「いま全部畳まれているか」を配置のたびに見る作りにしてはならない。** ①閲覧者が畳み直すたびに倍率が勝手に変わる ②**札を立てたまま展開すると、大きくなったグラフを収めにいって豆粒になる**（`viewport.ts` 冒頭が捨てた挙動そのもの）。開閉したら落として復帰させない
- ⚠ **判定は「畳んでいる集合が全シリーズを覆うか」で書く。** 記憶の極性は展開している側だが、**開閉を持たない面（ミニ曼陀羅・chrome 無しの全体）は「展開集合が空」でありながら実際は全展開**なので、展開側で判定すると裏返る
- ⚠ **`onInit` の `fitView` は空振りする。** その時点では React Flow の内部ストアにノードが入っておらず外接箱が出ない（実測: `translate(0,0) scale(1)` のまま残る）。**基準ノード配置は自前の `nodes` 配列と dagre の座標だけで足りるので露見しなかった**が、収める配置はストアに依存する。**両アプリとも「計測完了で1度置き直す」経路（`PlaceWhenNodesInitialized`）が必須**——サイト側にはこれが無く、今回新設した
- **`fitViewOptions.maxZoom` は自動配置の頭打ちにしか効かない。** 閲覧者の可動域は `<ReactFlow minZoom maxZoom>` 側で、どちらのアプリも未指定＝既定の 0.5〜2 のまま。**「開いた瞬間に実寸より大きくは描かれないが、手で 2 倍まで寄れる」**という関係
- ⚠ **収める倍率に下限は入れていない**（判断は 2026-08-26）。シリーズ6本では効く場面が無いため。**増えて読めなくなったら、下限を足す前に「畳んだ既定の姿」そのものを疑うこと**。経緯は `lib/mandala/viewport.ts` 冒頭
- **実測**（シリーズ6本を畳んだとき）: 外接箱 726 × 708。`rankdir: TB` なので**常に縦が制約**になり、収める倍率は 0.82〜0.83 前後——固定倍率 0.833 とほぼ同じ。**元の問題は倍率ではなく「`Start` 上端そろえで下へ押し出して `Goal` が切れる」ことだった**

#### 触るときに知っておくこと

- **変換スクリプトが入口**（`mandala/scripts/build-content.mts`）。正本の走査 → slug 検証 → `content/**` と `content/site-data.json` の生成 → 画像コピー、の順。ページ側は `site-data.json` しか見ない
- **生成物は毎回作り直される**（`content/` `public/images/` `out/`）。**ここを直接編集しても次のビルドで消える**——直すのは `scripts/` か `components/` か正本
- **トップページは `content/**/index.mdx` として生成され、MDX からコンポーネントを呼ぶ**。Next.js は同階層に `[series]` と Nextra の `[[...mdxPath]]` を同居できないため、`app/` 直下に独自ルートを作れない（この制約は動かせない）
- ⚠ **テーマの `<Layout>` を動的セグメント配下のレイアウトに置かないこと。** いまは `components/SiteShell.tsx`（`"use client"`）がルートレイアウトから描いている。**`app/[[...mdxPath]]/layout.tsx` に戻すと console エラーが再発する**——`[[...mdxPath]]` は全ページが同じセグメントの別の値なので、クライアント遷移のたびにレイアウトごと作り直され、next-themes の `<script>` が再マウントされて `Encountered a script tag while rendering React component` と、その巻き添えの `Element type is invalid` を撒く
- **言語別サイドバーは params ではなく `usePathname()` で解決する**（SiteShell）。`usePathname()` はプリレンダ時にも実ルートを返すため、静的 HTML の時点で正しい言語のツリーになる
- **サイドバーの「概要」項目は出さない。** シリーズ・コースの index に `asIndexPage: true` を付けてフォルダ自身をページにしている
- ⚠ **`_meta.js` の `theme` は子の階層へ継承される**。シリーズでパンくずを切ったぶんは**コース階層で明示的に戻している**——戻さないとコース・レッスンのパンくずまで消える
- ⚠ **dev / build とも `--webpack` が必須**（`package.json` の scripts）。`next.config.mjs` が rehype プラグイン（GitHub アラート）を関数で渡しており、Turbopack はローダー options をシリアライズ可能な値に限るため「does not have serializable options」で落ちる
- **リリース番号はサイドバーの `::before`** で描く（テーマに差し込み口が無いため）。**タグ由来でないビルドでは変数を置かない**ので `content` が無効になり、擬似要素ごと生成されない＝行も余白も出ない
- **ヒーロー画像は切り抜かない**（`width:100%; height:auto`）。**縦横比がそのまま高さになる**ので、差し替えるときは 3.75:1 前後に揃える
- **検索インデックスはビルドでしか作られない**（Pagefind の postbuild）。`public/_pagefind`（dev 用）と `out/_pagefind`（配信用）の**両方に出すのが要点**
- ⚠ **`--nextra-*` CSS 変数は `17,17,17` 形式のトリプレット。** 色として使うには `rgb(var(--nextra-bg))` と包む。`var(--nextra-bg, #fff)` は無効な指定になる
- ⚠ **全ページが単一のキャッチオール route（`app/[[...mdxPath]]`）から生成される。** クライアント chunk は**全ページの和集合**になるので、重いライブラリは静的 import が1箇所でも残ると全ページに載る。**曼陀羅の描画は必ず `components/mandala/LazyMandala.tsx`（`"use client"` ＋ `dynamic(..., { ssr: false })`）を通す**——モーダル側だけを動的 import しても分割されず、レッスンページに React Flow 約 520KB が載った
- ⚠ **React Flow の色は CSS 変数（`--xy-*`）で与える。** `nodeColor` 等の props はインラインスタイルになり、ダークテーマの stylesheet から**上書きできない**
- ⚠ **被覆率は stroke を含めて数える**。`getBoundingClientRect()` は **stroke を含まない幾何ボックス**を返すので、実測値をそのまま被覆率に使うと過小評価になる
- ⚠ **アイコンは「箱の数字」ではなく「見た目の幅」で揃える。** glyph が箱をどれだけ埋めるかが出所ごとに違う——`GitHubIcon`（nextra）は `viewBox="3 3 18 18"` で被覆 100%、lucide は `0 0 24 24` で `Map` 75% / `Compass` 83% / `MapPin` 67%。**同じ `size` を与えると揃わない**。⚠ **さらに、外接箱を揃えても足りない**——丸い絵と矩形の絵では同じ箱でも矩形のほうが大きく見える（面積比 4/π ≒ 1.27）。**矩形側は1割強ちいさくする**
- ⚠ **`:is()` の詳細度は引数の最大値を取る。** テーマのダーク上書き `:is(html.dark, .dark) .dxm-node` は (0,2,1) なので、**クラス2つ (0,2,0) では越えられない**。セレクタを2本並べる
- ⚠ **React Flow のクリックとパンの機構**:
  - `onNodeClick` を渡すと **全ノードの wrapper が `pointer-events: all`** になる。**一部だけ押せるようにしたいときは wrapper を `pointer-events: none` に落として子で拾う**（bubbling は `pointer-events` の影響を受けない）
  - **`.react-flow__pane`（d3-zoom がパンを見る要素）はノードの祖先**。「ノードを押せるようにするとパンできなくなる」は誤り
  - **移動後のクリックは d3-zoom が抑止する**（`dragEnable(view, g.moved)` → `yesdrag`）。⚠ ただし **`draggable: false` のノードでは React Flow 側の `nodeClickDistance` は効かない**
  - **`zIndex: -1` はヒットテストを塞がない**。重なり順の制御にだけ効く
  - ⚠ **`click` → `click` → `dblclick` の順に届く。** シングルクリックとダブルクリックの両方に開閉を割り当てると、2回目の `click` が開閉した直後にダブルクリック側でも開閉して**行って戻り、何も起きない**。しかも2回目の `click` がどう振る舞うかは「1回目の `router.push` がその間に届いたか」に依存するので、**同じ操作の結果がタイミングで変わる**。手当ては「直前のクリックがトグル済みならダブルクリック側は何もしない」1本（`toggledByClickRef`）
- ⚠ **絶対配置の基準はパディングボックス**（枠線の内側）。⚠ **シリーズ枠の枠線は 1.5px 指定だが実効値は 1px**（レイアウト時に丸められる）ので補正値はノードと同じ 1px
- ⚠ **曼陀羅の CSS は「変種 → 状態」の順に置く。** `.dxm-node-here` のような状態指定を `.dxm-node-compact` / `-collapsed` より前に書くと、同じ詳細度で後勝ちになり**変種側が状態を上書きする**
- **slug が1つでも欠けると変換が中断する**（URL を決められないため）
- **本文が参照する画像の実体が無いとビルドが失敗する**。参照切れの検出を兼ねた仕様。**`cover` は例外**
- **`mandala/__tests__/content-source.parity.test.mts`** が、mandala の読み取りロジックと Studio の `studio/lib/contents-loader.ts` のずれを実 `contents/` で突き合わせる。**走査規則を変えるときは両方を直す**
- ⚠ **mandala は `mandala/` の外の `node_modules`・設定に依存してはいけない。** CI は `mandala/` でしか `npm ci` しないので、外に寄生した瞬間 CI だけが落ちる。**この2つを「不要そうだから」で消さないこと**（spec `publishing-site-deployment` に明文あり）:
  - `mandala/postcss.config.mjs` — **中身が空なのが正しい**。Next の postcss 設定探索は `find-up` で親方向へ遡るため、親側に設定が生えた瞬間に黙って拾う構造へ戻さないための防御
  - `mandala/__tests__/helpers/studio-alias-hooks.mjs` の `ALLOWED_PACKAGES` — parity テストが Studio 側ソースを走らせるとき、**許可した名前だけ** `mandala/node_modules` から解決する。現在は `zod` の1件。⚠ mandala は 4.3.6・Studio は 4.4.3 で**版がずれている**——検証対象は走査規則であって zod の挙動ではない、という前提で受け入れている既知の近似
  - ⚠ 許可リストに無い依存が Studio 側に生えるとテストが落ちる。**それが仕掛けの狙い**

#### 既知の弱点・仮置き

| 項目 | 状況 |
|---|---|
| **`zod` を 4.3.6 に固定している** | Nextra 4.6.x が zod 4.4.x と衝突し全ページのプリレンダが落ちる（[nextra#5008](https://github.com/shuding/nextra/issues/5008)）。**上流修正後に `package.json` の `overrides` を外す** |
| **ビルドを webpack に固定している** | Turbopack はローダー options に関数を渡せない。**Nextra か unified が文字列でのプラグイン指定に対応したら `--webpack` を外せる** |
| **テーマ内部の class 名に依存している** | リリース番号は `.nextra-sidebar::before`、**サイドバー幅は `.nextra-sidebar.x\:w-64`**（展開状態だけを狙う。平坦に書くと手動トグルの `x:w-20` まで潰れて畳めなくなる）、Studio の帯は `[data-slot="sidebar-*"]`。壊れ方は「番号が出ない」「幅が広がらない」「帯が覆われる」で機能影響は無い |
| **supergraphic の `z-index: 40`** | ナビバーが `z-30` である前提の数値。**クラス名ではなく数値の依存なので更新時に気づきにくい** |
| **supergraphic 帯の固定は `fixed` + 高さ変数** | 帯は `position: fixed` でフローから外し、6px の居場所は `--nextra-navbar-height` を 64 → 70px にして確保。⚠ `sticky` に戻すと帯がフローの先頭 6px を占め、ナビバーがスクロール開始直後にずり上がる。⚠ 変数を戻して覆いかぶせる形にすると、ヘッダーも本文も 6px 上へ詰まる。**6px は帯の `height` と変数の加算分の 2 箇所** |
| **曼陀羅の辺の色が固定値で、しかも2箇所にある** | SVG の `<marker>` は CSS 変数を引けないため、辺と矢印は `Mandala.tsx` の `EDGE_COLOR`（`#7a8189`）に直値。**接続点の丸ポチだけは `globals.css` の `--xy-handle-*`**——**色を変えるときは両方直す**。値は「両テーマに対して同じくらいのコントラストになる明度」から決めており、片方に寄せるともう片方で沈む |
| **全体トップの曼陀羅が静的 HTML に無い** | 遅延境界（`LazyMandala`）の副作用。Pagefind の索引語数が 1434 → 1410 に減った（同じ語はシリーズ一覧にもあるので検索性への影響は無い）。初期 JS 519KB 減との引き換え |
| **モーダルの現在地はパス解決に依存** | レッスンページは素の MDX でページ側から現在地を渡せないため `usePathname()` から解く（`lib/current-course.ts`）。**URL 構造を変えると壊れる** |
| **Blob 画像モードは未実装** | 器（設定値と分岐）だけあり、選ぶとエラーで停止する。現 Blob は `access: "private"` で公開参照できないため、使うなら public 再アップロードが前提 |
| **ローカルの `npm ci` が EPERM で落ちる** | Windows で native モジュールがプロセスに掴まれるため。**CI（ubuntu）では起きない**。ローカルは `npm install` |
| **`mandala` の `npm run lint` が動かない** | スクリプトが `next lint` のままで、Next 16 で削除されたサブコマンド。`Invalid project directory provided, no such directory: mandala\lint` と出る。`eslint.config.*` も無いので `npx eslint .` も走らない。**mandala 側の静的検査は実質 `npx tsc --noEmit` とテストだけ**（CI もこの2つ）。直すなら flat config の新設ごと独立した change にする |
| **`cover` フィールドは温存だが未使用** | シリーズトップの画像表示を廃止したため、どのページでも表示しない |
| **曼陀羅ノードがキャッチを描画しない** | `Mandala.tsx` の `VARIANT = "compact"` が固定で、`CompactNode` は `.dxm-node-catch` を持たない。キャッチを描く `CardNode`（コメント上は「ミニ曼陀羅（コーストップ）用」）はどこからも使われておらず、コーストップに react-flow は無い。`site-data.json` は各ノードに `catch` を持ったままなのでデータ経路は生きている。⚠ **`publishing-site-pages` spec の「曼陀羅ノードは…タイトルの下の行に置く従来の表示を維持する」は実装と食い違っている**。実装を戻すか、spec の一文と dead code（`CardNode` ＋ `.dxm-node-catch`）を落とすかを決める独立した change にする |

### 2.3 Studio

- **ツリーの正本は spec `unified-content-tree`**（行表示・メニュー構成・DnD・複製・キーボード・検索・ホーム行）。ペイン幅は tree / pane4 の2ペインモデル
  - ⚠ **実装の内部識別子（`Pane4Shell` / `Pane4View` / `clampPaneWidth("pane4")`）は旧4ペイン構成の名残。** 見た目は**3ペイン**（左からツリー・エディタ／メタ・Agent／画像）で、コードの番号とは対応しない。⚠ **スキル文書にペイン番号を書かない**（spec `skill-host-independence`）——スキルは Claude Code・Cursor など任意のホストから読まれる
- **選択は「クリックした階層で止まる」**。フォーカス降下規則は廃止済みで、全空＝ホーム（全体）選択。正本は spec `workspace-state-hooks`。可視行・キーボード解決は `lib/content-tree-flatten.ts`（pure・テスト済み）
- **行クリックは2段構え**: 未選択の行＝「選択＋閉じているときだけ展開」、選択済みの行の再クリック＝開閉トグル。⚠ **EBEX（クリック＝常時トグル）との意図的な差分**なので「EBEX と違う」を理由に戻さないこと
- ⚠ **キーボードカーソルは実 DOM フォーカスを持つ**（`data-row-id` + `tabIndex={-1}` + effect で `focus()`）。**これは Shift+F10 の前提**——フォーカスをコンテナに戻すと行のメニューが出なくなる。行が消えたときの付け替えは `resolveFocusFallbackRowId` が担う
- ⚠ **カーソルは「選択」にも追随する**が、**この追随では DOM フォーカスを動かさない**——曼陀羅モーダルの再マウント中はフォーカスが一時的に body に落ちるので、動かすとツリーが横取りしてモーダルが閉じる。判定は `externalSyncRowId`（**state。レンダー中に ref を触ると lint エラー**）で、boolean のワンショットにすると StrictMode の2回実行で消費されて効かない
- ⚠ ツリーのキーボード操作を触るときは dnd-kit の `KeyboardSensor` を戻さないこと（Enter/Space を奪い合う。撤去済み）
- **ツリーの開閉と選択は cookie に保存され、サーバーが初期描画で復元する**（`lib/tree-collapse-cookie.ts` / `lib/workspace-selection.ts`、読む側は `app/page.tsx`）。保存するのは**畳んだ ID だけ**——展開側を保存すると、新しく生えたシリーズが畳まれて現れて挙動が裏返る。⚠ **曼陀羅の開閉記憶は逆に展開側を持つ**（→ 2.2）。既定と寿命が違うので、極性を揃えようとしないこと
  - ⚠ **`parseTreeCollapseCookie` は3状態を返す**（2026-08-26）: cookie が無い・壊れている → **`null`（記憶なし）**／正しい値 → その集合。**「記憶なし」と「畳んだ ID が0件」を潰さないこと**——前者は全折りたたみで開き、後者は「すべて展開している」という記憶なので全展開で開く。潰すと**全部開いた状態を保存した人が次回すべて畳まれて開く**
  - ⚠ **記憶が無いときは選択も `focusHome()` に倒す。** 先頭レッスンのフォールバックへ落とすと、下の「祖先を開く保険」が働いて**1本だけ枝が開いた全折りたたみ**になる
  - ⚠ **その抑止はクライアント側にも要る**（`restoredFromMemory` prop を `page.tsx` → `Workspace` → `ContentTreePane` へ通す）。**開閉は cookie・選択は `localStorage` にも残る**ので、**cookie だけ失効して選択が生きている状態**が起こる。実機で再現済み——サーバーは全折りたたみで描いたのに、hydration 後に届いた選択が祖先を開いてしまう
  - ⚠ **クライアント側で復元し直してはならない。** ここは 3 回踏んでいる: `useState` の初期化関数は **SSR でも走る**ので hydration が食い違う／`useEffect` は描画のあとなので全展開が一瞬見える／`useLayoutEffect` でも**同じ**——サーバーが描いた HTML は hydration まで表示され続け、**どの hook も hydration の前には走らない**。だから cookie でサーバーが畳んだ HTML を返す。EBEX にちらつきが無いのは保存していないから（既定＝全部畳む＋選択の祖先だけ開く）で、参考にならない
  - ⚠ **Vercel では cookie を読まない**（`process.env.VERCEL` 分岐）。`cookies()` は route を dynamic にし、静的焼き込み前提のデモ（spec `studio-demo-deployment`）を**中身が空**にする。ローカルの `/` は dynamic（ƒ）で正しい。⚠ **この分岐も「記憶なし」＝全折りたたみを返すこと**（`EMPTY_TREE_COLLAPSE` を返すと全展開になる）——デモは毎回全折りたたみで開く
  - ⚠ **cookie に書くのは「畳んだ集合 − 選択の祖先」。** サーバーは選択を知らないので、書く側で先に除く（保存 effect の依存に選択が入っているのはそのため）。画面上は選択中の行を畳めるが cookie には載らない＝リロードで開く。復元が届いたときに祖先を開く**一度きり**の保険が `prevSelectedRowId !== selectedRowId` ブロックにある
  - ⚠ **選択は `localStorage` と cookie の二重書き。** `page.tsx` の `firstLessonSelection` と `Workspace` のフォールバックは**同じ規則**に保つこと——ずれると選択レールと本文が hydration 後に移るちらつきが戻る。⚠ ただし**開閉の記憶が無いときはどちらもホーム**に倒す（上記）
  - ⚠ **ツリーを描くテストは `afterEach` で cookie を消す**（`max-age=0`）。jsdom の `document.cookie` はテスト間で残る
- **collapse all が開いたまま残すのは「選択の祖先」だけで、選択自身は畳む**（2026-08-24・`collapse-all-and-pin-polish`）。判定は `resolveCollapseAllTargets`（`lib/content-tree-flatten.ts`）が持つ——シリーズが祖先になるのは**コース以下を選んでいるとき**、コースが祖先になるのは**レッスンを選んでいるとき**（`selectionRowId` と同じ規約）。⚠ **選択自身を畳む対象から外さないこと**——シリーズ行・コース行は自分を畳んでも見えるので外す理由が無く、外すと「畳み済みのシリーズを選んで collapse all」で**逆に展開される**（報告されたバグ）
  - **collapse all はカーソル（背景のグレー）を選択中の行へ移す。** ⚠ **メニューを開いた時点でカーソルは右クリックした場所へ移っている**（`handleContextMenuChange` が `focusRow` を呼ぶ）——空きスペースなら行ですらない `"area"` が入る。そのまま畳むと `resolveFocusFallbackRowId` の最終手段（可視の先頭行）に落ち、**選択と無関係なホーム行がハイライトされる**。だから畳んだ直後に `focusRow(selectionRowId(...))` で選択へ寄せる（祖先は開いたままなので選択行は必ず可視）
  - ⚠ **cookie 側の「選択を除く」は別の規則で、こちらは選択**自身**を除いてよい**（spec `unified-content-tree` の「復元時は選択中のアイテムの祖先を展開する」が明示している）。**collapse all の規則と揃えようとしないこと**——復元は「選択が畳まれた枝に隠れた状態で開始しない」ための保険で、目的が違う
- **複製は `POST /api/content/duplicate`**。⚠ **実装で `fs.cpSync` を使わないこと**——Node v24.14 は宛先パスに全角文字（「（コピー）」等）があると try/catch も効かず**プロセスごとクラッシュする**（exit 127）。`readdir`＋`copyFileSync` の手書き再帰でコピーする
- **メタ編集の正本は spec `workspace-meta-views`**。コースメタは2列で、右列のミニ曼陀羅は `col-start-2 row-span-4 row-start-2` の**明示配置**（DOM 順は最後＝タブ順を自然に保つため）
  - ⚠ **ミニ曼陀羅の枠は `MiniMandalaSection` 内のサムネイルボタンが持つ1枚だけ**。呼び出し側で `border` のラッパーを足すと二重になる
  - ⚠ **右列セルの高さは左列4項目だけで決まる。** グラフの実寸を行の高さ計算に参加させると左列の行間が引き伸ばされる
  - ⚠ **ミニ曼陀羅モーダルの開閉 state は `Workspace` が持つ。** `CourseMetaView` は `key={course.id}` で再マウントされるので、下位に置くと「モーダルからノードをクリックして遷移 → モーダルが消える」になる
- **曼陀羅は React Flow ＋ dagre**（Mermaid は撤去済み）。実装は `studio/lib/mandala/` と `studio/components/workspace/mandala/`
  - ⚠ **サムネイルは compact ノード・拡大モーダルは card ノード**と出し分ける。カードのまま縮めると文字が潰れる
  - ⚠ **ノード寸法は `Mandala.tsx` の `SIZES` と `globals.css` の `.dxm-node-*` で二重に持つ。** dagre が固定寸法前提なので**片方だけ変えると辺の接続位置がずれる**。一致は `__tests__/components/mandala-node-size-parity.test.ts` が固定している（`globals.css` を読んで `SIZES` と突き合わせる。**値そのものはテストに埋めていない**ので、寸法を意図して変えるぶんには落ちない）
  - ⚠ **カードの幅と右端の逃げ（`padding-right`）は連動する。** 逃げだけ広げるとタイトル領域が食われて折り返しが早まる。「コース名を全角1文字ぶん広げる」なら幅にも同じ 14px を足すこと（2026-08-24 に一度この計算を間違えた）。逃げに見込むのは**語彙のうち最も長いラベル**——「独習 / 講義」の2文字（45.7px）ではなく「ハンズオン」の5文字（75.8px・実測）。いまは card 260×88 / 逃げ 5rem。⚠ **サイトの `card` は 280×140 の別物**（キャッチを載せる）なので揃えなくてよい
  - ⚠ **全体曼陀羅に `fitView` を使わない**（2026-08-23 に撤回）。収めると**コンテンツが増えるほどノードが縮む**——実測で、ノードを 200×52 から 240×72 へ広げた時点でサイトのホームは既に 0.83 倍だった（キャンバス 561×640 に対しグラフ 284×768。**縦だけが効き、横は 2 倍近く余っていた**）。いまは**等倍固定＋基準ノード合わせ**で、収まらないぶんは縦横とも切れる。正本は両アプリの `lib/mandala/viewport.ts`（**コピーで持つので片方だけ直さない**）
    - 基準の解決順は **現在地（`here`）→ `Start` → グラフ全体**。現在地は**縦横中央**、`Start`（と全体）は**横中央・上端そろえ**——`Start` は必ず最上段にあるので縦中央にすると上半分が空く。`Start` は複数宣言できるので合成外接箱で扱う
    - ⚠ **配置は `onInit` でも呼ぶこと。** `useNodesInitialized` を待つ経路しか持たないと、**ノードの実測が完了しない環境で配置ごと効かなくなる**（ブラウザペインで実際に踏んだ: viewport が単位行列のまま）。基準の算出は dagre の座標と固定寸法だけで足り、実測を必要としない
    - ⚠ **キャンバスが 0×0 のときは置かない**（`vh` 由来の高さが 0 に解決する場面がある）。リサイズ監視が拾い直す
  - **ミニ曼陀羅（サムネイル・拡大モーダル）は `fitView` のまま。** コース1件と隣接だけで大きさが増えないので、収める挙動が今も正しい
  - ⚠ **ノード名は折り返して全部見せる（`…` もツールチップも使わない）。寸法と行数の上限は「翻訳契約の名前の上限（36字）がその幅で何行になるか」の実測値。** ⚠ **机上計算しないこと**——compact は受講形態ラベル（`self-study` = 61px）に取られてタイトルが約 150px しか無く、200px 幅では 27 字でも 3 行になる。実測の結果 compact 240×72（3行）・サムネイル 220×56（2行）・折りたたみ 210×72（2行）。**測り方はブラウザで `n.style.width` を差し替えて `scrollHeight / 行高` を見る**
  - ⚠ **辺の線種で order / cross を区別しない**（両アプリで統一済み）。`animated` 辺はそれ自体が流れる破線として描かれるため
  - ⚠ **モーダル内の曼陀羅は公開サイトと同じ構成で組む。** ダイアログは高さを持たず中身なり・キャンバスだけ絶対長（全体 `min(72vh,680px)` / ミニ `min(64vh,520px)`）・開閉アニメーション無し（`animated={false}`）。**React Flow はマウント時に一度だけコンテナを測って座標を確定する**ので、ダイアログが高さを配る構成だと開き直しでずれる。⚠ **「リロード直後の初回だけ正しい」は正しさの証拠にならない**（遅延読み込みでマウントが遅れていただけ）
- **レッスンのメタは `.meta.json`**（frontmatter は廃止済み）。スキーマ正本は `lib/schema.ts` の `lessonMetaFileSchema`（未知キー拒否）。名前3つ（series/course/lesson）は持たない——フォルダ名が正本
  - ⚠ **壊れた `.meta.json` は全階層でエラーになる**（「無い」とは区別。`MetaJsonParseError`）。直すまでロードが止まる——これは仕様
  - **本文とメタの保存 API は別**（`save-lesson` / `save-lesson-meta`）。本文保存はメタに触れない
  - **画像の「使用中 / 未使用」は日英を合算する**（2026-08-23）。ローダーが `contents.en.md` を `Lesson.content_en` に載せ、`lib/extract-image-refs.ts` が両方を走査する。⚠ **編集言語で切り替えない**——片方でしか使っていない画像が `未使用` に見えると、削除確認の警告が出ないまま消えて、もう一方の本文が参照切れになる（実データで**英語だけが参照する画像が 7 枚**あった。日英で別ファイルを使うため）。英語本文の編集は `useLessonEnBody` の `onBodyChange` → `updateLessonEnContent` で**ツリー state にも移す**（保存は増やさない。日本語と同じ即時性にそろえるため）
  - ⚠ **テストで `loadContentsFolder` / API route を呼ぶときは必ず cwd を偽装する**——素の cwd（studio）だと実 `contents/` にローダーが id を書き戻す（実際に踏んで git 復元で救済した）
- ⚠ **コースメタに項目を足すときは `listCoursesNeedingMetaPersist`（`lib/course-flow.ts`）の比較にも足す。** 忘れると「その項目だけ変更」が保存されずに消える。⚠ 真偽値は `!!a !== !!b` で比べる（未宣言が「キー無し」と `false` の2通りで来る）
- **`is_start` / `is_goal`**（コース `.meta.json`・省略時 false）は**カリキュラムの入口・到達点の宣言**。**制約は一切無い**——前のコースを持つコースでも Start にでき、複数コースが宣言してよい。⚠ **`cross_series_prev` / `next` の配列に番兵 ID を混ぜてはいけない**（`stripDanglingCourseLinks` が実在しない ID として黙って消す）
- **`Course` 型に必須フィールドを足さない。** `style` と同じ `optional` にする——必須にすると全テストフィクスチャが型エラーになる
- ⚠ **shadcn base（Base UI）の `Select` はラベル解決に Root の `items` を渡す。** `SelectItem` の children だけではトリガーに**生の value** が出る。保存済みの値は候補一覧に無くても項目に入れること
- **Studio の Vercel デモは読み取り専用**（要件の正本は spec `studio-demo-deployment`）。ツリー・本文はビルド時に焼き込み、画像は Vercel Blob、保存・Agent は read-only FS で**失敗する。許容された仕様**
  - ⚠ **`Include files outside the root directory` は Enabled から動かさないこと。** 正本 `contents/` は Root Directory の**外**にあり、無効にすると `loadContentsFolder` が**黙って空を返す**ため、**ビルド緑・デプロイ成功・中身が空のデモ**という気づけない壊れ方をする
  - ⚠ **`next.config.ts` の `outputFileTracingRoot` を素朴に `__dirname` へ戻さないこと。** include-outside が ON だと Vercel はリポジトリ丸ごとを `/vercel/path0` に置き、ズレると `ENOENT: .../.next/routes-manifest-deterministic.json` で落ちる。`turbopack.root` は逆に `studio/` のまま動かさない
  - **番人がいる**: `studio/scripts/check-vercel-build-root.mjs` が `npm run build` の前段で上の2点を検査して止める

#### 名前と識別子

- **シリーズ名・コース名の出典は計画書「第5章 コース仕様」、レッスン名は「第6章 レッスン仕様」。** `slug` も同じ2章。`L05` の ID・`【撮】`『【録】』の印・`☆` は名前に含めない
- **曼陀羅グラフの箱の中だけは短縮表記**（箱幅の都合）。ここから名前を取らない
- **識別子は3層**（計画書 §8.2）: `id`（不変キー・進捗データ用）/ `slug`（公開 URL）/ 表示名（ディレクトリ名）。**slug は表示名と独立なので、リネームしても URL は壊れない**
- **レッスン名に `/` が含まれるものが2本ある**（L13「リポジトリを作る / clone」・L25「ファイル読み書き（CSV / JSON）」）。ディレクトリ名では `_` に置換される
- **リネームで起きること**: `id` は**保たれる**（ディレクトリごと移動するため）／レッスンの `series` / `course` は**ディレクトリ名から導出される**／`contents/.meta.json` の `order` は loader が実体に合わせて整理するので**末尾へ動く**（並び順を保ちたければ自分で書き換える）／会話履歴・画像参照は**影響なし**

### 2.4 デプロイ・CI

**Pages と Vercel は役割が違う。同じものを2か所へ配るのではない。**

| | GitHub Pages | Vercel |
|---|---|---|
| 位置づけ | **リリース版**（社内トライアル） | **最新版**（理想追求・実験） |
| 契機 | `v*` タグ（＋確認用の手動） | **`main` へのマージ** |
| 担い手 | GitHub Actions | **Vercel の git 連携** |
| リリース番号 | 出る | 出ない |

⚠ **両者の内容は一致しない。** マージからタグを打つまでの間、Vercel は最新・Pages は前回リリースのまま。**どちらを見ているかで判断が変わる場面では URL を明示すること。**

| ワークフロー | 契機 | やること |
|---|---|---|

- **リポジトリ切り出し（`AI_Driven_School` → `dx-training-studio`）でパス前提が変わった**。ワークフローの `paths` / `working-directory` は入れ物直下基準（`studio/**` `mandala/**` `contents/**`）。⚠ 旧 `dx-training-studio/` プレフィックスに戻すと **CI は発火しないだけで赤にもならない**——壊れに気づけない
- **`trailingSlash: true` は常時 ON**（`mandala/next.config.mjs`）。出力は `<slug>/index.html` 形式で、配信先間のビルド差は `NEXT_PUBLIC_BASE_PATH` の1軸だけ

- ⚠ **CI の `push` は `main` に絞ってある。外すと同じ push で2回走る**——`pull_request` と同じ paths を見ているため。`concurrency` の group は `github.ref` 依存で、push と PR は値が違うので相殺されない。**代償として PR を作る前のブランチ push では CI が回らない**
- ⚠ **作業ブランチの内容を「配信して」確認する手段は無い。** Pages は environment 保護で弾かれ、Vercel は Ignored Build Step で `main` 限定。確認は**ローカルビルド**か **`main` へマージ**のどちらか
- ⚠ **`github-pages` environment の保護を "No restriction" にしないこと**（`publishing-site-deployment` spec に明文あり）
- ⚠ **Vercel の Ignored Build Step は `exit 1` = ビルドする / `exit 0` = スキップ**。向きが逆なので**両方の分岐を書く**（`if [ "$VERCEL_GIT_COMMIT_REF" = "main" ]; then exit 1; else exit 0; fi`）。片方だけ書くと `if` 文が 0 を返し、**`main` こそがキャンセルされる**。**同じリポジトリを見ている Vercel プロジェクト全部に要る**
- ⚠ **`workflow_dispatch` の Run workflow ボタンは、デフォルトブランチのワークフロー定義を見て出る。** 手動トリガーを足したときは**一度 `main` にマージするまでボタンが現れない**
- ⚠ **Pages を通すには設定が2つ要り、順序がある**（Source の有効化 → environment のタグルール）。**手順は `mandala/README.md` が正本**。⚠ **environment はワークフローが参照した時点で自動生成されるので「設定画面はあるのに Pages サイトが無い」状態が起きる**——誤診の元
- ⚠ **ワークフローの発火条件（`v*`）と environment の許可パターン（`v*.*.*`）が一致していない。** `v6` のようなタグを打つと**ビルドは走ってから deploy だけが拒否される**。いまの27タグは全て `vX.Y.Z` なので実害は出ていない（→ 3章 P4）
- ⚠ **Pages は1リポジトリ1サイト。** comitora レポートのワークフローを GitHub 側で Disable して競合を外している。**再有効化するなら** comitora の手動実行時に `deploy_pages: false` を選ぶ運用に戻すこと
- タグが **main に含まれないと検証で止まる**（`git merge-base --is-ancestor`）。検証は2ファイルそれぞれに入っている（DRY 化していないのは意図的）

### 2.5 環境（事故りやすい点）

- ⚠ **横からコミットが生まれることがある**（英語メッセージ・意味のある単位）。**謎の自動機構ではなくユーザー自身が別ツールで行っているもの**。区切りごとに `git log` / `git status` を見る
- ⚠ **`contents/` の JSON を CLI から触るときは `node -e` で書く。** PowerShell の `Out-File -Encoding utf8` は **BOM を付ける**ため `JSON.parse` が失敗する。いまは静かに消えるのではなくロードがエラーで止まる（`MetaJsonParseError`・対象パス付き）
- ⚠ **Studio 実行中は `contents/` 配下が横から書き換わる。** loader が `.meta.json` に `id` を採番し `order` を整理する。画像挿入も同様。**編集前に外部変更を確認する**
- ⚠ **テストの前に dev サーバーを止める。** ただし `compileCss`（`inline-html-assets.test.ts`）は**止めても全体実行では5秒タイムアウトで落ちる**（単体なら 400ms 前後）。マシン負荷次第で同じ日でも通ったり落ちたりする。⚠ **全体実行でこれ1件だけ落ちたら、単体で回して確かめてから騒ぐ**
- ⚠ **`npm run build` の前にも dev サーバーを止める。** 同じ `.next` を使うため、ロックで「A next build still in progress」と出て**古い `out/` のまま**になる。**ビルドは失敗したのに測定だけ進むと誤った結論に至る**ので、成功行（`✓ Generating static pages (37/37)`）を必ず確認する
  - ⚠ **dev の起動直後に `.next/dev/prerender-manifest.json` の EBUSY と `Unexpected end of JSON input` が出るのは既知・無害**（初回コンパイルの1回だけ。リトライで 200 になる）。⚠ **build の順序は関係ない**——build は `.next/` 直下に、dev は `.next/dev/` に書き、**build はこのファイルを一切触らない**。「逆順（build のあとに dev を立てる）でも詰まる」という旧記述は誤診で、**`.next` を消しても解けない**のはこれが理由（消しても dev が同じ書き方で作り直す）。機構は**待機ループの多重リクエスト × Next 16 の非アトミックな read-modify-write**——`next dev` は `getStaticPaths` の完了時にこのファイルを読んで書き戻す（`next/dist/server/dev/next-dev-server.js:660` と `:690`）が、`withCoalescedInvoke` が束ねるのは**ワーカー実行だけ**で、**書き戻しは呼び出し数ぶん走る**。初回コンパイルの17秒のあいだに `-TimeoutSec 3` の待機ループが投げ続けたリクエストが一斉に解けて、同一ファイルへ同時 read/write になる（実ログ `mandala/.next/dev/logs/next-development.log` で3件が 0.3 秒内に並ぶ）。**踏むのは初回コンパイル中に手でブラウザを開いたときだけで、リロードで直る**。消したいなら起動 bat の待機ループを「1本ずつ待つ」形（`-TimeoutSec` を残り時間にする）にすればよい——⚠ ただし次項の「200 を返してからブラウザを開く」順序は維持すること。**2026-08-23 時点では未実施（様子見）**
  - **dev と build がロックで噛み合わないときは、静的 `out/` を別ポートで配信して検証するほうが速い**（`npx serve out -l <別ポート>` → `preview_start` に `url` を渡す）。postbuild 済みなので `<html lang>` も Pagefind も正しく、**検証対象としてはむしろ忠実**
- **起動 bat はサーバーが 200 を返してからブラウザを開く**（4本すべて。2026-08-23）。⚠ **順序を戻さないこと**——立ち上がり途中のサーバーへ投げた API 要求は空で返り、**画像ビューが静かに空のまま留まる**（UP/AI/Web が全滅し、Used だけ本文が参照する画像が「参照切れ」行として残る、という見え方になる）。待機は最大 60 秒で、超えたらブラウザを開かずに URL を出し、サーバーの起動は続ける
- ⚠ **dev サーバーは `content/site-data.json` をプロセス起動時に取り込む。** 正本を書き換えて `npm run build` し直しても稼働中の dev サーバーには反映されないことがある。**表示が合わないときはサーバーを立て直してから疑う**
- ⚠ **`_meta` ファイルの追加・拡張子変更も dev サーバーの再起動が要る。** ページマップは起動時に組まれるので HMR で拾われず、**コンポーネントの変更だけが反映されて「一部だけ効いている」状態に見える**
- ⚠ **長時間動いている dev サーバーは編集を拾わないことがある**（7時間動いていた 3001 が `globals.css` の変更を反映しなかった）。**測る前に、配信 CSS を `fetch` して自分の変更した文字列が入っているか確かめる**。`next dev -p 3001` は**ポートがハードコード**なので `preview_start` は別ポートへ逃げられず、**先に掴んでいるプロセスを止めるしかない**（`Get-NetTCPConnection -LocalPort 3001` で PID）
- **dev サーバーは同一プロジェクトで1台まで**（Next 16）。検証用に立てたら必ず止める
- ⚠ **`npm run format` はリポジトリ全体を書き換える**（Studio で 200 ファイル以上）。**コミット済みのコードが現行 prettier のバージョンで整形されていない**ため、無関係な差分が大量に混ざる。tasks.md に「format する」と書いてあっても**そのまま実行しない**
  - ⚠ **触ったファイルだけに当てても駄目だった**。5 ファイルに当てただけで hex の小文字化とコメントの再折り返しで **300 行以上の無関係な差分**が出た。**結論: そもそも当てない**。全体整形をやるなら独立した change にする
- ⚠ **React の dev 専用の警告・エラー全文は本番ビルドでは出ない。** `Element type is invalid` の詳細を追うときは **`npm run dev`** で確認する
- **`.gitignore` のパターンは必ず anchored**（`/images/` `/mandala/out/`）。非 anchored だと任意の深さにマッチし、**Tailwind のソース走査から `components/` 配下が丸ごと落ちて UI が崩れる**。変更したら **`.next` を削除する**。機構はメモリ `project-tailwind-gitignore-trap`
- **CRLF + BOM のファイルがある**（`__tests__/hooks/*.test.ts`・`__tests__/components/*.test.tsx` 等）。LF 前提の文字列置換が**黙って空振りする**ので、複数行の編集は Edit ツールを使う。⚠ `node -e` の `String.replace` は**エラーにならず「置換したつもり」で進む**——一括置換したら**必ず結果を grep で確かめる**
- ⚠ **vitest の alias は配列形式で順序を明示する**（`resolve.alias: [{find, replacement}, …]`）。広いプレフィックス（`@`）を先に置くと、**より限定的な別名（`@/content/site-data.json`）が食われて解決されない**
- ⚠ vitest を kill すると tinypool のワーカー（node.exe）が孤児化して以後の実行が `ERR_IPC_CHANNEL_CLOSED` で全滅する。素の node.exe を掃除してから再実行
- ⚠ **worktree を消すときは `git worktree remove --force`**（フォルダ削除だけだと登録がゴーストとして残る）。Windows ではファイル監視がディレクトリのハンドルを掴んでいて**空になったディレクトリだけ消えないことがある**——git 登録が消えていれば無害で、監視が離せば消える

#### ブラウザペイン検証の限界

⚠ **この盲点は実際に不具合を通した**（2026-08-21・曼陀羅 React Flow 化）。DOM で実測して「移植は成功」と報告したが、実機確認で問題が複数（重大なものを含む）見つかった。**「ペインで見られない箇所がある」は見た目の詰めの話ではなく、実装の正否そのものを見落とす穴**として扱うこと。

- **通った不具合**: ①サムネイルが**まったく表示されない**（`.dxm-mandala` に高さが無くキャンバスが 0px）②全体曼陀羅の**中心がずれる**（`fitView` は初回マウント1回きり）。**どちらも「辺が描かれない・fitView が効かない」という制約の陰に隠れていた**
- **教訓**: 制約を「見られないから未確認」と書いて終わりにせず、**制約の裏側で何が起きうるかを1段考える**。①は高さの解決という**レイアウトの話で、実は測れた**
- ⚠ **React Flow の辺は描画されない**。ノードの実測（ResizeObserver / rAF）が完了するまで `visibility: hidden` で、ペイン非表示だと計測が完了しない。**Base UI の Select** もポップアップが座標を持たず操作できない
- ⚠ **「キャンバスに対する位置」は測ってはいけない。** fitView が未適用なので viewport の transform は単位行列のままで、グラフは**左上に貼り付いた状態**にある。**有効なのはノード同士・ノードと子要素といった相対位置だけ**
- ⚠ **CSS transition は開始値のまま固まる**。ペインが非表示だと描画フレームが出ないため、`transition-colors` が**始点で止まり `getComputedStyle` もその値を返す**
  - ⚠ **凍結した値は「別の値」ではなく「一世代前の値」として出るので、実装バグに見える**（1時間溶かした）。ダークなのにボタンがライトの色を返し、CSS 変数は正しくダーク値を返す、という**辻褄の合わない組み合わせ**になる
  - **見分け方**: 同じ class の要素を `createElement` で新しく作って挿し、値を比べる。**新規ノードは遷移を開始しないので最終値を返す**
  - `transition-all` を持つ shadcn の `Button` は全部この影響下にある
- ⚠ **CSSOM を書き換えて `getComputedStyle` で確かめる検証は成立しない**（1時間溶かした）。`rule.style.setProperty()` を変えても**読み出しが古い値のまま返る**。**`:hover` の効きは配信 CSS のテキストを `fetch` して読み、詳細度を手で数えるほうが速くて確実**
- ✅ **「クラスを付け外して前後を比べる」は成立する。** `classList` 変更やインラインスタイルは**レイアウトを再計算させる**ので新しい値が返る。**テーマの切り替えも `html.classList` の付け外しで測れる**
- ✅ **「相手のアプリを同時に立てて実測値を突き合わせる」が一番強い。** 色合わせでは期待値の算術ではなくサイト（3002）と Studio（3001）を並べて `getComputedStyle` を読んだ。**式を移すのではなく、実効値を突き合わせること**
- ⚠ **ペインのビューポートは 0×0 のことも実寸のこともある。まず `innerWidth` を読むこと。** ⚠ **0×0 のとき `vh` 由来の長さは 0 に解決する**——`height: min(72vh, 680px)` が 0px と出て「バグ再発」に見える。`resize_window` で実寸にすれば正しい値になる
- ⚠ **`requestAnimationFrame` が発火しないことがある**（1228ms 待って 0 回）。**React Flow の辺・fitView・rAF に載せた自前の処理はこのとき原理的に検証できない**
- ⚠ **「ノードの実測が終わったら実行する」処理は、ここでは永久に実行されない。** `useNodesInitialized` が真にならないため。**症状は「機能が壊れている」ではなく「何も起きない」**なので、実装バグと区別がつかない（2026-08-23 に曼陀羅の配置で踏んだ——viewport が単位行列のまま動かなかった）。**見分け方は `document.querySelectorAll('.react-flow__edge').length` を見ること**——0 なら計測が完了していない環境で、計測待ちの処理は全部保留されている
  - **設計側の教訓**: 実測を必要としない計算を、実測待ちのゲートの内側だけに置かない。**`onInit` でも一度実行する**ようにすれば、計測が来ない環境でも成立し、来た環境では補正が効く
  - ⚠ **ただし「`onInit` でも一度」で救えない処理がある。** React Flow の `fitView` は**内部ストアに依存する**ので `onInit` 時点では空振りし、計測待ちの経路しか正解を出せない。**この種の処理はペイン非表示では原理的に検証できない**——次項の実ブラウザへ逃げること
- ✅ **ペインで詰んだら Playwright で実ブラウザを回せる**（`studio/node_modules` に入っている。2026-08-26 に曼陀羅の収める初期表示の検証で使った）。**ヘッドレス Chromium は rAF も ResizeObserver も正しく動く**ので、ペインの制約はすべて外れる。スクリプトはスクラッチパッドに置き、`createRequire("<studio>/package.json")` で `playwright` を解決する（**スクラッチパッドからは ESM の `import` で解決できない**）
  - **数値で判定できる形にすると強い**: viewport の `transform` と全ノードの矩形からグラフの外接箱を画面座標へ落とし、キャンバスに収まっているかを真偽で出す。**スクリーンショットの目視より確実で、差分の理由も説明できる**
  - ⚠ **セレクタはモーダルへスコープすること。** コースを選ぶとページにミニ曼陀羅が同居するので、`.dxm-mandala-canvas` の1つ目を取ると**サムネイルを測ってしまう**（`[role="dialog"] .dxm-mandala-canvas` / `.dxm-modal .dxm-mandala-canvas`）
  - ⚠ **Studio のツリー行はクリックしない。** 選択を作りたいだけなら `localStorage` / cookie の `dx-training-studio-selection` に差し込んでリロードするほうが安全（行の先頭ボタンは開閉、末尾は `status` の変更で、**押すと正本が変わる**）
- ⚠ **React Flow を測るなら `.react-flow` のルートの実寸まで見ること。** キャンバスの高さが `min-height` や `flex` の伸長だけで立っているとき、ルートの `height: 100%` は解決できず **0px になって error #004 が出る**。**キャンバスが非 0 でもルートが 0 のことがある**
- ⚠ **HMR 後の DOM は信用しない。** 「要素が無い」と判断する前に一度リロードする
- ⚠ **ペインのコンソールは編集途中のエラーを保持し続ける**（2回誤診しかけた）。**`read_console_messages` は蓄積されたバッファを返すので、いま壊れている証拠にならない**
  - **見分け方**: ①エラーが指す**行番号が現在のファイルの行数と食い違っていたら古いバッファ** ②`console.error` をその場で差し替えて**その後に新規で出るかを見る**
  - **確証の取り方は3点一致**: `tsc --noEmit` が通る／テストが通る／実機で新しい挙動が観測できる。**コンソールの赤だけで実装を疑わない**

### P2: 将来構想（別プロジェクト規模）

#### ゲーミフィケーション

**目的と最終形.** レベルアップ構造で受講者のモチベーションを維持する。最終目標は「**DX免許皆伝**」——曼陀羅を全踏破した状態。

⚠ **曼陀羅はすでにその器として設計されている。** 「コース修了で次の複数コースが解放／複数コース受講済みでないと次に進めない」というフローチャート構造が最初からゲーミフィケーション前提だった。つまり **`cross_series_prev` / `next`・`is_start` / `is_goal` は解放条件の宣言**であって、単なる図の飾りではない。

```
  すでに手当て済みのもの ────────────────────────────

  ・安定 id（srs- / crs- / lsn-）はゲーミフィケーションのために存在する
      ⚠ 「slug だけ使う」を却下した理由がこれ——タイトル推敲で slug を
         変えると進捗レコードとトロフィーが壊れる
      → spec stable-entity-ids として実装済み

  ・Vercel を GitHub Pages と分けて維持しているのもこのため
      Pages = 社内トライアル（静的）／ Vercel = 動的の受け皿

  未決のまま残るもの ──────────────────────────────

  ・Goal 未宣言（いまは Start のみ）が「免許皆伝」の定義を保留している
```

## 4. 作法（守らないと事故る）

### 4.1 OpenSpec

- planning home は **`dx-training-studio/`**（リポジトリルートではない）。ルートから叩くと `No OpenSpec changes directory found` / `Unknown item`。⚠ **Bash の cwd はツール呼び出しをまたいで戻ることがある**ので、毎回 `cd` してから叩く
- **`openspec/changes/` は `.gitignore` されている。** アーカイブした artifacts は**このマシンにしか存在しない**。コミットされる設計の記録は **`openspec/specs/` だけ**
- ✅ **`openspec archive <change名> -y` は spec 同期まで自動でやる。** **手で spec を書かないこと**
- ⚠ **先に手作業で spec を同期してしまうと `openspec archive` が使えなくなる。** delta を再適用しようとして止まる。そうなった場合だけディレクトリ移動でアーカイブする
- ⚠ **`openspec archive` はトランザクショナルではない。** 中断時に「Aborted. No files were changed.」と出るが**嘘**で、処理済みの spec は書き換わっている。中断したら `git status openspec/specs/` で実害を確認する
- ⚠ **spec 同期が成功してもディレクトリ移動が EBUSY で失敗することがある。** その場合は `openspec/changes/archive/<yyyy-mm-dd>-<change名>/` へ**手で移動**すれば完了
- ⚠ **capability を廃止する delta（全要件 REMOVED）は archive が受け付けない** — 「Spec must have at least one requirement」で落ちる。全廃が必要なら「新 capability を ADDED し、archive 後に旧ディレクトリを削除する」
- ⚠ **要件を削ったら `## Purpose` も見直す。** 同期は Purpose を触らない
- ⚠ **複数 change を続けて archive するときは順序に注意。** 後の change の delta は**それを書いた時点の spec** に対して書かれている。**archive 後に横断検索で確認する**
- ⚠ **`## MODIFIED Requirements` は1ファイルに1つだけ。** 複数書くと**最後の1つしか適用されず、残りが黙って落ちる**。同じ種別の要件変更は**1つの見出しの下にまとめる**。取りこぼしは archive の出力（`~ 1 modified` 等の件数）と delta の要件数を突き合わせれば気づける
- delta 側の要件見出しは必ず `### Requirement: <名前>`。**要件内の小見出しに level-3 を使わない**
- ⚠ **要件変更を伴わない作業は change にしない。** `validate` は「差分が最低1つ」を要求する。**要件を捏造して通さないこと**
- アーティファクトは日本語で書く

### 4.2 スキルの SSoT 作法

スキルの作成・更新には **`creating-skills` スキルを使う**（SSoT 監査とハードコード・不整合レビューがゲートになっている）。

- `SKILL.md` は 200行が目安・500行が上限。`references/` は各300行以内、100行超なら目次
- **同じ内容を2箇所に書かない。** 特に `SKILL.md` に references の本文を写さない
- 外部ファイル（`lib/schema.ts` 等）の内容をスキルに写さない。参照先を示す
- **模範解答から読み取れるものは明文化しない**。例外は**負の制約**——良い実例をいくら読んでも「書いてはいけないもの」は復元できないので `design-principles.md` に明文で置く
- ⚠ **ホスト依存の語をスキルに書かない**（spec `skill-host-independence`）: 画面座標（ペイン番号）・「〇〇は Studio が行う」型の担当先の補足・ホストごとの能力差の要約。**残すのは実装契約としての参照だけ**（`studio/lib/translation/freshness.ts` のように実際に import するパス）。⚠ **例外は `general-chat`**（`hidden: true` ＋ Studio 固有ツールを宣言した Studio 専用スキル）

### 4.3 コミットしない

⚠ **AI 側から `git commit` しない。** 変更は作業ツリーに残し、**コミットするかどうかは人が決める**——ユーザーが差分を読んで学習材料にするため。`tasks.md` にも「コミットする」を入れない。

- **archive までは AI がやってよい**（実装 → `openspec archive` → spec 同期）。コミットだけが人の仕事
- 「作業が終わったのでコミットしますか」と毎回聞かない。**聞かずに残すのが既定**
- ⚠ **例外はユーザーが明示的に指示したときだけ**。そのときもブランチを切ってから
- ⚠ 未コミットの差分が積み上がるのは正常。次のセッションの冒頭では `git status` と `git log` で**どこまでが push 済みでどこからが作業ツリーか**を確かめる

### 4.4 案内文書のペインの呼び方

⚠ **見た目は3ペイン**（左からツリー・エディタ／メタ・Agent／画像）。**読み手向けの説明にペイン番号を書かない**（spec `project-layout`）。`Pane4Shell` / `clampPaneWidth("pane4")` のような**コード上の識別子は旧4ペイン構成の名残**で、画面の番号とは対応しない——文書に引くときは識別子である旨を添える。

- `contracts/agent-write-contract.md` の「ペイン4」は**改名しない**（スキル・spec からの参照が広い）。断り書きだけ置いてある
- spec 名（`pane4-component-structure` / `pane4-side-panel`）も同様に据え置き

### 4.5 用語

- **人が後工程で埋める箇所は「空欄」。** 旧称は「穴」。スキルと spec は移行済みだが、**`docs/` の過去記録と run ディレクトリには旧称が残っている**
- ⚠ **「プレースホルダー」を空欄の意味で使わない。** この語は `{{XXX}}` / `<!-- XXX_START -->` の**機械が決定的に埋めるスロット**を指す既存語で、agent の完了ゲートが「残留していたら未完了」と扱う。空欄は残っていて正常なので、**完了判定の意味が正反対**になる
