**public 化の前にやること（注意）**

- **モノレポ全体＋全 git 履歴が公開される**（ebex / minutes-maid / my-proposals / 各 docs/grill-me の社内文脈を含む記録も）。一度 public にすると履歴はクローンされ得るため、後から private に戻しても回収不能

- **Pages は1リポ1サイト**。comitora レポート（workflow_dispatch 時の `deploy_pages`）と公開サイトが**互いに丸ごと上書きし合う**。当面は comitora 側の `deploy_pages` を使わない運用で回避し、両立したくなったら同一 artifact 内サブパスへの統合を検討

### 6. 曼陀羅（React Flow）

| 項目         | 決定内容                                                                                                                                 |

**見せ方の決定（2026-08-14 追記）** — すべて静的サイトで動作可能（React Flow は完全クライアントサイド。サーバーが要るのは受講進捗などの実行時データのみ＝ゲーミフィケーション領域）

| 項目               | 決定内容                                                                                                                                                                                       |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| フロー方向         | **上から下（TB）で統一**。分岐・合流が増えるほど縦流れが読みやすく、縦スクロールとも相性が良い                                                                                                 |
| ノード密度         | **階層で変える**: グローバル曼陀羅=コンパクトノード（名前＋status色）、シリーズ曼陀羅・ミニ曼陀羅=**リッチカード**（catch・レッスン数・所要時間・statusバッジ）。同一データから2密度を描き分け |
| 現在地ピン         | 表示中のシリーズ / コースを強調表示（「いまここ」）                                                                                                                                            |
| 推奨ルート         | 次に進む辺を animated（流れる破線）に                                                                                                                                                          |
| 操作設計           | 初期 `fitView`＋パン/ズーム無効（ページスクロール優先）→ クリックで操作可能に。グローバル曼陀羅のみミニマップ                                                                                  |
| ホバートレース     | ホバーで前提チェーン（上流）と発展先（下流）を跨ぎ含めてハイライト・他を減光。**ポインタデバイス限定**（タッチでは発動しない。タップ＝遷移は不変）                                             |
| シリーズ折りたたみ | グローバル曼陀羅のシリーズ枠を展開/折りたたみ可能に。既定は全展開（増えたら「現在のシリーズのみ展開」へ）                                                                                      |
| 将来               | セマンティックズーム（ズーム率でカード⇄コンパクト切替）、進捗リング付きノード（ゲーミフィケーション）                                                                                          |

### 12. デプロイトリガーと継続的テスト（2026-08-14 追記）

| 項目                 | 決定内容                                                                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 公開サイトのデプロイ | **main ブランチに release タグを付けた時だけ実行**（push/merge では走らない）                                                        |
| Studio のデプロイ    | 既存どおり **main マージ時に Vercel へ**（ローカル前提ツールだが一応残す）。公開サイトとは **Vercel プロジェクトを分けて住み分け**る |
| リリース表示         | **全体トップページに release 番号と GitHub リポへのリンク**を表示                                                                    |
| 継続的テスト         | **push/merge のたびに走る CI ジョブを別途用意**。HTML 変換（変換スクリプト＋Nextra ビルド）まで実行し、**デプロイはしない**          |
| Pages の配信方式     | **artifact 方式**（同一リポ配信のため。1章参照。gh-pages ブランチ方式の決定は撤回）                                                  |

推奨実装（実装時に確定）:

- タグ規約は `v*`（例 `v0.1.0`）とし、workflow は `on: push: tags: ['v*']`。タグはブランチに紐付かないため、**タグのコミットが main に含まれるかのチェック**をジョブ先頭に入れる
- release 番号はビルド時に `GITHUB_REF_NAME` からサイトへ注入（Pages / Vercel 共通）
- **Vercel も同じ release workflow から CLI でデプロイ**する（Vercel の git 連携任せだと push ごとに勝手にデプロイされ、「タグ時だけ」と「Pages/Vercel は常に同一」の両方が崩れるため、git 連携の自動デプロイは切る）
- トップのリポリンクは正本リポ（private）を指す。社外の閲覧者には 404 になるが、想定読者（社内・発表聞き手）には問題ない

## 却下した案

| 案                                       | 却下理由                                                                                                                                                                  |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ~~モノレポを一時 public 化して Pages~~   | 当初却下したが**方針転換**: public 化を許容し同一リポ配信へ（1章）。「一時」ではなく public 維持が前提。却下理由だった同居プロジェクトの公開は、public 化前の棚卸しで対処 |
| 成果物のみ public 専用リポへ push        | 同一リポ配信への方針転換により不要に（gh-pages ブランチ方式・デプロイキーごと撤回）                                                                                       |
| slug の自動ローマ字変換                  | URL 品質が機械任せ・同名衝突や読み揺れのリスク                                                                                                                            |
| 変換スクリプト内の slug 対応表           | URL 決定権が正本の外に出て Studio から見えない                                                                                                                            |
| frontmatter 廃止を先にやり切る（A案）    | 必達ラインと直交する横断リファクタが経路上に入る                                                                                                                          |
| 手書き `overview.md` 対応                | 書く物と Studio 側 UI が増える。トライアルには過剰                                                                                                                        |
| シリーズ跨ぎを「矢印＋ラベルだけ」       | `cross_series_prev/next` が持つコース粒度の情報を捨てることになる                                                                                                         |
| done のみ公開（＋準備中表示）            | → 全 status 公開＋バッジに決定（透明性重視）                                                                                                                              |
| 日本語のみで先行（`/en` 後回し）         | → 今回から `/en` を用意に決定                                                                                                                                             |
| `.meta.en.json` 並置                     | 翻訳対象が2フィールドしかなく、構造情報の持ち主問題が増えるだけ                                                                                                           |
| カバー画像の AI 生成（イラスト調で統一） | 本採用としては却下（チープさ・統一感・ブランド乖離のリスク）。ただしサンプルは AI でまず試す                                                                              |
| 実写ストックフォト運用                   | ライセンス確認の手間とバラつき（→ UP モードの実画像に包含）                                                                                                               |
| メタ編集 UI を今回実装                   | 将来の大改修構想（下記）とまとめる方が二度手間にならない                                                                                                                  |
